# 战斗与轰炸流程重构及核对

接续 447d4a6 的补给域迁移。本轮核对 OCS v4.3 第 9、10 章和斯摩棱斯克相关专规，处理声明、付款、掷骰、战果落盘及退出保护。

## 普通地面战斗

| 步骤         | 决定与执行者                                                             | 提交约束                                                                         |
| ------------ | ------------------------------------------------------------------------ | -------------------------------------------------------------------------------- |
| 宣布         | 攻方选参与单位及防御格；同格全部守方战斗单位防御                         | 引擎验证相邻、攻击资格、模式及本环节攻击账本；未付费草稿可以取消                 |
| 战斗补给     | 双方声明实际来源、部队储备选择；守方可拒绝供给；现有面板一起确认双方决定 | 全部付款验证成功后一起提交盘面和状态；失败仍停在补给步，不留半笔扣款             |
| 行动值       | 攻方先公开实际参战单位，守方随后公开；NKVD 约束由引擎检查                | 预选不等于公开；公开的攻方选择锁定；面板不再允许改选已锁定单位                   |
| 地形及攻防比 | 守方为进攻堆叠选格内或格边地形，为自己选格内地形                         | 引擎计算修正战力和初始列，组件不重复计算                                         |
| 奇袭         | 自动掷 2d6；发生奇袭后另掷 1d6 横移                                      | 行动值差值与工事修正按 9.8 使用                                                  |
| 战斗骰       | 自动掷 2d6，应用行动值差值和完整工事等级，查 CRT                         | DG 立即作用于守方，撤退前可读取；越步和重复调用不消耗随机源                      |
| 战果         | 攻方强制损失 → 攻方选项 → 守方强制损失 → 守方选项                        | 引擎验证 AR 第一损失、军力容量及选项；守方忽略选项按 9.10c 判断                  |
| 撤退         | 双方分别选自己的路径；地图和热坐共用第一份未选齐的计划                   | 保留完整距离、地形、战斗开始位置、DG/ZOC、跟随者判定；路径中的 9.14 处置逐项完成 |
| 推进及进击   | 常规战斗由攻方选择合格单位推进，成功突袭强制推进；再按 9.13 判进击标记   | 特殊位移未解决时不能跳过推进；结束后下一次地图选战斗会清理现场，但保留攻击账本   |

补给成功提交后必须处理到结束。取消、改目标/攻方、切换查表模式、换阶段、换回合、换方及手动跳环节均不能抹去义务。整局重置和读取完整存档使用明确的复位路径。突袭仍复用同一条九步链，由攻击类型、奇袭表、推进与移动 MP 收束规则处理差异。

## 火炮与空中轰炸

| 步骤      | 规则与操作方                                                                       | 本轮保证                                                                           |
| --------- | ---------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------- |
| 宣布      | 先确定参炸类别、目标格及整体目标                                                   | 同一场只用同一类别；后续结算使用宣布目标，不受草稿选格覆盖                         |
| 补给      | 火炮按横移前初始列收费，来源满足共同 HQ/补给站及实际可达要求；空军免补给           | 验证成功才更新状态和扣款；已提交不能取消或改选；阶段格/单位账本继续生效            |
| 横移      | 战斗单位表使用密度、工事、合法地形、观察员、战略模式、空军短程等事实；目标方选地形 | 设施表不使用这些横移；热坐在目标决定时交给目标方                                   |
| 掷骰      | 战斗单位表 2d6，设施表 1d6，普通半点结果补 1d6                                     | 记录实掷骰面；非法手填值不改变骰源；重复按钮不重掷                                 |
| 军力与 DG | 目标拥有者分配损失；不套用战斗的 AR 优先损失规则                                   | 以明确的增量损失扣现有军力，归零走公共淘汰通道；限制容量及重复承受者               |
| 设施结果  | 基地降级、逐机损失、运输破坏分别处理                                               | 基地读取真实等级并写回；逐机骰只认目标格实际飞机，缺省自动掷 1d6；运输破坏真实入账 |

`[1/2]` 的条件解释继续使用现有引擎。需要取整骰时，4–6 损失一点军力并 DG，其余仅 DG；本轮修正了这里误用 2d6 的错误。

## 修复的问题

1. 轰炸补丁把“损失点数”当“剩余军力”：一军力单位中一点损失仍剩一点，多军力单位也会被错误设成一点。现以 `stepLoss` 明确传递损失并正确淘汰。
2. 半点取整误用主轰炸骰函数，实际掷成 2d6，甚至超出合法单骰范围。
3. 越步或重复掷骰先消耗随机源、再被引擎拒绝。现预先检查步骤。
4. 战斗或轰炸付款验证失败前已经推进状态。现把状态提交放到全部付款验证之后。
5. 已付款轰炸能被取消、改选或开关工具覆盖；战斗部分入口也可破坏现场。现统一保护已提交义务。
6. 攻方 AR 半步声明未写入状态，先后顺序仅存在于文案。现保存并锁定公开声明，正式入口强制先攻后守。
7. 热坐未覆盖守方 AR、地形及轰炸目标决定。现共享角色投影，撤退交接也与地图一致。
8. 基地降级和运输破坏仅打印成功日志。现通过设施端口实际写盘；逐机损失拒绝目标以外的飞机编号。
9. 撤退穿越特殊目标遇到待决就返回，后续路径没有续跑入口。现保留顺序队列，每次位移决定后继续，不重复判已处理格。

## 模块边界

| 模块                                  | 职责                                                                                                            |
| ------------------------------------- | --------------------------------------------------------------------------------------------------------------- |
| `stores/fire-resolution.ts`           | 独立持有战斗/轰炸现场、输入、骰面、等待标记；编排掷骰、轰炸结果及撤退穿越队列；盘面、设施、淘汰与日志经端口提交 |

## 验证及剩余范围

专项回归覆盖实际减损/淘汰、超额损失、取整骰及骰源不变、义务保护、付款重试、AR 顺序、热坐角色、实际基地和飞机损失、撤退队列恢复。原账本测试里“付款后直接取消或换段”的夹具改为真正完成战斗/轰炸，再检查账本；保留原有每环节/阶段一次的断言。旧档可空字段恢复仍保留，不因新域复位丢弃已保存账本。

本轮迁移了交战现场、骰序、轰炸结果提交和待决编排；地形、战斗补给及部分特殊战斗函数仍在工作台。仍按完整战斗结算点存档，不声称支持中途恢复战斗。斯摩棱斯克没有海军与港口盘面，本轮没有新增这些实体。复杂可选规则组合仍需专项认证。

最终验证：24 个专项文件、284 条用例通过；全量 303 个测试文件、4007 条用例全部通过。类型检查、ESLint、全仓格式检查、架构扫描和生产构建通过。构建保留既有单包体积提示。
