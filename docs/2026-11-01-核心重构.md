# 对局核心重构

本轮从 d7837ee 开始，将阶段生命周期、完整对局快照、盘面版本兼容及状态提交拆成独立模块。保留当前地图、数据、规则函数、对外操作接口和存档格式。

## 模块边界

| 模块                          | 职责                                                                          |
| ----------------------------- | ----------------------------------------------------------------------------- |
| `engine/game-lifecycle.ts`    | 只根据正式记录轨判断阶段/回合变化，决定追溯重判和自动增援时点；统一行动方计算 |
| `stores/phase-coordinator.ts` | 编排阶段推进，先处理义务，再清理和发布胜利判定；不使用界面显示用的阶段兜底    |
| `engine/board-snapshot.ts`    | 纯粹解析盘面信封、检查版本和字段、为旧档补显式默认值；返回独立的完整值        |
| `stores/snapshot-registry.ts` | 完整值与 Pinia ref 的映射；捕获时深拷贝，恢复后处理失败时回滚全部映射字段     |
| `stores/game-snapshot.ts`     | 统一捕获、校验会话＋盘面＋初设，供实际保存和读取入口使用                      |
| `stores/workbench.ts`         | 现有规则域与界面的兼容适配器；不再自行维护快照解析器和阶段生命周期编排        |

这轮不只是搬文件：兼容性检查不再修改“上次校验的档案版本”，恢复始终独立解析自己收到的载荷；版本 3.5 等未声明版本被拒绝；旧档缺省值来自固定契约，不能读取当前局中的残留值；盘面适配后处理失败有独立的字段回滚保护。

## 验证

新增测试覆盖旧档补默认值、不共享对象、未知版本、缺字段、校验无副作用、后处理失败回滚、整局快照一致性、天气子步、反应行动方、阶段/回合重置顺序和待决义务阻止推进。

原有整局回归继续覆盖七剧本双方初设和首回合、剧本1推进到终止并重开、冷读档、整备付款、恢复幂等、E段实际移动，以及战斗到损失/选项/推进的完整收束。本轮全量验证为301个测试文件、3990条用例全部通过；类型、lint、格式、架构扫描和生产构建均通过。

## 后续迁移边界

此次完成的是生命周期与持久化边界，尚未把工作台里的所有移动、战斗、空军、补给状态迁成单个强类型运行时。下一阶段按规则域将正式状态和动作提交迁入统一状态模型；每迁一个域保留既有接口并用相同流程回归对照，最后收缩兼容适配器。

仍保留完整结算点存档策略；战斗中途续局、完整动作重放以及所有复杂规则组合的专项认证不在本轮冒充完成。
