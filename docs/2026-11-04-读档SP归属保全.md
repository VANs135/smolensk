# S1/A3第八批：读档SP归属保全

基线`3c8cb0d`。检查SP流转发现，`normalizeSpDumpsOnLoad`只按阵营和格号归并，可能把同格不同集群的SP合成一笔并沿用第一条归属；第一条未归属时还可能使后续已归属SP丢失实际归属。

本批把装甲集群归属加入轴方补给站恢复归并条件。不同集群、未归属与已归属的条目各自保留；同归属仍保留第一条ID并加总资源。苏方归并口径不变。恢复提示同步说明只归并同归属条目。没有更改存档格式或规则数值。

新增3项store回归，从真实开局进入存档流程，构造同格多来源SP账本，验证两种不同归属组合保留每笔数量及归属，再次存读档结果稳定；同归属条目仍合并，资源总量保持23T。测试构造来源账本，不冒充已经通过真实运输装卸流程。相关2个文件26项回归通过。

本批不宣称完成运输、装卸、实际付款或完整资源总账验收，S1/R0仍未完成。原有两份未跟踪UI分析文档保持原样，不纳入提交。

最终全量324个文件、4242项测试通过（278.16秒），类型、ESLint、全仓格式、架构检查及生产构建通过，构建保留既有大包提示。
