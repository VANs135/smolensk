# A3第十四批：按实际供养重算费用

基线`6d9f95b`。D段供养计划按累计RE计算整T追加费用；两名1RE单位的计划费用分别为1T和0T。此前实际结算直接消费计划费用，第一名付款失败后，第二名仍可按0T成功供养，造成没有实际付款却摘除断补标记、漏掉损耗义务。

本批将追加费用提取为纯引擎函数，由计划与实际结算共用。实际结算只累计成功供养单位的RE，付款失败或单位已不存在时不增加累计量；下一名按实际累计量重新计算追加费用，再从自身可达来源付款。成功后才记入已供养名单及实际支出，失败保持断补并进入实际损耗义务。仍使用既有计划中选定且预算允许的名单，不自动替玩家扩选单位。

新增3项行为回归：首名失败后余量1T时第二名实际扣1T；余量0T时两名均断补并承担损耗；两名都正常付款时仍仅总付1T。失败路径同时检查实际支出日志与重复提交不重复收费。修改前前两项因付款请求为`[1, 0]`而失败，修改后相关5个文件53项回归通过。

边界：保留现有供养批次的累计RE口径，没有完成不同可达来源间的额度分组与整体分配验收。真实拖取/投递网络、资源总账、待决损耗存读档、完整回合及人工界面验收仍需继续核对，S1/R0未签收。存档结构与规则数值不变。原有两份未跟踪UI文档未修改、未提交。
