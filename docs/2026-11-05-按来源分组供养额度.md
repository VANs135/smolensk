# A3第十五批：按实际付款来源分组供养额度

基线`7fae13e`（交接文档提交；程序基线`904a6c0`）。交接文档 §6 点名的「跨来源借用已付费额度」已在真实工作台复现：D 段 12.6c 吃图上补给的批量取整按**全阶段全局**累计已喂 RE，而付款是逐单位从**各自可达补给站**扣。两座互不可达的补给站各供一枚 1RE 单位时，计划给出`[1T, 0T]`，第二名不从自己的站扣分文却摘掉断补标记；其中一组无余额时仍被判`affordable=true`，等于凭空补给。

规则依据：OCS v4.3 12.6c（txt:1948-1952）「每消耗 1T，就可以为最多 2RE 的战斗单位提供追溯补给（前提是单位在补给站的拖取或投递距离内）……所有小数向上取整」；12.3a/12.3b 是仅有的取补途径。1T 是从补给站**实际消耗**的 SP，取整留下的零头属于付过款的那一组来源；仓库交互链已按同一补给站记账（`oosFedReByDump`，`workbench.ts:3935-3959`），本批让 D 段与它对齐。规则未明定跨站转移额度，按既有裁定取保守值，不施加该效果。

改动：

- `engine/rules/supply-phase.ts` 新增`FeedingSourceFacts`（来源组键＋该组实际可用 T）；`planSupplyPhase` 可选`feedingSources`，按组分别累计已喂 RE 与预算，计划条目只在给出来源事实时附`sourceKey`；未提供时保持「全阶段一批」的旧口径（旧档与既有调用兼容）。
- `stores/supply-phase.ts` 新增可选`feedingSources`事实端口；落盘按计划里的`sourceKey`分组重算追加费用，付款失败者不占该组额度，旧计划无该键时沿用全局口径。
- `stores/workbench.ts` 由`deliverableDumpsFor`（与付款端口同源）按可达站 id 的有序集合生成组键，可用 T 取实际持有量，不采用玩家输入的数字。
- 存档字段表与版本不变，未新增存档字段；规则数值不变。
