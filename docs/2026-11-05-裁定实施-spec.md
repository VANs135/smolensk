- **用例**：`axis-consolidation-3-3d-pending.test.ts` 三条启用；`consolidation-axis-ban.test.ts`
  两处期望按 3.3d 更新（飞机由"拒"改为"允许"，标注条款与裁定日期）；源码守卫改查 3.3d 文案。

## 5. ⑦ 3.3c 撤离 + 通用选择机制（已实施）

### 5.1 规则依据与口径

- 专规 3.3c：「On 19 August, start rolling during every Axis Reinforcement Phase until a division,
  either SS Reich or 14th Motorized, is Removed (using the 1.6a procedure). See Axis Arrival Card.」
  表值：`1 → remove SS Reich (all)`、`6 → remove 14 Mtr (all)`、`2-5 → roll again next turn`。
- 1.6a：「When a unit is called on to be "Removed" by the arrival charts **it, or else a unit with
  identical factors**, is immediately removed from play, regardless of its current situation
  (even if in the dead pile or surrounded).」
- 用户裁定（2026-11-05）：撤离结果出现时**直接移除**该编队；若该编队已无算子在场，**由玩家从符合条件者中选择**。
  通用交互要求：高亮有可选单位的格子、玩家点选；堆叠中只列可选单位。

★ 口径（**实现依据：1.6a 原文**；2026-11-05 用户裁定"按原文来"，无需另裁）：

1. 「已被消灭」＝**盘面与死亡堆都找不到该编队算子**。依据：1.6a 原句
   「…is immediately removed from play, **regardless of its current situation (even if in the dead pile
   or surrounded)**」⇒ 死亡堆内的目标仍**直接**移除、不触发选择。
2. 「符合条件」依据 1.6a 原句「**it, or else a unit with identical factors**」：本实现取**战斗面印值
   `attack`/`ar`/`ma` 三元组**相等（不含移动力 / 炮击值 / 军力）。替补只在**盘面**算子中挑选
   （死亡堆无格可点，不列入——界面要求"高亮格＋点选"）。
3. 表值的 `(all)` ⇒ 一次移除该编队**全部**算子（盘面地面 + 死亡堆地面）。
   空军单位**没有 `formation` 字段**，无法按编队匹配；且 SS Reich / 14 Mtr 均无飞机 ⇒ 行为上等价（不虚构匹配）。

回滚点（技术留痕，不挂审批）：`workbench.ts` 的 `resolveVariableExitNow` / `variableExitSelectionSet`，
以及 `tests/engine/unit-selection.test.ts`、`tests/stores/variable-exit-flow.test.ts` 里
"同印值替补 / 死亡堆直接移除"两组断言。

### 5.2 引擎：可复用「可选单位清单」（新文件 `src/engine/rules/unit-selection.ts`）

纯函数、零规则判断（只做集合运算），供任何"规则要求玩家选单位"的情形复用：

```ts
export interface UnitSelectionCandidate {
  id: string
  col: number
  row: number
  /** 是否可选 */
  eligible: boolean
  /** 不可选原因（eligible=true 时忽略；本机制只列可选者，故一般不用） */
  reason?: string | null
}

export interface UnitSelectionHex {
  col: number
  row: number
  /** 该格**可选**子集（不含不可选者） */
  ids: readonly string[]
}

export interface UnitSelectionSet {
  /** 全部可选 id（按输入顺序、去重） */
  eligibleIds: readonly string[]
  /** 有可选单位的格（只含有可选子集的格；本机制不给"整格都不可选"的格高亮） */
  hexes: readonly { col: number; row: number }[]
  /** 每格可选子集 */
  byHex: readonly UnitSelectionHex[]
}

export function buildUnitSelectionSet(
  candidates: readonly UnitSelectionCandidate[],
): UnitSelectionSet
```

- 排序：`byHex` 与 `hexes` 按 `row` 升序、同 `row` 按 `col` 升序，保证界面与测试稳定。
- 只把 `eligible === true` 的候选放进 `eligibleIds` / `byHex` / `hexes`。
- 单测：空输入；全部不可选；同格混选（只列子集）；跨格混选；重复 id 去重；排序。

### 5.3 引擎：撤离表 → 编队代号映射（`src/engine/rules/variable-exit.ts`）

```ts
/** 战役称谓 → 单位库编队代号（3.3c 表值 "SS Reich"/"14 Mtr" ↔ formations.json 的 code） */
const VARIABLE_EXIT_FORMATION: Readonly<Record<string, string>> = {
  'SS Reich': 'SS-R',
  '14 Mtr': '14MTR',
}

/** 表值里的称谓取编队代号；不认识则 null（不做模糊匹配） */
export function variableExitFormationOf(removedUnit: string): string | null
```

- 只做精确查表，不猜；`null` 时由调用方记警告、不推进。
- 数据侧现状（2026-11-05 核实）：`formations.json` 只有 `formationId` / `formationCode`，**没有**战役别名
  ⇒ 本表暂为引擎内特例（不虚构数据条目），已列入待审批表次要条目 ⑦-a。
- 单测：两个称谓各自命中；`"SS Reich (all)"` 之类的**已剥离**形态之外不命中；未知称谓 → `null`。

### 5.4 Store：`workbench.ts` 的落盘（照 1.6a，复用既有设施）

新增/修改（不新增存档字段）：

1. **修正 `resolved` 置真条件**（当前对 `reroll` 也置真，与 3.3c「until … is Removed」相反）：
   仅当 `data.variableExit.kind === 'remove'` 时 `variableExitResolved = true`；`reroll` 保持未了结，
   下一回合继续掷。
2. `resolveVariableExitNow(result)`（内部函数，掷骰分支调用）：
   - `formation = variableExitFormationOf(result.removedUnit)`；`null` ⇒ `pushLog('warning', …)` 并返回。
   - `targets = [...units, ...deadPile 的地面条目].filter(u => u.side === 'axis' && u.formation === formation)`
     （`ConsoleAirUnit` 无 `formation` 字段，不参与匹配；两编队均无飞机）。
   - `targets.length > 0` ⇒ 逐个 `removeFromPlayEverywhere(u)`（1.6a：不论处境，含死亡堆），
     每个记一条 `pushLog('info', '… 按 3.3c 移出游戏（1.6a）', '3.3c')`；
     `recordSettlement({ action: 'variableExit', rule: '3.3c', data: { mode: 'direct', removedUnit, formation, unitIds } })`。
     选择流程不打开。
   - `targets.length === 0` ⇒ 打开选择：`recordSettlement({ action: 'variableExit', rule: '3.3c',
data: { mode: 'select', removedUnit, formation } })` + `pushLog('warning', '3.3c：该编队已无算子在场，须由玩家选择同印值算子（1.6a）', '3.3c')`。
3. `variableExitPendingSelection`：**从 `session.log` 反向推导**（不新增 save 字段，读档后自动恢复）——
   从日志末尾往前找**第一条** `action === 'variableExit'` 的条目：`data.mode === 'select'` ⇒ 待选，
   返回 `{ removedUnit, formation }`；`data.mode` 为 `direct` / `confirm` ⇒ `null`；没有该条目 ⇒ `null`。
4. `variableExitSelectionSet`（computed）：待选时
   - 参考印值集 = `unitsAxis.units.filter(r => r.formation === formation)` 的战斗面 `attack/ar/ma` 三元组；
   - 候选 = `units`（盘面）中 `side === 'axis'`、`formation !== 目标编队`、`isCombat`、且印值三元组命中参考集者；
   - 全部 `eligible: true`（本机制只列可选）⇒ 交给 `buildUnitSelectionSet`。
   - 空集 ⇒ 面板为空（`CounterPicker` 自带「本组没有可选的算子」），并
     `pushLog('warning', '1.6a：盘面无同印值算子可替 ⇒ 请裁判手工处理', '1.6a')`（留白，不推算）。
5. `variableExitPickItems`（computed → `CounterPickerItem[]`）：仅含 `eligibleIds`，
   `id = instanceId`、`imageUrl = counterImageUrlOf(unit)`、`name`、`selected = false`、`hex`、`groupKey = 'col.row'`。
6. `variableExitPickHexes`（computed → `HexRef[]`）：`variableExitSelectionSet.hexes`（供地图高亮），
   **仅在"轴方 + 增援阶段"时非空**——切集团军 / 离开增援阶段 / 确认移除 / 读档后已确认，一律清空，
   避免"格还亮着但已不可点"。
7. `confirmVariableExitSubstitute(instanceId)`：id 必须在 `eligibleIds` 内（否则拒绝并记日志）；
   `removeFromPlayEverywhere` + 日志 + `recordSettlement({ action: 'variableExit', rule: '1.6a',
data: { mode: 'confirm', removedUnit, formation, unitId } })`。
8. `setVariableExitHover(instanceId | null)`：`hoverHex = 该算子所在格`（null 清除）。

★ 并发/顺序：直接移除与选择都在**增援阶段**发生；待选期间不阻止玩家继续掷骰，但 `resolved` 已置真，
后续回合不再掷，直至确认。
