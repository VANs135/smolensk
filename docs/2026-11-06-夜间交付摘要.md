### R2（裁定）12.3c 采纳读法 A

**原文**

- 12.3c：补给到达**单位相邻格**即可（适用直接拖取与指挥部投递）；不是把范围整体扩一格。

**查到的偏差**

- `hqDeliveryDumpKeys`（`src/stores/workbench.ts`，原 ~9963 行）原先只对**单位所在格**调用单目标距离（`countSupplyDistanceViaTable({ to: unit.hex })`），没有"邻格在范围内"的分支 ⇒ 第 21 格会被误判为不可得，且不报错、只少算。

**改了什么**

- `src/engine/rules/trace-supply.ts` 新增 `countSupplyDistanceToUnitViaTable`（`trace-supply.ts:626`），目标集合＝`selfAndNeighbors(unitHex)`（自身首位 + 6 邻格），委托读表版多目标 Dijkstra，取 min、无早停。
- `countSupplyDistanceToAnyViaTable`（`trace-supply.ts:649`）为读表版多目标入口；删除不再使用的单目标 `countSupplyDistanceViaTable`。
- `src/stores/workbench.ts` 4 处 HQ 投递判据（`6852` / `7074` / `7634` / `9973`）统一改用 `countSupplyDistanceToUnitViaTable`；直接拖取路径此前已用 `selfAndNeighbors`，不改。

**验收夹具（`tests/engine/hq-delivery-adjacency.test.ts`，全绿）**

1. 10 MP / 20 格连续道路（0.5 MP/格）：第 20 格（10.0 MP）⇒ 可得。
2. 第 21 格（自身 10.5 MP 在外、邻格=第 20 格）⇒ **可得**（读法 A）。
3. 第 22 格（自身与全部邻格都在范围外）⇒ 不可得。

### R3（裁定）补给阶段流程与 12.8e 首回合豁免

**原文**

- 12.8a：「在补给阶段中，无法'获得追溯补给'或'吃图上补给'的友方堆叠会被标记为断补，并检查损耗。……标记为断补的单位必须在每个友方补给阶段**结束时**检查损耗。」
- 12.8e：「在一个单位发现自己没有追溯补给的**第一个回合**（不是在'吃图上补给'之后，也不是在使用补给储备或树皮汤等特殊的追溯补给方式之后），上述条件将被免除，且成功概率会提高，即获得 +1 的掷骰修正，并且运输点数也允许进行突围。」

**改了什么**

- 新增 `isOutOfSupplyNow(unit, turn)`（`src/engine/rules/trace-supply.ts`）：`!hasTraceSupply && sustainedBySpecialSupplyTurn !== turn`。
- `refreshTraceSupply`（`workbench.ts:11089`）：不再把"本回合靠特殊方式续命"算进 `inSupply`；`cutSinceTurn` 仅在真正断补且尚未开始时置回合。
- 喂食落盘（`supply-phase.ts:302`）：只有 `assessment.status === 'inSupply'` 者 `markTraceSupply(true)`；被喂饱者只 `markSustainedBySpecialSupply`（写 `sustainedBySpecialSupplyTurn`），**不写 `hasTraceSupply`** ⇒ 删除"两路径并存"。
- `markSustainedBySpecialSupply`（`workbench.ts:10847`）：若 `cutSinceTurn === 当前回合` 则清空（续命当回合不算第一断补回合）；若连续断补早已开始则不重置起点。
- 所有 `outOfSupply` 消费点（`toBattleUnitView` / `hotseat` / `map-view` / 损耗义务）统一改 `isOutOfSupplyNow`。

**与用户口径逐点比对**

| 用户口径                 | 当前实现                                                                                                                      | 判定                     |
| ------------------------ | ----------------------------------------------------------------------------------------------------------------------------- | ------------------------ |
| 先判追溯补给             | 进入补给阶段即 `refreshTraceSupply`（`workbench.ts:5442`）                                                                    | 一致                     |
| 再判是否吃图上补给       | `planSupplyPhaseNow` → `applySupplyPhaseFeedingNow`（`supply-phase.ts:134/302`），在追溯判定之后                              | 一致                     |
| 不吃就**马上**断补判损耗 | 喂食后立即用 `isOutOfSupplyNow` 重算 `attritionDuty`（`supply-phase.ts:364`），损耗未结清不得离段                             | 一致（同一补给阶段内）   |

| 下个回合突围有豁免/修正  | 2.2 SOP：**突围是运动阶段首环、补给阶段在其后** ⇒ 断补后第一次突围必在**下一回合** ⇒ `cutSinceTurn === turn - 1`（`e46cf7c`） | 一致（已由回合序列闭环） |

**验收夹具（`tests/stores/trace-firstturn-flow.test.ts`，已按真实回合序列改写）**

- T 补给阶段落断补（`cutSinceTurn = T`）⇒ **T+1 运动阶段突围**免除 A/B 且 +1 DRM；T+1 开局不再落起点。

- 恢复补给 ⇒ 清零；再次断补 ⇒ 从**新的**补给阶段 T' 重新算，豁免落在 T'+1。

- 已在连续断补中吃图上补给 ⇒ 不重置 `cutSinceTurn`，该回合不判补但**无**首回合豁免。
- 12.6h 空投当回合豁免。

## 3. R4 schema 方案

### 字段

```ts
// src/data/schema/units.schema.ts
throwMobility: z.object({
  combatFace: z.enum(['leg', 'truck', 'tracked']).optional(),
  moveFace: z.enum(['leg', 'truck', 'tracked']).optional(),
})
  .strict()
  .optional()
```

- 位置：与 `throwRange` 同级，属 HQ 印值的一部分。
- 缺省值：不写字段 ⇒ `ConsoleUnit.throwMobility = null` ⇒ `throwMobilityOf` 返回 `'truck'`（12.3a 默认）。
- 逐面：只写一面时，另一面回退 `truck`（当前 `throwMobilityOf` 的实现；是否应回退到"另一面的印刷移动类型"属未提，见"待裁定 D"）。

### 迁移方式

- **无迁移**：字段可选，生产数据 0 写值；旧存档不含该字段照常加载（状态里本就不存该字段，由单位库现算）。
- 后续作品若要徒步/履带投递 HQ：在对应单位 JSON 写 `throwMobility` 即可，引擎零改动。

### 缺省兼容性验证办法

1. 数据扫描：`units-*.json` 中 `throwMobility` 写值数 = 0（本夜实测 axis 0/13、soviet 0/17）。
2. 路径等价：缺省时 `throwMobilityOf` 恒返回 `'truck'`，`toThrowHqView` 的参数与修前完全相同。
3. 数值等价：`throw-mobility.test.ts` 断言"缺省 vs 显式 truck"的投递距离逐字段相同。
4. 回归：全部既有补给用例 + `drawable-dumps-equivalence.test.ts` 一字未改全绿。
5. 全量：`vue-tsc` / ESLint / Prettier / `arch` / `build` / 全量 vitest 全绿（见 §6）。

**判定（读法 2：断补判定发生在突围之后）**

- 12.8a：「在补给阶段中，无法"获得追溯补给"或"吃图上补给"的友方堆叠会被标记为断补，并检查损耗。……标记为断补的单位必须在每个友方补给阶段**结束时**检查损耗」

  ⇒ 断补后**第一次可执行**的突围必定在 **T+1 运动阶段**，它就是 12.8e 所说的"第一个回合"
- 实现：`isFirstTurnOfBeingCut = cutSinceTurn === turn - 1`；且 `refreshTraceSupply` **只在补给阶段**落起点
  （运动阶段进入时只重判标记、不写起点，避免"敌方回合被切断"白拿一轮）；提交 `e46cf7c`
- 12.6c 自洽性：「12.6c 吃图上补给。无法向补给源"追溯补给线"的战斗单位，可以通过"吃"SP，来获得追溯补给」
