## 三、冲突报告（不择一，等用户裁定）

### ① 14.10a × 专规 2.2b × 数据：本作无合法「战斗单位空投」路径

- 14.10a 要求：只有带 Para 标识的**战斗单位**可空投。
- 专规 2.2b：**禁止苏军计划空降**（`air-interaction.ts:714-715` `plannedAirdropNotAllowedForSide`）。
- 数据：仅 3 个苏军伞兵旅 `capabilitiesRaw:["para"]`（`units-soviet.json`），且 `record.specialized` 未含 `para`，转换层只读 `specialized`；轴方无 Para 单位。
- 结论：若把 Para 改为**按单位**判定，本作只剩「苏军 Para 单位」，但 2.2b 又禁其计划空投 ⇒ **合法路径为空**；若维持全局布尔，则 14.10a 的「按单位适用性」形同未实现。
- 需用户裁定：A) 本作按「空中打击/无空投」处理，14.10a 记「不适用」；B) 认 2.2b 只禁「计划空投」而 SP 空投不受限（14.10b 注：补给空投从不需要预计划），并明确是否允许苏军战斗单位空投；C) 其他。

### ② 12.6h × 14.10b/14.10c：豁免是「计划」还是「实际执行」

- 12.6h 注：**计划空投的单位**在被空投的回合不需要追溯补给。
- 14.10c：计划可在整备阶段取消/延迟，取消后计划不复存在。
- 现状：引擎只在**成功交付**时写 `airDropExemptTurn`。
- 冲突点：若单位当回合被计划但最终取消/延迟，是否仍享 12.6h 豁免？原文两句无法同时字面满足。
- 需用户裁定，裁定前**不改** `airDropExemptTurn` 写入时机。

### ③ 14.9d「SP 不能在任务前后移动」× 12.2a 防接力

- 两句同向（禁接力），无实质冲突；已在 `checkAirTransportMovementHandoff` 侧把关，本批只补断言，不新增语义。
