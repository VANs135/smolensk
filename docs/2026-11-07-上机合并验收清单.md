## 分配原则

三份来源的验收项都不随剧本变化。为“按剧本分组”且“去重”：

- **剧本 1** 承担 P7 连续签收、R1 完整 A–H、UI1–UI6 全部肉眼项（19 回合，能跨关键日期）。
- **剧本 2** 承担 R2 全部空运/空投与旧档（8 回合，上机成本最低）。
- **剧本 3–7** 只做同一批通用项的抽样冒烟，不重复展开，也不编造来源里没有的剧本专属项。

上机前：`npm run dev`，浏览器开 `http://localhost:5173`，**不要清 localStorage**（旧档兼容项要用）。

### A6 R1：断补损耗与分摊（含 P8 回归点）

**进哪一屏**：对局台 → 流程条推进到 `D 补给` → 补给结算面板。

**做什么**：先让若干单位断补；点 `掷损耗骰`；对 `全部单位各 1 步` 与 `按点数` 两类结果分别分摊；点 `落盘分摊（12.8b）`。

**应看到**：

### A7 UI4/5：移动额度与预览

**进哪一屏**：对局台 → 选中一个战斗单位 → 右栏 `移动` 面板。

**做什么**：看额度；悬停/点路径前两格；提交一步；点 `不再移动`；走入 ZOC。

**应看到**：
- `额度：可用 X / 已耗 Y / 剩余 Z MP`，三个数与单位印值、本回合已耗一致。
- 预览行显示 `路径 N 格 · 累计 X MP｜本步 Y MP`，且提示 `预览不扣 MP、不付款、不掷骰；提交时由规则域重新检查。`
- 预览过程中右侧额度**不变**；提交后 `剩余` 减、`已耗` 加，差值等于本步消耗。
- 点 `不再移动` 后出现“本环节（X）不做移动”的说明，且列出 `C 移动·模式与移动`、`E 反应·反应移动`、`G 进击·进击移动` 三个环节（P8 投影，顺序不得变）。
- 进入 ZOC 时出现 `进入并停止（4.5a-A）` 与 `留在原格` 两个选择；选前者后单位停在 ZOC 内。

来源：UI4/5 + P8 · 已实现待验

## B. 剧本 2 `Short Campaign`

参数：8 回合，8 Jul 41 → 1 Aug 41；先手 **axis**；先布设 **soviet**。

### B1 空运核心四项（R2）

**进哪一屏**：对局台 → 右栏空军面板（OCS 14.0/15.0）→ 任务分配。

**做什么与应看到**：

1. **14.9a 两架合并承运**：选任务类型 `空中运输`，勾选两架运力各 0.5 T 的运输机，装载 `1` T SP。
   - 应看到两架都被点名，任务可执行；装载计数为 `1`。
   - 只用一架时装载 `1` T 被拒，提示 14.9b 超运，任务不宣布，飞机仍为激活。

2. **14.9b 拒绝超运且不留存**：用一架 1 T 运力装 `2` T。
   - 应看到拒绝说明；任务不产生货单，不出现“先装后丢”的半截账。

3. **14.9d 移动限制**：空运前后各移动一段。
   - 应看到本阶段已耗 MP 累加；总移动超过印刷 MA 的 1/2 时提交被拒并给出 14.9d；反应阶段上限为 1/4。

4. **14.9e 航程三档**：分别做正常航程、两倍航程、半程。
   - 正常：任务后飞机返航到起飞基地，任务结束时仍为 `激活`。
   - 两倍：目的地格飞机显示 `非激活`。
   - 半程：面板 `运力 X T` 变为两倍（如 1 T → 2 T），返航只到半程可达基地。

来源：R2 · 已实现待验（★核心必验）

### B2 空运扩展与账本（R2）

**做什么与应看到**：

- **14.9f 卸载限额**：在等级 2 基地卸 5 T。应看到上限 `2 T × 等级 = 4 T`；超额时提交被拒，勾选 `超限卸载时，本次运输机全部留在目的地并转非激活（14.9f）` 后才可执行。
- **逐机货单**：两架各装 1 T，返航前任一架被击落。应看到只有该机的 1 T 消失，另一架照常卸载。
- **多起点**：两架分别从两个基地各装 1 T。应看到两个基地各扣 1 T，返航各回各基地。
- **部分留场**：一架留场、一架返航。应看到留场飞机 `非激活` 且停在目的地，返航飞机回原基地。
- **离图盒扣账/回盒**：盒 `2 SP + 0 T` 装 1 SP。应看到盒变 `1 SP + 0 T`；未卸下的货在任务结束后回到盒，总数不丢。
- **旧档 v6**：读入旧档后补给站账本仍显示原 `SP + T`，种子与已掷次数一致。

来源：R2 · 已实现待验

### B3 补给空投（R2，★核心必验）

**进哪一屏**：对局台 → 空军面板 → 任务类型 `空投` → 装载 SP → 执行。

**做什么与应看到**：

1. **不要求计划**：计划回合留空/0、执行回合为当前回合，直接执行。应看到任务成立，不出现“须提前 ≥2 回合”的阻断。
2. **双方都能空投**：轴心国行动时一次、苏联行动时一次，两次都成立。
3. **轴方反应阶段可执行**：行动方=轴心国、阶段=反应，重复一次空投，任务成立且返航步照跑。
4. **损失骰**：每 1 T 掷 2 骰。应看到逐 T 的 `掷 X+Y=Z` 与失败 T 数；失败部分从货单扣除。
5. **落点有敌方战斗单位**：空投的单位货物被摧毁。应看到单位从盘面/货单移除，日志有 `摧毁` 条目；纯 SP 不受此条。

来源：R2 · 已实现待验（★核心必验）

### H1 铁路修理单位“库为空”误报（13.3g/13.3f）【已修 2026-11-07】

- **修复前现象**：补给账本铁路修理段没有候选，并显示 `当前单位库里没有铁路修理单位算子…`，验收清单据此把 13.3f 判成 N/A。**该结论错误**。
- **实际数据**：库里有 3 支，`specialized` 均为 `["rail_repair"]`：
  - `su-engineer-west-rr-rgt`（苏，剧本 1/2 条件放置，3–7 固定格）
  - `ax-engineer-ge-i-2-rr-bn`（德，剧本 3–7）
  - `ax-engineer-ge-ii-2-rr-bn`（德，剧本 3–7）
- **根因（逐层）**：数据层与合并路径正常（`scenario 4/6` 经 `sharedSetupWith` 继承 3/5 后也能拿到三支）；`isRailRepairUnit` 判据读 `ConsoleUnit.specialized`，字段与取值一致。真正的缺口是 UI 层：① 空态文案过期，仍写“尚未入库”；② 候选只从盘面实例取，初设未落位/增援未到场时为空，文案却把“盘面没有”说成“库里没有”；③ 候选未按当前行动方过滤，会把对方 RR 单位摆成可点入口。
- **修复**：store 新增只读投影 `railRepairUnits`（盘面实例 ∩ `activeSide` ∩ 13.3g 谓词），组件改取；空态文案改为“须先落位或随增援到场”，并写明库内三支与剧本归属。
- **是否影响验收**：不再 N/A，改为 A6b 必验。修复前后差异：修复前误判“库空”并关闭 13.3f 验收；修复后候选按本方盘面实例出现，换轨继续由引擎复核 13.3g/13.3f。
- **同类范围**：全库仅这 3 支带 `rail_repair`，无其他单位受同一根因影响。
