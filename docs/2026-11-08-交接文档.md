## 2. 架构（依赖只能自上而下）

```
components/views → stores → engine
render/ 只读引擎输出；engine/ 不引 Vue/Pinia/DOM，随机只走 engine/rng.ts
```

| 层                        | 职责                                                        | 关键落点                                                                  |
| ------------------------- | ----------------------------------------------------------- | ------------------------------------------------------------------------- |
| `engine/`                 | 规则纯函数：移动/战斗/轰炸/补给/空军/回合流程               | `move.ts`、`combat.ts`、`barrage.ts`、`trace-supply.ts`、`turn-driver.ts` |
| `data/`                   | JSON + Zod schema + 唯一加载入口                            | `units-axis/soviet.json`、`map-config`、`scenarios/`                      |
| `stores/`                 | Pinia：界面状态 + 引擎状态只读投影                          | `workbench.ts`（编排/提交入口）、`map-view.ts`（点选与会话）、`setup.ts`  |
| `stores/session-steps.ts` | **U1-b 新增**：纯函数投影，任一会话只暴露一件事             | `planSessionSteps` / `exposedSessionStep`                                 |
| `components/`             | 面板与对话框；规则判定一律回调 store 的具名 `xxxNow/submit` | `components/session/SessionStep.vue`（按 `sessionStep.id` 只渲染一步）    |
| `render/`                 | Canvas 绘制与命中检测                                       | `map-canvas.ts` 等                                                        |

会话模型（U1-b 之后）：`sessionBase`（map-view）定"开哪类会话"，`session-steps.ts` 定"这一步做什么"，
`SessionStep` 只按 id 命中渲染；`MapDock` 提供 `SESSION_STEP_GATE`。所有入口遵循**点击操作才出现会话、一次只办一件事**。

U1-b 的四项结构（改 UI 前先读懂，别绕过）：

1. **[session-steps.ts](../src/stores/session-steps.ts)**：纯函数投影 `planSessionSteps(facts)` / `exposedSessionStep(items)`。事实全部来自既有 store 投影与引擎状态机，本模块只排顺序、写一句文案，**不做规则判定**。

- **提交纪律**：每批单独 commit + push，先红后绿；不把无关格式化夹进功能提交。
- **规则争议**：原文能确证 ⇒ 按原文实现；原文缺失/自相矛盾 ⇒ 停下报歧义（见 [CODE_SPEC](../CODE_SPEC.md) §0）。

### 9.5 已知会误导人的陷阱

- **`advanceBlock` 只做就地提示**：它由 `FlowStrip` 在推进被挡时显示一句原因，不是按钮状态来源。
- **推进按钮置灰只看 `flow.canAdvance`**：不要用"上次失败原因"去锁按钮或做禁用判据（会变成陈旧状态）；每次推进按当前 `flow` 重算。
- **人员空投入口已下线**（U0）：不要重新加回 `AirPanel` 的「单位货物」；SP 货物保留。
- **`capabilitiesRaw` 不派生能力**：它是源库原始能力串，不是分类后的规则能力；能力判定走既有 `capabilities` / 引擎谓词与 store 投影，别拿原始串自己解释。
- **战雾不是新规则**：U1-f 只做展示裁剪，不新增「侦察/探测」判据；原文没有可执行判据的场景一律不实现。
