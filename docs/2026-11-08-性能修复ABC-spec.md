## A. 移动会话 1327ms → ≤300ms（生产包）

### 根因（已定位）

1. `buildMoveContext` 把 store 里的 `unit.hex` **引用**放进 `MoveUnitView`；该对象是 Pinia 深层响应式代理，
   BFS 每步读 `hex.col/row` 都走 Proxy get（CPU 采样：`Vue reactive get` 362ms）。
2. `evaluateStepFrom` 每走一步都做**全单位扫描**：`hasEnemyCombatUnit`、`stackCombatReAt`、
   `inEnemyZocAt → zocSourcesOf`（每步新建 sources 数组），ZOC 判定再对 sources 逐个 `areAdjacent`。
3. `crossingForStep` 每步 `new Set(...)` 重建架桥格集合（且 `violatesReciprocity` 再建一次）；
   `map.terrainsAt` / `crossingBetween` 每步重复查询（同一格/边多次）。
4. `path: [...current.path, step]` 每个节点复制整条路径。
5. `neighbor()` 每次新建 `{col,row}` 并多次读 `hex.col`（代理期放大）。

### 设计（全部为等价变换，判据/顺序不变）

| 文件 | 改动 |
| --- | --- |
| `src/stores/workbench-model.ts` `buildMoveContext` | 一次性 plain 快照：`hex` 克隆为 `{col,row}`；`safeEdgeHexesBySide`、`bridgedHexesBySide`、`ownBridgeHexByUnitId` 的值一并克隆为 plain，context 内不再持有任何响应式代理 |
| `src/engine/rules/move.ts` | 新增内部 `MoveStepFacts` 与 `buildStepFacts(context)`（每次 `computeReachableHexes` 只建一次）：按格分桶的单位索引、每方 ZOC 覆盖格集合（`zocSourcesOf` + `projectsZoc` + 六邻一次算定）、每方架桥格数字键集合、`terrainsAt`/`crossingBetween` 记忆化、六邻预生成表 |
| `src/engine/rules/move.ts` `StepOptions` | 增加**可选** `facts?: MoveStepFacts`；`evaluateStepFrom` 在提供 facts 时走索引化查询，无 facts 时行为与现在完全相同（单步点击路径不变） |
| `src/engine/rules/move.ts` `computeReachableHexes` | ① 以数字键（`col*128+row`）做状态表；② 节点只存 `parent` 父指针，输出时一次性回溯成 `path`；③ 队列用读指针而非 `shift()`；④ 六邻用预生成表就地比较；⑤ 结果记忆化：`WeakMap<MoveContext, Map<unitId, Result>>`，键天然含「起点+模式」（来自该 context 的单位视图），context 重建即「地形/盘面版本」变化；仅对**非战略、非预备**单位启用（这两类结果依赖 `traceSupplyAt`/`hedgehogLevelAt` 活回调，不缓存） |

### 等价性闸门（先红后绿）

1. `tests/engine/move-reachable-equivalence.test.ts`：固定**改前**输出（逐单位：`ok/ma/reachable` 全序列，含
   `mpSpent/minimumMove/forcedStop/path`），覆盖开阔地、道路、河、EZOC（被抵消/未抵消）、敌方占格、
   战略断补、预备+工事、6.1c 最小移动、边界格。改后逐字符一致。
2. `tests/engine/move-reachable-budget.test.ts`（**改前红**）：用 Proxy 计数的 `units` 数组 + 计数的
   `MapFacts`，断言一次 BFS 对 `units` 的读取 ≤ `单位数×20`、`terrainsAt` 调用 ≤ 地图格数、`crossingBetween`
   调用 ≤ 邻接边数。改前必然超限，改后必须通过（确定性计数，不受机器快慢影响）。
3. `tests/stores/move-context-plain.test.ts`（**改前红**）：`buildMoveContext` 产出的 `units[i].hex`、
   `safeEdgeHexesBySide`、`bridgedHexesBySide` 经 `isReactive` 判定必须为 `false`。
4. 全量 `vitest`（381 文件 / 4680 passed / 1 skipped 基线不得变差）。

## B. 突围段 734ms → ≤250ms

### 根因（已定位）

1. `breakoutPathFacts` 每个候选做**两趟全图洪泛**（2156 格 × 6 邻），每格调
   `inEnemyZocAt(moveContext.value, …)` → 每格重建全单位 `zocSources` 并逐个 `areAdjacent`（O(格×单位)）。
2. `queue.shift()` 使队列出队 O(n)，两趟洪泛退化为二次。
3. `stepPassable` 对同一格边重复 `terrainsAt`/`crossingBetween`；`seen` 用字符串键。
4. `breakoutCandidates` 每次求值重建 `createMapFacts()`（2156 格 + 6662 边索引）。

### 设计（行为不变：候选集合、顺序、判定、拒绝理由逐字符一致）

- `src/stores/workbench.ts`：扩展 `BreakoutSharedFacts`（每次求值建一份，全候选复用）
  - `zocCoveredBySide`：用引擎导出的只读投影**一次算定**每方 ZOC 覆盖格（判据仍为 4.5 的
    `projectsZoc` + 六邻；4.5b 抵消用按格分桶的 `mpLockedThisPhase` 战斗单位查）；
  - `passability`：`Map<机动类型+格边, boolean>`，同一格边只算一次；
  - `enemyCombatSides`、`tracedFriendSides` 沿用既有 `buildBreakoutUnitIndex`；
  - 洪泛改用数字键 `seen` + 读指针队列，**保留 FIFO 顺序**（拒绝理由的取证依赖访问顺序）；
  - 每格齐备事实后，单候选成本从 O(全图) 降为 O(1)（事实已在 shared 内）。
- 「只计算玩家点到的堆叠」落点：`breakoutNow`（点格即结算）本就只算该单位；列表 `breakoutCandidates`
  需展示全部灰显原因，改为惰性会改变界面信息 —— **本批次不惰性化**（为满足「行为不变」）。
  若要列表惰性化，放到 UI 批次，届时另行审批。
- 补给追踪：复用既有 `trace-supply.ts` 缓存，不新建、不改键。

### 等价性闸门

- 既有 `tests/stores/breakout-index-equivalence.test.ts` 的 `BASELINE` **一字不改**必须通过；
- 新增 `tests/stores/breakout-budget.test.ts`（**改前红**）：断言一次 `breakoutCandidates` 求值中
  `terrainsAt`/`crossingBetween` 调用次数 ≤ 格数/边数常量级，且 `units` 读取 ≤ 单位数×20；
- 全量 vitest 全绿。

### 验收

- 同一探针「切换环节→突围」≤250ms；基线快照逐字符不变；规则判定影响 = 0。

## C. 进入对局台 478ms → ≤250ms

### 根因（已定位）

挂载期 `getBoundingClientRect` 94–111ms（`perf-probe3` 采样），并与样式写入交错触发同步布局。

### 设计

- `src/components/map/MapCanvas.vue`：`syncSize` 内**一次**量取容器/画布矩形并缓存为 `surfaceRectCache`；
  `surfaceRect()`、`hexToWindow()` 只读缓存；`ResizeObserver`/缩放/滚动时失效重取。
- `src/components/map/MapDock.vue`：把「量面板基准矩形 + 量容器 + 量标题栏高度」合并为**批量读取**，
  再统一写 `left/top`（消除读-写-读交织）。
- 只动尺寸测量与 transform 写入时序，不改任何布局结果与交互判据。

### 验收

- 同一探针「进入对局台」≤250ms（`getBoundingClientRect` 自耗时 ≤30ms）；
- 全量 vitest 全绿；布局/命中测试快照不变（若有 DOM 断言用例同样必须绿）。
