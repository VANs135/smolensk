# 斯摩棱斯克棋桌 UI 重做任务方案

2026-11-08 · 交付分支 `codex/command-table-ui` · 基线 `814a57a`

## 交付目标

熟悉实体规则的玩家打开棋桌后，能直接认出当前决策方、阶段、环节和待办。选算子、选目标格、确认结果形成一条操作链。常驻文字限于状态、操作提示和规则章节号。战况、盒表、战报和设置从左侧导轨按需打开。

棋桌接入重构后的正式判定与命令。行动候选从现有阶段闸门、单位资格和目标投影取得。推进按钮读取当前阻断，独占会话按当前步骤呈现。提交前允许改选，提交后的必做步骤由原会话继续承接。界面验收以实际入口能提交合法操作、拒绝非法操作并回显结果为准。参考 [交接文档](./2026-11-08-交接文档.md) 和 [阶段与操作矩阵](./阶段-环节-操作矩阵.md)。

## 阶段验收矩阵

逐项记录一个合法候选、一个被拒候选以及提交后的盘面或账本结果。详细操作从 [54 项操作矩阵](./2026-11-07-全操作冒烟与遗留问题归因.md) 补齐，剧本和专规差异按 [上机合并验收清单](./2026-11-07-上机合并验收清单.md) 核对。

| 阶段或环节         | 从哪里操作                                   | 必查结果                                                                                              |
| ------------------ | -------------------------------------------- | ----------------------------------------------------------------------------------------------------- |
| 初设和回合开始     | 剧本、共识、初设队列、待答                   | 双方轮流确认，落点由地图选，强制未完项挡住开局。天气、先手、决策方和回合记录一致。                    |
| A 空军整备         | 点本方基地或展开空军盒，选择飞机             | 检查基地与盒内各一例。支付来源、额度与飞机状态按实际结算。                                            |
| B 增援             | 增援会话和地图候选格                         | 入场、补员重建、迁移与当期专规按条件出现。锁定的增援仍可查状态。                                      |
| C 突围、移动与空军 | 突围入口、点己方算子和目标格、右键及基地名册 | 单枚和整叠的选择范围一致。检查燃料、ZOC、突袭、运输、换轨、工程、拆分与低空扫射在各自合法环节的入口。 |
| D 补给             | 补给结算会话、地图单位与补给站               | 检查追溯、图上补给、恢复和损耗。存在必须分配的损耗时给出下一步，处理后恢复推进。                      |
| E 反应             | 流程条、反应方算子和空军入口                 | 反应方获得操作权，交接屏、行动方和观察方保持一致。                                                    |
| F 战斗             | 炮击与战斗会话、地图目标和撤退格             | 检查供给、参战对象、损失、撤退和推进。掷骰后待决结果持续到处理完毕。                                  |
| G 进击             | 合格算子、地图和当前会话                     | 检查进击资格、移动、战斗与结束；普通算子仍可查看，提交受资格约束。                                    |
| H 清理和换回合     | 同一推进入口与交接屏                         | 自动清理结算一次，更新阶段、决策方、计分和日期。结算点可存，读档能回到相同局势。                      |

## 运行与验收

在仓库根目录执行 `npm ci` 后，用 `npm run dev` 打开开发版。先跑剧本 1 的 A13、剧本 2 的 B5 和剧本 3–7 的 C5–G5，记录每局是否进入第 2 回合。接着在剧本 1 核对 A6b 铁路、A9 会话关闭和 A11 存读档，在剧本 2 跑 B1–B3 的空运与补给空投。使用热坐、单人、人机各过一遍决策切换。

视觉检查使用 1600×1000 和 1366×768，另取一个窄窗检查导轨、抽屉与提示。拖动地图后点选原目标，检查滚轮缩放、会话拖动、右键菜单关闭、堆叠重叠区域和键盘焦点。首屏性能按同机器、同视口、同剧本记录构建和样本，目标为进入棋桌 ≤250 ms。使用 [性能验收口径](./2026-11-08-性能修复ABC-spec.md)。

交付前运行 `npm run check` 与 `npm run build`。前者覆盖 lint、格式、类型、测试和架构，后者验证生产构建。用 `git diff --stat 814a57a -- src/engine src/data` 核对 UI 批次边界。真实上机、自动测试、构建和性能各自记结果。
