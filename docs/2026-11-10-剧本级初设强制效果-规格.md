## 2. 数据模型：`setup.effects[]`

位置：`scenarios.json` 每个剧本的 `setup.effects`（新字段）；`formationDraw` **迁入**为其中一条（数据搬家，字段不变），旧读取处以派生访问器过渡，不再保留双份数据。

```ts
type SetupEffectTiming = 'afterSetupConfirm' // 本批唯一允许值
type SetupEffect =
  | {
      kind: 'formationDraw'
      id: string // 稳定 id，写进台账/日志
      timing: 'afterSetupConfirm'
      once: 'perGame'
      rule: string // 条款出处，如 'ch10 / 剧本页'
      raw: string // 原文整句
      pool: number // 入杯数（与 poolFormations.length 必须相等）
      poolFormations: string[] // 名单在剧本数据里声明（不再全局常量/后缀推导）
      groups: Array<{
        kind: 'shiftWest' | 'moveMode' | 'mtrAufkSwap' | 'deadPileKrd' | 'deadPileAufk'
        count: number
        shiftHexes?: number // shiftWest 必填
        label: string
        rule: string
        effect: string
      }>
      reducedCount?: number // No Counterattack 选项
      note?: string
    }
  | {
      kind: 'applyStatus'
      id: string
      timing: 'afterSetupConfirm'
      once: 'perGame'
      rule: string
      raw: string // 原文；缺失则此条不得落库
      status: string // 状态登记键（本批注册表只含已裁定项；剧本 1 待 Q1，未答不注册）
      target: {
        side: 'axis' | 'soviet'
        scope: 'allGroundCombat' // 待裁定可扩：allGround / allUnits / formationIds[]
        formationIds?: string[]
        excludeFormationIds?: string[]
      }
      duration: {
        until: 'cleanup' // 待裁定：turn1Cleanup / ownCleanup…
        turns: number // 待裁定：1 = 仅第一回合
      }
      visibility: { log: true; marker: true }
    }
  | {
      kind: 'other' // 预留：只允许显式注册的 handlerId，不允许代码内按剧本 id 分支
      id: string
      timing: 'afterSetupConfirm'
      once: 'perGame'
      rule: string
      raw: string
      handlerId: string
      params: Record<string, unknown>
    }
```

### 2.1 初设限制也由剧本数据声明：`setup.modeConstraints`

```ts
type SetupMode = 'combat' | 'move' | 'reserve' | 'strat'
type SetupModeConstraints = {
  /** 初设允许玩家主动选择的模式；缺省 = ['combat','move','reserve']（Q5 待裁定是否含 strat） */
  allowedSetupModes?: SetupMode[]
  /** 预备：上限；缺省取 setup.reserveMarkers[side] */
  reserveMax?: { axis?: number; soviet?: number }
  /** 初设阶段禁用预备（只作用于初设；正式回合不生效）；缺省 = reserveMax 为 0 时等同禁用 */
  reserveSetupForbidden?: boolean
}
```

- **缺失即「无额外限制」并登记缺口**：字段不存在 ⇒ 用上面注释里的默认值执行，同时在加载时向 `setupGaps` 写一条
  `{ scenarioId, field:'modeConstraints', action:'skip+default', note }`；不得因为缺字段而静默当成某个剧本的特例。
- 现有 `setup.reserveSetupForbidden`（剧本 3）迁入 `modeConstraints.reserveSetupForbidden`；
  `setup.reserveMarkers` 继续作为上限来源，供缺省使用。**初设禁令不修改 `reserveMarkers`，也不影响正式回合的 5.7 转入。**
- 剧本数据里没有的声明，引擎一律不猜：允许集合缺失＝默认集合，上限缺失＝标记数，抽签池缺失＝加载报错（抽签池无安全默认）。

约束（Zod `.strict()`）：

- `id` 在剧本内唯一；`timing` 只允许 `afterSetupConfirm`；`once` 只允许 `perGame`。
- `formationDraw.pool === poolFormations.length`；每个 id 必属该剧本 `formations.json` 的**轴方多单位编队**。
- `applyStatus.raw` 为空字符串时 schema 直接拒绝（禁止无原文落库）。
- 不同剧本各写各的：剧本 1 的池 12、剧本 3 的池 14，**不共享常量**。

引擎：`src/engine/rules/setup-effects.ts`（新）

```ts
export type SetupEffectHandler = (effect: SetupEffect, ctx: SetupEffectContext) => SetupEffectResult
export const SETUP_EFFECT_HANDLERS: Record<SetupEffect['kind'], SetupEffectHandler>
export function runSetupEffects(effects: readonly SetupEffect[], ctx): SetupEffectResult[]
```

- `formationDraw` 处理器内部仍复用现有 `drawFormations` + 各 `apply*`（不重写扣签算法）。
- `applyStatus` 处理器只做「写 `unit.mode.dg = true` + 校验 `validateModeState` + 记日志」，不新写规则。
- 任何处理器失败 ⇒ 整体不提交（不半执行），返回 `ok:false` 与 `issues[]`。

## 3. 初设内的模式设置

### 3.1 默认与允许集合

- 所有地面战斗单位初设默认 **战斗模式、战斗面**（`mode:'combat'`、`orientation:'combat'`）。
- 玩家可在初设阶段把单位改为：
  1. **移动模式**（翻到移动面）——5.5/5.6；`switchUnitMode` 既有实现；
  2. **预备模式**——5.7；受 §3.2 数量与剧本禁令约束；
  3. **战略模式**——5.8（必须移动面、移动须在追溯补给格结束）。
- 不允许改的：DG/进击（非玩家主动选择；DG 只能由效果施加）、运输点数（5.10c）、空军（另按 IV 初设规则）。

### 3.2 预备数量上限（从剧本数据取）

- 上限 = `setup.reserveMarkers[side]`（剧本 1：轴 14 / 苏 0；剧本 3：轴 14 / 苏 4）。
- 剧本 3 `modeConstraints.reserveSetupForbidden === true` ⇒ **仅在初设阶段**任一方都不得以预备初设，即使标记数 > 0；
  **进入正式回合后不生效**：只要未超上限、满足 5.7 转入条件即可转入预备。
- 苏 0 标记 ⇒ 实际可预备数为 0（无需特判剧本 1）。
- 校验放在既有模式校验链（`legality.ts` 的 `modeTarget:'reserve'`）之前的一层「初设模式守卫」，只读剧本数据，不写死数字。

### 3.3 UI 入口（不新增描述文字）

- 复用**堆叠窗内右键单枚算子**的既有三键模式菜单（`c496226`：改变朝向 / 转入转出预备 / 战略）。初设阶段菜单项按 §3.1/3.2 可判定为可用/不可用；不可用不列。
- 初设面板只加一个最简计数：`预备 轴 3/14 · 苏 0/0`（或剧本 3 显示 `禁止`），不写规则说明。
- 每次改模式即校验并落 `unit.mode`，与开局后同一套函数；不引入第二套模式逻辑。

### 3.4 原则：初设相关的限制一律由剧本数据声明

- 包含：**初设允许的模式集合**、**预备数量上限或禁用（仅初设）**、**抽签池**、**开局强制效果清单**。
- 引擎只做两件事：读剧本声明 → 执行通用校验/执行器。**禁止**出现 `scenarioId === '1'` / `'3'` 之类的分支，
  也禁止把某个剧本的行为写成示例特例。剧本 1 的混乱、剧本 3 的抽 5 师改机动都只是 `setup.effects[]` 的两条数据。
- 数据字段缺失时的统一处理：**跳过该限制/效果 + 在 `setupGaps` 登记缺口**（加载与首局日志各可见一次），
  不静默套用某剧本的特例，也不因缺字段阻塞开局；唯一例外是抽签池名单缺失 ⇒ 加载报错（抽签无安全默认）。
- 正式回合的规则（5.7 转入预备等）不读这些初设字段，初设限制天然不泄漏到回合内。

## 4. 执行时机、抽签按钮与可见性

抽签是**强制**的，交互只给一个按钮，不给参数、不给选落点、不允许跳过。

1. **两段式流程**（`src/stores/setup.ts`）：
   - 「确定初设」仍走 `startGameNow()`：只做校验与收束；若本剧本有未执行的 `setup.effects`，**不建会话、不推进**，
     置 `setupConfirmed = true`，界面出现唯一按钮「抽签」（此时按钮之外不出现任何参数/选项）。
   - 点「抽签」→ 新函数 `drawSetupEffectsNow()`：一次性执行 `effects[]`（抽取 → 西移/改模式/施加状态 → 落账），
     成功后立刻 `game.startGame()` + `advanceToNextStop()` 进入第一阶段，按钮消失（或显示「已完成」置灰）。
   - 没有 `effects` 的剧本：确认即开局，不出现按钮。
2. **按钮可见条件**（唯一判据，组件不写规则）：
   `setup.finished === true && !setupEffectsExecuted(scenarioId)`；执行中 `disabled`；无「跳过/关闭」入口。
3. **一次且不可重入**：台账 `setupEffectLedger` **随存档持久化**（与 units/session 同层，刷新后仍在）；
   - `executedAt` 存在 ⇒ 按钮不出现、不重放；
   - 失败 ⇒ 恢复执行前快照、不写台账、按钮保留、返回 `issues`；
   - 新局（`selectScenario` / `resetSetupDraws`）清空台账。
4. **事务性**：执行前快照 `units` 与抽签状态（落点、模式、DG），任一效果失败恢复快照，杜绝半执行。
5. **顺序**：`effects[]` 数组顺序即执行顺序；抽签类效果排在状态类之前（数据里显式排序）。
6. **结果展示（极简）**：按钮处展开一块纯清单，只列「抽中的师 → 落点」：
   `29 Mtr Div　4.18 → 1.19`；`4 Pz Div　8.8（无西向道路，未移动）`；剧本 3 为 `10 Pz Div　Move Mode`。
   **不放解释段落、不放规则条文、不放操作按钮。**
7. **日志（完整）**：一条总记录 + 逐项明细——
   `ch10 抽签（确认初设后）：抽中 29 Mtr Div / 4 Pz Div / 12 Pz Div / 7 Pz Div`；
   `ch10 西移：29 Mtr Div 4.18 → 1.19（沿道路 4.18–3.19–2.18–1.19）`；
   `剧本 1 特规：第一回合苏军地面 MA 减半（专规 1.5）`。种子已按已批口径写在日志头。
8. **盘面**：单位实际换位/翻面/状态标记可见；禁止无日志的静默变更（断言：每组效果 ≥1 条日志）。

### 6.2 Q1 已裁定（原文由用户给出）

**原文**：“The Soviets are in disarray, so all of their ground units move at 1/2 MA on the first
turn. This can be further adjusted by mode effects (e.g., DG).”

**裁定**：剧本 1 / 第一回合 / 苏军 / **地面单位**，MA 减半。这是**独立生效的一条本回合效果**，
不是给单位贴标记、不是给单位加状态、不改算子正面，也不写进单位固有数据（第二回合自动恢复）。

- **不用 `applyStatus` 实现**。数据位沿用剧本顶层 `sovietFirstTurnHalfMa`；引擎消费点在
  `workbench.sovietFirstTurnMaFactor()`（仅苏方 + 首回合返回 0.5）→ `moveContext.maFactorOf`
  → `move.availableMa` 的 `scenarioMaFactor`；
- **DG 不写进这条效果**：DG 由 `modes.maMultiplier` 按 5.10b 自行结算。`availableMa` 的算式
  `ma × maMultiplier(模式含 DG) × 0.5` 在乘法上等价于「先减半、再按 DG 规则算」，
  DG 不会被减半吸收、也不因开局减半而免除；**本批不改模式计算链、不调整任何顺序**；
- 取整：按 6.1h 一律不取整（MA 5 ⇒ 2.5），与既有实现一致；
- 范围：`units` store 只含地面单位（飞机在 `airUnits`）⇒ 苏军空军/非地面单位天然不受影响；
  轴方由 `unit.side !== 'soviet'` 排除；
- 日志：第一回合首次进入正常流程时记一条「第一回合苏军地面 MA 减半（专规 1.5）」，无需玩家操作。

**断言调整**：

- 第一回合苏军地面单位（无 DG）MA ＝ 模式折算后的 0.5 倍；
- 第一回合同一单位吃到 DG 后，结果 ＝ 模式折算(含 DG) × 0.5 —— 两者都生效；
- 轴方单位、苏军空军不受减半影响；
- 第二回合恢复原值；DG 只按自身持续时间存在；
- 该效果不写入单位数据（换剧本/重开局不残留）。
