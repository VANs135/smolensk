## 1. 共用放置方法（三段通用）

第一段、第二段、第三段中需要玩家选落点的地方，**都走这一套，不另做第二套交互**。

### 1.0 落点类型：地图落点 / 图外盒落点（全 docs 统一写法）

凡描述「把单位放到哪里」，必须显式区分两类，**不许混写**，也不许只写「高亮可放置位置」：

| 类型       | 形态                                                                               |
| ---------- | ---------------------------------------------------------------------------------- |
| 地图落点   | 引擎算合法格 → **高亮地图上的格** → 点格即放置（点格即生效，不弹二次确认）         |
| 图外盒落点 | 盒是**界面面板不是格**，没有格可高亮；点即移入（或先选盒再移入），不弹二次确认     |
| 两类都允许 | 明写「二选一：先选落点类型，再选具体位置」，不得用一句「高亮落点」把盒和格混在一起 |

### 1.1 放置与撤回（全阶段唯一一处定义）

| 动作     | 操作                                                                                                                                                                              |
| -------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 放置     | 点击待放单位 → 合法格高亮 → 点格 → 落位（**点格即生效，不弹二次确认**）                                                                                                           |
| 撤回     | 对**本环节已放置**的该单位**再点一下** → 收回待放列表，角标加回；若是重建产出，**补员点数退回**；可重放                                                                           |
| 时效     | 撤回**只在同一段内有效**；一旦结束本环节，视为已消耗，不可撤回                                                                                                                    |
| 适用范围 | 第一段到达、第二段全部掷骰产出、第三段重建（死亡堆 / 盘面打残 / **地图空军基地**）与撤回；**图外盒落点没有格可高亮，不套「点格」**，只按 §1.0 的盒规则「点即移入 / 先选盒再移入」 |

撤回就是「再点已放置单位即收回」，**不另设撤回按钮、不另设撤销栈**；第一版文档里的「待放手牌 / 可撤回 / 未清空不得关窗」与本轮的重建撤回，全部合并为本节这一套说法，第三段只引用、不重述。

### 1.2 角标口径

角标数字＝该条目待放的**算子枚数**，同时也是**点数**（本作一枚一点，补员与 SP 均按此计）。例：`Pax 3` = 3 枚 1 点 Pax 算子 = 3 点。角标随放置 / 撤回即时增减。

**只在第二段的批量手牌上出现**；第一段是逐张手牌，不显示枚数角标（用户裁定）。

### 1.3 合法格由引擎算

| 对象                   | 高亮判据                                                                                                                                                                                                                                                                                            |
| ---------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 到达单位               | 专规 3.1（轴）/ 2.1（苏）的字母入场格；入场格被敌方单位阻挡 → 自动给**最近的未阻挡边缘格**（13.6b）                                                                                                                                                                                                 |
| 飞机                   | **二选一：先选落点类型，再选具体位置。** ① 地图落点：只限**处于追溯补给**的本方空军基地格 → 高亮这些格 → 点格即放置，按 **14.2a** 激活堆叠容量决定亮或不亮；② 图外盒落点：本方**地图外空军盒**是面板不是格，**不亮任何格** → 点即移入（若存在多个盒，先选盒再移入），盒内容量按 1.4a 无限、免费整备 |
| 补员（Pax / Eq）       | 2.1 / 3.1：可追溯补给的指挥部，或地图边补给源格（**均为地图落点**）                                                                                                                                                                                                                                 |
| 重建（死亡堆中的单位） | **地图落点**：满足 13.5a 第 1) 项的格：所需补员**全在该格**、该格在**友方指挥部 2 格内**、指挥部在战斗模式或 DG 朝战斗面（5.10e）、该格无未抵消的敌 ZOC；**按所选那枚单位所需的补员亮格一次**，同一格能凑出多组组合时也只亮一次，实现内部取任一可行组合（用户裁定）                                 |
| SP                     | 同上；走铁路的 SP 只亮铁路卸货格（**地图落点**）                                                                                                                                                                                                                                                    |
| 死亡堆回场             | **地图落点**（与"重建"同一套合法格）；**图外盒落点**只在空军条目出现（飞机回盒见下行）                                                                                                                                                                                                              |
| 离图盒操作             | **入盒＝图外盒落点**（面板点即移入，不亮格）；**出盒＝地图落点**（引擎给本方空军基地格，点亮后点格落位）                                                                                                                                                                                            |
| 撤离 / 退场            | 撤离落点是**地图落点**（9.12：引擎给合法撤退格，点亮后点格）；退场/离图是"移出盘面"，不是落点，不套本表                                                                                                                                                                                             |
| 增援到达允许放图外     | 当前到达数据只给 `anyAirbase`（**地图落点**：本方空军基地格）；**图外空军盒尚未作为到达落点接线**，登记为数据缺口，不臆造盒落点。若将来数据给出盒落点，按 §1.0 二选一：先选"地图空军基地"或"地图外空军盒"，再按对应类型的规则落位                                                                   |

玩家不需要自己判断能不能放，也不需要记忆兜底格。

### 1.4 无合法格：留到下一回合

- 条目保留，标记「留到下一回合」，不丢弃、不静默消失。
- 进下一回合**对应那一段**的手牌（按来源：到达表 → 到达段；掷骰产出 → 掷骰段），**来源标签保留**。
- **用户判断（记录在案）**：正常不该出现「无可用铁路格」；若出现，只能是地图数据有误，或对手堵死全部铁路入口。属数据问题 / 极端封锁，不作为常态流程设计。
- 入场格一侧有 13.6b 的就近边格兜底，通常不会落到这一分支。

### 1.5 待放手牌与结束条件

| 要点 | 形态                                                                                 |
| ---- | ------------------------------------------------------------------------------------ |
| 汇总 | 第二段把该掷的都掷完后，产出汇进同一张待放手牌；**先判完，再一口气放**，不顺判顺放   |
| 条目 | 图标 + 数量角标，带来源标签（到达表 / 可变表 / 事件 / 方面军预备队）                 |
| 结束 | **流程条上一处「结束」按钮，三段共用**；增援必须放完（或已声明放弃），否则不允许结束 |
| 关窗 | 未放完且未放弃不得关窗；第三段没有待放项，流程条上的同一个按钮直接可用（§4.6）       |

### 1.6 放弃上场：不另设入口，用「结束」确认即声明

| 要点             | 规则                                                                                                                                                                                     |
| ---------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 无独立入口       | **不设**「放弃增援」按钮或勾选框；玩家不另做声明动作                                                                                                                                     |
| 触发             | 手牌**未清空**时点流程条的「结束」                                                                                                                                                       |
| 确认             | 弹出「确定不放上场」，确认即视为完成声明（只此一次确认，不弹解释）                                                                                                                       |
| 判据             | **本段结束时手牌非空 ∧ 玩家确认放弃**                                                                                                                                                    |
| 后果             | 未放项**作废**：不补、不顺延、不留到下一回合，也不进后续回合的手牌                                                                                                                       |
| 适用范围（收紧） | 只针对**从未放上场的增援**，含补员点数尚未放下的情形；**一旦放上场，补员点数即成为盘面资源**，第三段没用完的部分**继续留在图上，跨段、跨回合都有效**，不因换段或换回合失效、也不会被清掉 |
| 与 13.5 的关系   | 盘上补员点数可留到以后回合使用，与 13.5「may be saved for later」在**结果上一致**；本作只是把「保留」实体化为留在图上的补员算子                                                          |
| 与免费重建的区别 | 本节的「作废」是**未上场**才发生；1.6c / 2.3c 的免费重建是**按单位点名、不扣点**，当期不用即作废（§4.6），两者不是同一件事                                                               |
| 结束条件         | 作废项视为已处理，手牌可因此清零并允许结束                                                                                                                                               |
| 依据             | 13.6「玩家不能延迟增援单位的进入，因此……"被遗忘"的单位永远不会再抵达」——放弃即永久失去，与原文一致                                                                                       |

### 4.3 合并与整编：只保留一个菜单项

13.9 标题是「单位的合并」，正文写「被交换或合并的地面单位」——**「合并」与「整编」是同一动作（Consolidation）的两种叫法**，不是两个规则。因此只保留一个菜单项，文案「整编（13.9）」，副标题标「单位的合并」；条款引用统一写「13.9 单位的合并」。

**出现判据（全部满足才出现）**：

1. 当前选择 ≥2 枚己方单位；
2. 同格，或同在地图外区域（13.9 类型 1 / 4）；
3. 两枚算子**两面完全相同**（13.9 正文）；
4. 两枚都**不是**低补给 / 耗尽，也**不是** DG（13.9 正文）；
5. 轴心方：所选**不得是多单位编队**（专规 3.3d）；
6. 时段：**地面单位只在增援阶段**（13.9 段首）；**飞机在任何阶段都可**（类型 4），且两架都须**军力减损**；
7. 合并后军力确有变化（见下）。

**不出现判据（任一满足即不出现）**：选择少于 2 枚；跨格且不在地图外区域；任一枚 DG / 低补给 / 耗尽；两面不完全相同；轴心方多单位编队（3.3d）；飞机任一架为满军力；地面单位满军力 + 满军力（**实现判据**，原文只规定「超出直接丢失」，未禁止）。

### 4.4 原文核对：飞机整编的时段例外

用户称「只有飞机在其它时候也可整编」。核对结果：**成立，但范围与条件比「飞机例外」更窄**。

> 4. 如果两架类型、数值和状态(非激活或激活)相同的军力减损的飞机位于同一格内(或地图外区域内)，则可合并为一个完整军力的飞机。这可以在任何阶段进行(不仅仅是增援阶段)。
>    —— 通规 13.9 类型 4（同上，第 2578–2581 行）

| 核对点     | 原文表述                                                                                     | 结论                                           |
| ---------- | -------------------------------------------------------------------------------------------- | ---------------------------------------------- |
| 是否有例外 | 「这可以在任何阶段进行(不仅仅是增援阶段)」                                                   | 有，仅类型 4 明写                              |
| 例外范围   | 仅飞机；类型 1 地面多军力单位、类型 2 / 3 换编均无此句                                       | 只有飞机                                       |
| 适用条件   | 「两架」「类型、数值和状态(非激活或激活)相同」「军力减损的飞机」「同一格内(或地图外区域内)」 | 两架都须军力减损，同格或地图外，同型同值同状态 |
| 结果       | 「合并为一个完整军力的飞机」                                                                 | 与地面「超出直接丢失」不同                     |

### 4.5 第三段的落点

- **死亡堆重建**：右键某枚算子后，地图高亮**该单位所有合法重建格**（判据见 §1.3，即 13.5a 第 1) 项）；点高亮格即扣补员、落位，不弹二次确认；再点刚重建出的单位即撤回，补员退回（§1.1）。**这是地图落点。**
- **盘面打残重建**：单位已在地图上，落位格就是它所在格；补员必须同格（13.5a 第 2) 项），故**地图落点已固定、不出高亮**，右键结算后同样可再点撤回。
- **空军重建：二选一，先选落点类型，再选具体位置。**
  - ① **放入地图空军基地**（地图落点）：只限**处于追溯补给**的本方空军基地格，按 14.2a 激活堆叠容量决定亮或不亮；点高亮格即落位，落位后可再点撤回（§1.1）。
  - ② **放入地图外空军基地**（图外盒落点）：盒是面板不是格，**不亮任何格**；点即移入本方地图外空军盒，不弹二次确认。本方只有一个盒就直接移入；若存在多个盒，先列盒让玩家选定再移入。盒内**没有槽位概念**，容量按 1.4a 无限。

## 6. 必须补齐

### 6.1 补员点两用同池：盘面打残单位也要有右键入口

**原文依据**：13.5a 第 2) 项「被重建的单位必须与所使用的补员堆叠在一起」。

1. 重建右键入口**不能只在死亡堆窗内**；地图上有军力损失的己方单位被右键时，同样出「重建」菜单。
2. 两个入口**共用同一份 Pax / Eq 点数池**：扣除、余量显示、日志记账同一份。
3. 判据差异一条：盘面重建额外要求被重建单位与补员同格；不同格时菜单项不出现。
4. 池余量可见（Eq / Pax 各若干）。

**与现行的关系**：现行候选生成已含「死亡堆 + 盘面打残单位」，规则判据已覆盖；缺的是右键入口与同一份点数池的可见与扣减。

### 6.2 共用放置方法落地

现阶段第一段是「逐张手牌」、第二段没有待放手牌、第三段没有选格入口，三套交互。要合并为 §1 的一套：

| 要求                             | 现状                                                    |
| -------------------------------- | ------------------------------------------------------- |
| 点单位 → 点格落位                | 第一段有，第二段无手牌                                  |
| 再点已放置单位 → 收回可重放      | 无                                                      |
| 角标＝枚数＝点数                 | 无（第二段结果散落在块内）                              |
| 每段一个「结束」，未放完不可结束 | 只有到达步的 `arrivalHandDone` 自动关窗，且后续块不可达 |
| 无合法格 → 留到下一回合          | 无                                                      |

### 6.3 合法格高亮由引擎算

13.6b 就近未阻挡边格、14.2a 基地容量、2.1 / 3.1 补给源与入场格都要在点击时给出，不由玩家判断；无合法格时一句话原因（不写规则解释）。

### 6.4 第三段收尾

Pax / Eq 两栏 + 点数字展开死人堆 + 「结束」（§4.6）。缺它则第三段没有结束点，也没有可用补员可见。

### 6.5 右键菜单：不可用能力不出现

重建与整编的不出现条件见 §4.2 / §4.3；落地时统一「不生成菜单项」，不生成灰项、不生成带解释的禁用项。
