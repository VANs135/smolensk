## 一、第 2 条：德军 SP 分集群的前提

### 1.1 原文依据

文件：`D:\OCS\OCS斯摩棱斯克素材\斯摩棱斯克工程数据库\raw_text\专规及表格__Smolensk_Rules_v1.1.txt`（第 4 页）。

**3.4 首段（可选性）**：

> This rule has two sections. The "dividing line" part is very easy to use, but "supply restrictions" adds extra complexity that might not be worth the effort. **It's your choice to use one or both parts.**

**3.4b Supply Restrictions（归属义务）**：

> The Axis must evenly divide Supply Table arrivals between Guderian and Hoth, with the odd point going to Guderian. SP from the "wrong" panzer group cannot be used to pay the fuel, combat, or barrage costs of a multi-unit formation. Aside from this, use of SP is not restricted.
>
> - At the start of a scenario, SP must be divided per Setup Note "F" (p. 5).
> - **All new Axis SP must immediately be assigned to a panzer group.**

**时限**：

> This rule only applies before 19 August and only affects multi-unit formations. It does not limit infantry divisions and independent units at all!

**Setup Note F（第 5 页）**：

> When using 3.4b (part of "Guderian & Hoth"), on-map SP should be assigned to a Pz Grp during setup. Use the Dividing Line as a guide, but the player can freely decide ownership of dumps.

### 1.3 核对结论：勾选是不是前置条件

**是，三层都已把「勾选 3.4b」当前置条件**：

1. 工作台闸口 `axisGated = panzerGroupRulesOn.value && input.side === 'axis'`（`workbench.ts:11951`）；`panzerGroupRulesOn` 含共识勾选。
2. 初设 `setup.panzerGroupRulesOn()`（`setup.ts:2558-2563`）同样把勾选乘进去；未勾时 `spOwnershipEntryVisible === false`（2572-2574），`setSpAssignment` 直接早退（2586），`confirmSpOwnership` 不写 `spDumpPanzerGroups`（2606-2612）。
3. UI 的归属按钮/下拉只在 `panzerGroupRulesOn` 为真时出现（上表）。

未勾选时：不要求归属、无归属 UI、不写归属账本——与用户口径一致。

### 1.4 现状与口径的差异

- **P1（UI 仍有「未归属」选项）**：`SetupPanel.vue:529` 的 `<option value="">（未点名）</option>` 是一个可主动选回的「不属任何集群」态；虽然 `confirmSpOwnership` 会拒绝未点名，但界面确实提供了该选项，与「不提供『不属任何集群』这个选项」字面冲突。
- **P2（同格单集群继承，未显式指定）**：`addSpAtHex` 的并入选择（`workbench.ts:11956-11964`）在同格只有一个集群时，允许**不带 group** 的落账并入该站，闸口按「继承已有归属」放行（11972-11982）。这不是玩家对这批 SP 的**本次**指定，严格按「必须由玩家指定」应改为拒绝。
- **P3（初设不是到场即归属）**：初设走 `landSetupSpDumps` 直接写账本，归属在 `confirmSpOwnership` 统一补；Setup Note F 允许「during setup」统一指定，故可接受，但与「所有入口统一同一套判据」的表述有差距。
- **P4（旧账本字段仍在）**：`pendingSpGroupAssignment`（21408、21411-21420）新入口不再产生，只在旧档或 `setDumpPanzerGroupNow(id, null)` 撤销时出现；当前 UI 只传 G/H，撤销不可达（初设下拉的空串除外，见 P1）。
- **P5（均分对象）**：`applySupplyArrivalsNow` 只对 Supply Table 到货做 G/H 均分校验，补给列车不在均分对象——与 3.4b 原文「Supply Table arrivals」一致，现状正确。
- **P6（满载入场的额外 SP）**：2.1/3.1 的「运输点满载入场」不产生独立 dump，归属要到落账时才判；原文「All new Axis SP must immediately be assigned」是否覆盖这些随运输点入场的 SP，需裁定。

## 二、第 3 条：分阵营的进场铁路网

### 2.1 原文依据

**专规 2.1（苏）**：

> Map-edge hexes **east of 12.xx** where any type of road or railroad enters the map are Soviet supply sources. Examples are 13.01, 37.35, and 62.16. Note some supply sources "shut down" per 2.1a.

**专规 3.1（德）**：

> Map-edge hexes **west of 10.xx** where any type of road or railroad enters the map are Axis supply sources. Examples are 1.03, 1.26, and 4.00 (but not 11.33!).

**专规 2.1a（关停）**：

> These supply sources cease to exist on fixed dates: **Entry L on 19 July**. **Entry E (and all South edge sources west of there) on 19 August**.

**通规 12.6a①**：

> Map-edge railroad hexes that allow Reinforcement entry, plus other supply sources mentioned in the game-specific rules.

**通规 13.3c（原文，工程库 `stage_v1_supply_detrain.py:395-400`）**：

> A railroad hex is detrainable if it meets all of these requirements: (1) It has a village, city (any size), port, or Engineer-Capable HQ (13.8a). (2) It is under control (13.3h). (3) It has a rail path free of enemy ZOC back to a supply source. Extender links can be part of this for trace supply, but not for moving cargo. Note EZOC cannot be negated to move cargo, but can to connect with a supply source.

**专规 1.2 / 通规 13.3f（轨距）**：全部初始为宽轨；苏方只能用宽轨，轴方只能用标准轨，玩家用铁路修理单位改变轨距。

**专规 3.6 / Axis Arrival Card（补给列车）**：

> The Axis gets 2 SP of extra supply at any one detrainable hex (no Rail Cap used).

### 2.2 现状（代码位置）

- **分层结论**：`engine/rules/rail-supply.ts:185-291` 的 `railSupplyPath(facts, side)` 已经**按方**从 `baseSourceHexes(side)` 做 BFS，并逐格过滤「轨距可用（1.2/13.3f）」「无未抵消 EZOC（13.3c③）」，延补队按 12.7a-B/C 作连接。
- **事实装配**：`workbench.ts:3429-3452` 的 `railSupplyFacts`，其 `sources` 只取**玩家手工声明的** `supplySourceDecls`（`kind !== 'detrainable'`）。
- **两方分别计算**：`workbench.ts:3455-3458` 同时算 `axis` / `soviet` 两张网；但 `detrainableHexes` 只暴露当前行动方（3459、3462）。
- **补给列车落点**：`workbench.ts:17836-17838` `supplyTrainPlacementHexes = detrainableHexes`（当前行动方）；落点校验 17853-17856。
- **铁路运货卸货**：`workbench.ts:1693-1735` `beginRailMoveHexPickNow` 用 `detrainableHexes` 再叠 `railPathBetween`；`railMoveFacts.isDetrainable` 只认当前行动方（3777-3779）。
- **免费铁运城市格**：`workbench.ts:17741-17744` 用同一份 `detrainableHexes`。
- **剧本图边源清单**：`src/data/scenarios.json:240` 等 `supplySources.axisLive`（含 `1.03/1.04/1.07/1.12/1.19/1.26/4.00/8.00`）；关停投影 `openSupplySourceHexes`（`workbench.ts:17576-17585`）只服务到达落点与免费铁运余额，**没有进入铁路网的 seed**。

### 2.3 现状与口径的差异

- **R1（seed 不是进场铁路）**：铁路网的起点是玩家手工声明的源，不是 2.1/3.1 的图边进场铁路。没有任何声明时两张网都是空的，补给列车与铁路卸货的候选也是空的（用例里都是手工 `push` 声明 `kind: 'edgeRail'` 才跑起来的，见 `tests/stores/free-rail-arrival-flow.test.ts:56-61`）。
- **R2（声明不分阵营）**：`supplySourceDecls` 是全局的，`railSupplyPath` 只按 `decl.side` 分桶，没有校验「该格是否真是该方的进场铁路」。同一格可以被双方各声明一次，两个 seed 都成立。
- **R3（补给列车取网）**：`supplyTrainPlacementHexes` 取 `activeSide` 的网，方向本身正确（德军事件取轴方网）；但若轴方网是被一条错误的声明 seed 出来的，仍会给出不属于德军进场铁路网的格。
- **R4（交叉/共用段）**：轨距是**单值**（`railGaugeAt`，`workbench.ts:3526-3528`：要么印值宽轨，要么已转标准轨），所以两张网按轨距严格互斥，不存在同格双属；目前地图数据里也没有「双轨/共用」字段。
- **R5（2.1a 关停）**：关停只影响到达落点，未影响铁路网 seed；Entry L（19 Jul）、Entry E 及西侧南缘（19 Aug）关停后仍可作为网起点（只要被手工声明）。
- **R6（孤立支线）**：按上一轮试算，东南支线 `36.24…42.35`（15 格）不与任何一方进场铁路连通，`36.3` 也不在网内；这些格不应成为任何一方的补给列车落点（数值需在实现时以地图数据复核）。

### 2.4 拟改判据

1. **进场铁路种子（每方各自）**
   ```text
   entryRailHexes(side, date) =
       scenarioSupplySources(side)                  // 2.1 / 3.1 的 Live 清单
     ∩ isRailHex(hex)                                // 该格至少一条铁路格边
     ∩ isMapEdge(hex)                                // 图边进入
     ∩ supplySourceOpen(side, hex, date)             // 2.1a 关停
   ```
   其中「图边」按现有 `mapEdgeHexes` 口径（缺邻格）；`scenarioSupplySources` 已按 2.1 / 3.1 的 east of 12.xx / west of 10.xx 收过。
2. **两张网（分别 BFS，互不混用）**
   ```text
   railNetwork(side) = BFS(entryRailHexes(side, date))
       step: railNeighbors(hex)
       allow: isRailHex && railGaugeUsable(hex, side) && !inUnnegatedEnemyZoc(hex, side)
       extra: 12.7 延补队只作「连接器」把已到达格接到其所在格（12.7a-B/C），不作 seed
   ```
3. **可放置格（13.3c 仍是最终过滤）**
   ```text
   placementHexes(side) = railNetwork(side)
       ∩ isRailHex ∧ railGaugeUsable(side)
       ∩ isControlledBy(side) ∧ !inUnnegatedEnemyZoc(side)
       ∩ (村庄/城市/港口/工程 HQ)
   ```
   即把现在的 `detrainableHexes` 从「手工源网的派生」改为「进场铁路网的派生」。
4. **消费方统一取本方网**
   - 3.6 补给列车：`placementHexes(eventSide)`（德军事件恒为 `axis`，不取对方网）。
   - 13.3e 铁路运货卸货：`placementHexes(activeSide) ∩ railPathBetween(from, hex, activeSide)`。
   - 2.1/3.1 免费铁运城市格：`placementHexes(activeSide) ∩ 城市格`。
5. **空网可诊断**：若 `entryRailHexes(side)` 为空或 `railNetwork` 为空，记一条 `13.3c` 告警（说明是数据缺口还是关停所致），不再静默给出空候选。

### 2.5 交叉 / 共用段怎么归属

- 现行轨距账本是**单值**：每格要么宽轨（苏可用），要么已转标准轨（德可用），因此**两网在格级严格互斥**，不存在「共用段」需要分摊。
- 一段铁路被 13.3f 转换后，整格从苏方网转入德方网；德方网向前推进的边界就是已转换的最东端。
- 若将来地图数据引入「双轨」格，需要新增 `gauge: 'dual'` 一类字段；届时两网都含该格，但 SP / 归属账本仍按 `side` 各记各的，不共享余额。当前无此数据，不预造。

### 2.6 影响面

- `railSupplyFacts.sources` 的语义（声明 → 进场铁路种子），以及 `detrainableHexes` / `supplyTrainPlacementHexes` / `beginRailMoveHexPickNow` / `freeRailCityCandidates` 四处消费方。
- 12.6a② 追溯补给源会随 `detrainableHexes` 收窄：手工声明任意源把全图点亮的情况会消失。
- 用例：`detrainable-*`、`free-rail-arrival-flow`、`supply-train-*`、`rail-move-*` 需要改成从剧本进场铁路 seed，而不是手推声明。
- UI 候选数量会下降（尤其是开局未转换的东段），需要一条可诊断日志。

### 2.7 要裁定的点

1. **Entry E / 南缘**：2.1a 关停后是否仍算「进场铁路网」的 seed？（建议：不算，按 `openSupplySourceHexes` 同步。）
2. **手工声明源**：是否仍允许作为铁路网的 seed？（建议：不再 seed 可放置网，只保留其 12.6a① 追溯源身份。）
3. **12.7 延补队**：是否允许把网延伸到「进场铁路不可达」的前段铁路？（13.3c 允许延补队作路径的一部分；建议允许作连接器，但不改变 seed。）
4. **东南孤立支线 `36.24…42.35`**：确认不属任何一方网、不可落补给列车；若剧本专规另有说明，需补原文。
5. **苏方东缘进场铁路清单**：试算为 `62.16 / 62.23 / 62.3 / 62.33 / 62.4`，需与地图 rail 格边数据逐格复核后定稿。
6. **共用段**：确认本作不存在双轨数据；若存在，需先定 `dual` 字段再实现。
