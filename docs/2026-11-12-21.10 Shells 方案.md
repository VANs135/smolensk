## 3 口径细化

### 3.1 付款顺序与账目

```
每枚 Shells 面值 2T，按枚整花：
  applied_i = min(2, 剩余成本)
  waste_i   = 2 − applied_i
先花 Shells（不可拆分），不足部分再由 SP 补；SP 仍按 12.3a/12.3b 选源。
```

- `markersSpent` 按**实际花掉**的枚数扣；`wasteT` 入日志与结果账，便于复盘。
- 撤销（未掷骰前）与 SP 一致：`barragePaidSupply` 同时记 `markersSpent`，撤销时原数退回。
- 溢出只在"最后一枚"发生；不允许多花无意义的标记（界面按 `ceil(剩余/2)` 上限提示）。

### 3.2 降档选列

```
v  = roundBarrageValue(本次总轰炸值)          // 4.2：先合并再取整（DG 减半后）
c0 = columnOf(v)                              // 10.1b：成本取初始列
B  = markersSpent × 2 + spT                   // 本次可用额度
若 cost(c0) ≤ B ⇒ 不降档
否则取最大的 c ≤ c0 且 cost(c) ≤ B；无解 ⇒ 拒绝本次炮击
valueUsed = min(v, upperBound(c))             // 列区间上界，回代必须落在 c
```

- 列横移（密度/地形/观察员/短程）仍作用在 `c` 上；**成本照旧取初始列 c**（10.1b）。
- 默认给"最高可负担列"，玩家可手动再降；不得高于 `c0`。
- 多门炮齐射按**加总值**选一次列（10.0a），不逐门降档。
- 降档只影响本次炮击值，不改变单位印值。

### 3.3 资格

- 只有 **HQ 投递的炮击**可用 Shells（原文 "barrage being thrown supply by an HQ"）；
- Shells 让 HQ **绕过 trace 判定**，但仍须是本次投递的合法 HQ；
- 11.x 的空军轰炸不吃补给，不适用。

## 6 开放点

- 用户示例"20 值 = 4T"与项目表不符：`charts-tables.json` 中 20 落在 **17–24 列 = 3T**，4T 是 25–40 列；方案按表实现。
- 降档下限：最低到 "2" 列（1T）；"1 or less" 列成本 1T，是否允许 1 点炮击需按 10.0 最小轰炸值 `BARRAGE_MIN_VALUE` 复核。
- 混付时 SP 是否仍须"同一 HQ/同一补给站"（10.1b-A）：按原文是，Shells 只替代 T，不改变来源约束。
