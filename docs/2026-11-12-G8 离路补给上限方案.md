### 1.2 三问复核

#### 问 1：「沿路不限」有没有原文支持？

**没有直接原句。** 逐条核过：

- 12.6 只写"检查是否存在追溯补给"，并写"直接拖取/指挥部投递用于接收与分配"，**没有"长度不限/任意长度"**。
- 12.6a 只列三类源，**没有距离**。
- 12.3d 只说"追溯"是一种补给路径、怎么计距离，**没有上限，也没有"不限"**。
- 12.3a 的 5MP 只针对"单位到一个**补给站 (dump)**"。
- 12.7a–c 只说延补队"创造新位置、延续追溯、可串成更长的连接"，**没有定义单位到源的长度**。

因此：

- 若按"必须有原句才能叫口径"的标准，**"沿路不限"不能登记为实现口径**。旧文（本文件上一版与台账 §1.4）
  把它写成"实现口径（用户 2026-11-12 确认）"是**证据等级错标**，本版已撤销。
- 现状的**无界洪泛**因此有两种可能身份：按读法 A 是**缺陷 U23**；按读法 B 是"与原文不冲突的实现"。
  在裁定前，统一按 **U23（待裁定）** 登记，不当作已证成的口径。

#### 问 2：12.6a 的三类源与 12.3a 的 5MP 是什么关系？

**源的"资格"不受 5MP 约束；争议只在"单位 → 源"这一段。** 分开看：

1. **源的选取**：12.6a 只要求格的类型（边缘铁路格 / 13.3c 卸货格 / 含延补队的格），
   12.6b 只要求源格无未抵消敌 ZOC。**两条都没有距离条件**。所以"一个源离单位多远才算源"不是 12.6a 管的事。
2. **接收段**：12.6 那句"直接拖取 (12.3a) 和指挥部投递 (12.3b) 用于接收与分配"才是距离争点：
   - **读法 A（严格）**：既然"接收"用 12.3a/12.3b，就要连它们的**距离**一起用 ⇒
     单位到源 ≤ 5 轮式 MP，或经 HQ 在印值投递距离内。即"源由 12.6a 选，接收由 12.3a/b 限"。
   - **读法 B（结构）**：12.3d 已把"追溯"列为与 draw/throw **并列的第三种补给路径**，
     并给了它自己的计费方式；12.6 那句话只是说"源上的补给用拖取/投递的**路径规则**来接收与分配"，
     不是在 draw/throw 的距离上限上再套一层。即"单位到源按 12.3d 的追溯路径走，原文未设上限"。
3. 两读都**不**认为 12.6a 的源需要"位于某单位 5MP 内"才成立；差别只在上限是否施加于接收段。

#### 问 3：「到达源之后沿铁路/道路继续向前」在原文里存在吗？

**不存在。** 原文没有"穿过源继续向前"的机制：

- 12.6a 的三类源是**终点**：边缘铁路格是入场源；13.3c 卸货格是"铁路路径**回连**到源"的资格；
  延补队格是"延补队**回连**到卸货格/源"的资格。三者的路径方向都是**向源**，不是"过源继续"。
- 唯一"往前延伸"的机制是 **12.7a 创造新的源点**（延补队），以及 12.7c 的延补队锁链；
  它们改变的是"源的位置"，不是允许单位越过某个源免费前进。
- 12.7a 还明确"不能增加投递或抽取的距离"⇒ 也不存在"到源后再借铁路免费续一段"的规则。

因此：如果实现把"与源连通的整张道路/铁路网"都当作可无限取用，那实质上是**把整张路网当成了源**，
这不是原文的机制；它要么是读法 B 下"单位到源路径不设上限"的结果（仍以源为终点），
要么（若跨过源继续算）就是**超规则**。这一点两读一致。

## 2. 判据设计（按两读分别给出，不预选）

### 2.1 统一抽象仍然成立

```ts
type SupplyBudget =
  | { kind: 'fixed'; maxMp: number } // 读法 A 的追溯；12.3a/12.3b/12.7b 的现状
  | { kind: 'offRoad'; maxMp: number } // 旧混合方案（C），本版仅留作记录，不推荐实施
  | { kind: 'unlimited' } // 读法 B（= 现状）
```

- 三态只是**同一搜索原语**的不同预算；无论选 A 还是 B，都不需要在 store 里再写一套判据。
- **A**：追溯入口传 `fixed(DIRECT_DRAW_RANGE_MP)`（= 5），道路照常计费，总距离 ≤5。
- **B**：追溯入口传 `unlimited`，等同于现状；不改 `trace-supply.ts`（这条路线下 U23 关闭为"按读法 B"）。
- `fixed` 的语义已经在 `searchFrom(maxMp)` 里存在，A 的改造量小于旧混合方案。

### 2.2 读法 A：有界 Dijkstra（铁路线提出的修法）

```text
edge 的追溯成本 = 该步轮式正常地形 MP（含 6.2a 道路优先，道路只降费）
路径合法 ⇔ 累计 ≤ 5
```

- 与 12.3a 完全同口径：道路**不免费**，只是按 6.2a 的更低道路费用计。
- 12.3c"相邻即可"**不**适用于追溯（原文只把它给 draw/throw），故 A 下不做相邻格膨胀。
- 12.7b 延补队回连仍按印值；单位到新源点按 5 判。

### 2.3 读法 B：保持无界（现状），补齐"源是终点"的约束

- 距离不设上限；只保留 12.3d 的可走性与阻断（敌方战斗单位、卡车 EZOC、禁入地形）。
- 必须明确：**到达源即止**，不允许"穿过源继续沿路"（§1.2 问 3）。
- 现状代码在这一点上没有"过源"逻辑（`baseSourcesFor` 命中即返回），B 下无需改动。

### 2.4 旧混合方案 C（道路 0 计费 / 离路 5）——**撤回**

上一版本文把"沿路不限、离路 5"当作落地口径。复核后：

- "沿路不限"无原句；"离路 5"也无原句；它既不是 A 也不是 B，是**第三种自造口径**。
- 因此本版**撤回 C 作为实施方案**，只在 §5 用例里保留一列，供用户裁定后对照；不进入实施。
- 若用户裁定"既不选 A 也不选 B"，再单独讨论 C 的原文依据（目前为零）。

### 2.5 两读共同的不变量（无论选哪边都不许动）

- 12.3d 的可走性：图内、不穿敌方战斗单位、卡车 MP 路径被未抵消 EZOC 阻挡进出（4.5b 可抵消）。
- 12.6b：源格有未抵消敌 ZOC 则源不可用。
- 12.6a：源的类型资格。
- 12.7a：延补队只是新源点，不增加 draw/throw 距离；12.7b 回连用印值；12.7c 可串联。

## 6. 落点建议

### 6.1 顺序

```text
① 用户裁定 D1：选 A（5 轮式 MP）还是 B（无上限）
   ├─ 选 B：U23 关闭（只改文档/注释），本方案终止
   └─ 选 A：继续 ②–⑤
② 铁路链路收尾（rail-supply / railhead / 13.3e）
③ 战斗链路收尾（combat-interaction / CombatPanel / workbench 战斗 hunk）
④ 补给消耗段红用例转绿（attrition / feeding / plan / reach-payment…）
⑤ U23-A：trace-supply 有界化 + 新用例 + 全量回归
```

理由：`trace-supply.ts` 是补给核心的唯一搜索原语，一动则铁路延补队回连、战斗断补减半、补给阶段喂食与损耗、
AI 对打同时变化；必须在"其他线都已绿"的基线上做，红了才能一眼归因。

### 6.2 分批（仅 A）

1. **批 1（纯引擎 + 单测）**：有界追溯 + 9 条用例（按 A 列）。
2. **批 2（接线显式化）**：`workbench.ts` 构造点显式传 `TRACE_BUDGET_FIXED_5`；补一条 store 级流程用例。
3. **批 3（文案 + 回归）**：`SupplyPanel` 提示；跑全量并记录 AI 对打是否 stall。

### 6.3 风险与回滚

- **判严后 AI 对打 stall**：`tests/flows/ai-selfplay.test.ts` 的 `stalls` 必须仍为 0。
- **性能**：有界 Dijkstra 规模小于无界洪泛，但缓存键多一维（`maxMp`）；确认 `traceCoverageHexes`
  仍按方一次缓存（9.14d 曾因逐格洪泛到 5 秒级）。
- **回滚**：A 只依赖一个预算值；异常时可切回 `unlimited`（读法 B），无需回滚 store。
