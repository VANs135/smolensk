### 1.2 三问复核

#### 问 1：「沿路不限」有没有原文支持？

**没有直接原句。** 逐条核过：

- 12.6 只写"检查是否存在追溯补给"，并写"直接拖取/指挥部投递用于接收与分配"，**没有"长度不限/任意长度"**。
- 12.6a 只列三类源，**没有距离**。
- 12.3d 只说"追溯"是一种补给路径、怎么计距离，**没有上限，也没有"不限"**。
- 12.3a 的 5MP 只针对"单位到一个**补给站 (dump)**"。
- 12.7a–c 只说延补队"创造新位置、延续追溯、可串成更长的连接"，**没有定义单位到源的长度**。

因此：

- 按"必须有原句才能叫口径"的标准，**"沿路不限"不能登记为实现口径**。旧文把它写成"实现口径（用户确认）"
  是**证据等级错标**，本版已撤销。
- **用户 2026-11-12 裁定 D1=A**：现状的**无界洪泛**是**缺陷 U23**，按 12.3a 的 5 轮式 MP 收紧。
  读法 B（无上限）被否决；旧混合方案 C（沿路 0/离路 5）无原文依据，一并否决。

#### 问 2：12.6a 的三类源与 12.3a 的 5MP 是什么关系？

**源的"资格"不受 5MP 约束；争议只在"单位 → 源"这一段。** 分开看：

1. **源的选取**：12.6a 只要求格的类型（边缘铁路格 / 13.3c 卸货格 / 含延补队的格），
   12.6b 只要求源格无未抵消敌 ZOC。**两条都没有距离条件**。所以"一个源离单位多远才算源"不是 12.6a 管的事。
2. **接收段**：12.6 那句"直接拖取 (12.3a) 和指挥部投递 (12.3b) 用于接收与分配"就是距离判据：
   - **读法 A（已裁定采用）**：既然"接收"用 12.3a/12.3b，就要连它们的**距离**一起用 ⇒
     单位到源 ≤ 5 轮式 MP，或经 HQ 在印值投递距离内。即"**源由 12.6a 选，接收由 12.3a/b 限**"。
   - **读法 B（已否决）**：曾把 12.3d 的"三种路径"读成 trace 有自己的无限路径；该读法与 12.6 的
     "接收"句冲突，且会让 13.3c 卸货格失去意义，不采用。
3. **裁定后的一致结论**：12.6a 的源**资格**不受 5MP 约束（只受类型与 12.6b 的 ZOC 约束）；
   但**单位能否从该源收到补给**，受 5 轮式 MP（或 HQ 印值投递）约束。源**只是终点**，不是中转站。

#### 问 3：「到达源之后沿铁路/道路继续向前」在原文里存在吗？

**不存在。** 原文没有"穿过源继续向前"的机制：

- 12.6a 的三类源是**终点**：边缘铁路格是入场源；13.3c 卸货格是"铁路路径**回连**到源"的资格；
  延补队格是"延补队**回连**到卸货格/源"的资格。三者的路径方向都是**向源**，不是"过源继续"。
- 唯一"往前延伸"的机制是 **12.7a 创造新的源点**（延补队），以及 12.7c 的延补队锁链；
  它们改变的是"源的位置"，不是允许单位越过某个源免费前进。
- 12.7a 还明确"不能增加投递或抽取的距离"⇒ 也不存在"到源后再借铁路免费续一段"的规则。

因此（**用户裁定 A 后的定论**）：

- **源是终点**：到达 12.6a 的源即止，**不存在"越过源继续沿铁路/公路免费走"**。
- **路网不能当源**：与源连通的整张道路/铁路网**不是**补给源，不能被无限取用；这既不是原文机制，
  也与"单位 → 源 ≤ 5 轮式 MP"的裁定直接矛盾。
- 要延伸补给：只能按 12.3b 用 HQ 投递，或按 12.7a 用延补队**创造新的源点**；延补队自身仍受 12.7b 印值约束。

## 2. 判据设计（裁定 A：单态 `fixed(5)`）

### 2.1 统一预算只剩单态

```ts
type SupplyBudget = { kind: 'fixed'; maxMp: number } // 追溯 = fixed(5)；12.3a/12.3b/12.7b 同族
```

- `fixed` 的语义已经在 `searchFrom(maxMp)` 里存在：追溯入口直接传 `DIRECT_DRAW_RANGE_MP`（= 5）。
- 旧混合方案 C 需要的 `offRoad` 态、读法 B 需要的 `unlimited` 态**均不实现**；只保留 `fixed`。
- store 不需要第二套判据，只是把追溯洪泛改成有界。

### 2.2 核心公式

```text
edge 的追溯成本 = 该步轮式正常地形 MP（含 6.2a 道路优先；道路只降费、不免费）
路径合法 ⇔ 累计 ≤ 5
源 = 终点：到达 12.6a 的源格即停止，不越过源继续累计
```

- 与 12.3a 完全同口径：道路**不免费**，只是按 6.2a 的更低道路费用计。
- 12.3c"相邻即可"**不**适用于追溯（原文只把它给 draw/throw），故不做相邻格膨胀。
- 12.6f 的"同源"按到达的那个源格算；若两单位不能在同一条 5MP 路径内到达同一源，就拆为 covered/uncovered。

### 2.3 关键分界（裁定 A 的落地判据）

| 情形                                               | 结论                                         |
| -------------------------------------------------- | -------------------------------------------- |
| 单位距源 20 格，但全程道路、总距离 10MP            | **断**（道路不免费，10 > 5）                 |
| 单位距源 3 格，但每格 2MP（6MP）                   | **断**                                       |
| 单位距源 2+3=5MP                                   | **可供**                                     |
| 单位距源 4MP，源在道路网另一端、中间 20 格道路     | **断**（到源总距离 24 > 5；不能把路网当源）  |
| 13.3c 火车卸货格作为源，单位距该格 5MP             | **可供**（13.3c 因此有用）                   |
| 13.3c 火车卸货格作为源，单位距该格 6MP             | **断**                                       |

## 3. 改法（裁定 A，实现由 `trace-supply.ts` 统一改）

### 3.1 常量与默认

- 追溯入口的预算设为 `fixed(rulesConstants.supply.directDrawRangeMp)`（= 5），
  **不新增** `traceOffRoadBudgetMp`（C 撤回后该常量没有依据）。
- 建议在 `trace-supply.ts` 导出命名预算 `TRACE_BUDGET_FIXED_5`，让 store 显式引用，避免隐式默认。

### 3.2 `TraceSupplyFacts`：A 下**无需**新增字段

- 旧混合方案 C 需要的 `isRoadStep` 一并撤回；A 只需要现有的 `stepCost`。
- 这是 A 相对 C 的另一个好处：facts 接口零改动，手写 facts 的测试不受影响。

### 3.3 搜索原语（A）

- `searchFrom` / `runDijkstra` / `cachedSearch` / `distanceTableKey` 已经支持 `maxMp`；
  A 只需让追溯洪泛也走"有界最短路"，而不是 `floodFrom` 的无界 BFS。
- `reachableFrom` / `floodFrom` / `floodIncoming` 改为带 `maxMp` 的有界 Dijkstra（或直接复用 `searchFrom`）；
  `floodIncoming` 判 `next → current`，取费仍看被进入格。
- 缓存键加入 `maxMp`（同一 facts 下 5 与 ∞ 分开）。

### 3.4 入口函数（A）

| 函数                                                          | 预算（A）                    | 说明                            |
| ------------------------------------------------------------- | ---------------------------- | ------------------------------- |
| `baseSourcesFor`                                              | `fixed(5)`                   | 12.6a①②③ 基础源可达             |
| `traceSourcesFor` / `hasTraceSupply`                          | `fixed(5)`                   | HQ 投递支仍 `fixed(印值)`       |
| `hasDirectDrawTraceSupply`                                    | `fixed(5)`                   | 只走基础源；G7 见 D4            |

| `createTraceSupplyAt`                                         | `fixed(5)`                   | 透传                            |
| `formationTraceTradeoff` / `assessUnitSupply`                 | 透传                         | 只改调用参数                    |

| `connectsBack` / `extenderConnectsBack`                       | `fixed(印值)`                | **不动**                        |

### 3.5 向后兼容（A）

- 返回结构全部不变；只把追溯洪泛从"无界"换成"有界"，并新增可选预算参数。
- 影响最大的是**手写 facts 的旧用例**：原来放 10 格外的源会突然变断。需按 §5 的 V1/V2 逐条核对，
  不能为了变绿把断言放宽（用户明令）。
- 不允许"默认仍无界、store 再显式切 5"的双口径过渡：裁定 A 后追溯入口的默认就是 `fixed(5)`，
  否则等于把 U23 又留了一遍。

### 3.6 是否需要统一 `tracePathBudget` 抽象

**需要，且只在 `trace-supply.ts` 一处。** 裁定 A 后抽象只剩 `fixed(5)` 一种值；仍保留命名预算类型，
是为了让"追溯 = fixed(5)"显式可读，并防止 store 另写一套距离判据。

## 6. 落点建议

### 6.1 顺序

```text
① D1 已裁定 A（2026-11-12），无需再等
② 铁路链路收尾（rail-supply / railhead / 13.3e）
③ 战斗链路收尾（combat-interaction / CombatPanel / workbench 战斗 hunk）
④ 补给消耗段红用例转绿（attrition / feeding / plan / reach-payment…）
⑤ U23-A：trace-supply 有界化 + 新用例转绿 + 全量回归
```

理由：`trace-supply.ts` 是补给核心的唯一搜索原语，一动则铁路延补队回连、战斗断补减半、补给阶段喂食与损耗、
AI 对打同时变化；必须在"其他线都已绿"的基线上做，红了才能一眼归因。

### 6.2 分批

1. **批 1（纯引擎 + 单测）**：有界追溯 + 10 条用例（V1–V10，A 列）。
2. **批 2（接线显式化）**：`workbench.ts` 构造点显式传 `TRACE_BUDGET_FIXED_5`；补一条 store 级流程用例。
3. **批 3（文案 + 回归）**：`SupplyPanel` 提示；跑全量并记录 AI 对打是否 stall。

### 6.3 风险与回滚

- **判严后 AI 对打 stall**：`tests/flows/ai-selfplay.test.ts` 的 `stalls` 必须仍为 0。
- **性能**：有界 Dijkstra 规模小于无界洪泛，但缓存键多一维（`maxMp`）；确认 `traceCoverageHexes`
  仍按方一次缓存（9.14d 曾因逐格洪泛到 5 秒级）。
- **回滚**：追溯只依赖一个预算值；异常时可临时调大 `fixed(maxMp)`，但**不允许**回到无界的读法 B。
