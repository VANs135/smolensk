## 0. 结论摘要

1. **正式对局台（`GameTableView`）里只有三条空军入口**：右键敌方目标 → 轰炸/低空扫射；左键点击「无己方地面单位」的格 → target-first 空军任务；空军基地小窗 → 整备/修建/缩减。**没有「点基地 → 选机 → 起飞」的入口**，与 `AirPanel` / `BarragePanel` 注释里写的设计口径不一致。
2. **空军任务的 C–F 步是自动连跑的**（点「执行任务」或改任务类型即开跑），所以正式界面里大部分「上一步/下一步」按钮只存在于验证页（`stepwise === true`）。这带来两类后果：**拦截分支永远走不到**；一旦自动连跑在中间步失败，界面没有前进按钮。
3. **空运/空投存在硬卡死**：F 步货物结算只有自动连跑一个入口，界面上没有「重新结算货物」按钮。防空货损或超限卸载把自动连跑打断后，玩家处理完货损/勾完卸货，点「⑤ 记录任务结算」会被 `resultReady` 静默拒绝，**除了刷新页面无路可走**。
4. **空战步没有生产用前进按钮**（② 结算空战仅在 `stepwise` 下渲染）；它通常被自动连跑带走，但一旦被引擎拒绝就停在该步。
5. **公告后无法取消**：`×` 号看起来可点但被 `canReplace` 拒绝，错误只写日志；「放弃本次任务」按钮只在验证/裁判段渲染；14.3d 主动返航在空战前要求至少留一架，因此「整组返航」也会被拒。
6. **改任务格是坏的**：面板内「点地图选任务格」只写显示文本，不写引擎实际使用的 `airTargetHex` ⇒ 任务会按旧格结算（K16）。

## K1【卡死】空运/空投 F 步没有「重新结算货物」入口

- **现象**：自动连跑在 F 步因「超限卸载需要玩家选择」或「防空货损待处理」而中断后，界面只剩卸货复选框 + 「⑤ 记录任务结算」。玩家勾完货、处理完货损，点 ⑤ 没有反应（错误只写日志/`airError`，而 `airError` 在任务段不渲染）；界面没有任何按钮能再次调用 `resolveAirCargoNow`，**只能刷新页面**。
- **代码位置**：
  - 唯一的货物结算调用点：`workbench.ts:16993 autoResolveAirMissionNow` 内 `resolveAirCargoNow()`（函数本体 `workbench.ts:15734`）。
  - ⑤ 的守卫：`workbench.ts:17127-17131`（`state.cargo === null` ⇒ `cargoOutcomePending`，直接 return false）；`stores/air-mission.ts:109`（`ports.resultReady`）。
  - 需要玩家选择才失败的判据：`engine/rules/air-cargo-unload.ts:56-58`（`airUnloadSelectionRequired`）。
  - 货损处理完之后**只清 `cargo`，不续跑**：`workbench.ts:16698-16769 confirmAirCargoLossNow`（末尾 `cargo: null`，无后续调用）。
  - `airError` 只在 `AirPanel.vue:1303`（`showsCapture` 段）渲染。
- **触发条件**：空运载有单位货物，且目的格卸载限额不足（`planAirUnload` 判定 `refusedT > 0` 且含 `unit`）；或防空命中使容量下降产生 `airCargoLossPending`。
- **严重度**：**卡死**（无界面出口，必须刷新）。

## K2【卡死·条件性】空战步（`airCombat`）没有生产用前进按钮
