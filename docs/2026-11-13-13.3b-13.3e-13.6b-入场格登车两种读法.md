## 1. 四段原文

### 13.3b（运力的使用时机）

> **英文**：Rail Cap is available every turn. It cannot be “saved” for use in another Movement Phase. Rail Cap can only be used in the Movement Phase (never during Reaction or Exploitation).

> **现行译文**：剧本规则会规定铁路运量的多少，每回合都可以使用。它不能”保存”到下一个移动阶段使用。铁路运量只能在移动阶段中使用(永远不能在反应阶段或进击阶段中使用)。

出处：英文 `:2325-2334`；译文 `:1763-1767`。

### 13.3e（铁路移动三步；本次只引 1) 与 2)）

> **英文**：Rail movement includes three steps: entrain, move, detrain. All three steps must be done in the same phase.
>
> 1. To entrain, the cargo must be in a detrainable railroad hex (13.3c) that is not in an enemy ZOC. A unit moving by rail must be in Move Mode, and can expend up to half its MA in the phase before entraining. **Reinforcements and new SP can entrain “off-map” if their arrival hex contains a railroad (13.6b).**
>
> 2. To move, the cargo follows a path of connected rail hexes that does not enter a hex with an enemy combat unit or ZOC. Rail hexes that are wrong gauge (13.3f) or uncontrolled (13.3h) cannot be used.

> **现行译文**：铁路移动包括三个步骤：登车、移动、卸货。这三个步骤必须在同一阶段完成。
>
> 1. 货物登车时，货物必须位于不在敌方 ZOC 内的一个可火车卸货的铁路格(13.3c)。通过铁路移动的单位必须处于移动模式，并可在该阶段中登车之前消耗最多一半的 MA。**如果增援和新的 SP 的抵达格包含一条铁路(13.6b)，则它们可以在”地图外”登车。**
>
> 2. 货物移动时，货物必须沿着相连的铁路格移动，且不可进入有敌方战斗单位或 ZOC 的格。不能使用错误轨距(13.3f)或未控制(13.3h)的铁路格。

出处：英文 `:2306-2337`；译文 `:1804-1818`。

### 13.6b（增援入场）

> **英文**：Reinforcements can enter in any voluntary mode. They can be placed in hexes in an enemy ZOC (but note the Port restriction in 13.6a), and **can arrive by rail (ignoring the usual “entraining” requirements of 13.3e)**. If a map-edge arrival hex is blocked by enemy units, the reinforcements can be placed in the nearest unblocked map-edge hex.

> **现行译文**：增援可以以任何主动模式进入游戏。增援单位可放置在有敌方 ZOC 的格中(但要注意 13.6a 中的港口限制)，**也可通过铁路抵达(忽略13.3e中通常要求的”登车”)**。如果地图边缘的入场格被敌方单位阻挡，增援可以放置在最近的且未被阻挡的地图边缘格内。

出处：英文 `:2455-2466`；译文 `:1878-1883`。

## 2. 读法甲：13.6b 的「增援铁路抵达」

**主张**：13.6b 给**增援（含新 SP）**一条专门通道——抵达格含铁路时，可在「地图外」登车；13.3e-1 的登车格检查（是否可卸货 / 是否在敌 ZOC / 是否被敌占 / 是否有铁路）对这一类货物不适用。这就是 13.3e-1 末句与 13.6b 括号里那句「忽略通常要求的登车」在说的事。

**原文依据（逐句对应）**：

| 行为要素   | 依据原句                                                                                                                    |
| ---------- | --------------------------------------------------------------------------------------------------------------------------- |
| 谁能走     | 「**Reinforcements and new SP**」/「增援和新的 SP」                                                                         |
| 何时走     | 增援到场时（13.6b）。13.3b 的「运力只能在移动阶段」与它冲突，**13.6b 作为更具体条款构成例外**——用户 2026-11-13 已裁定此读法 |
| 起点条件   | 「if their **arrival hex contains a railroad**」/「抵达格包含一条铁路」                                                     |
| 起点豁免   | 「ignoring the usual “entraining” requirements of 13.3e」/「忽略13.3e中通常要求的“登车”」                                   |
| 不豁免什么 | 13.3e-1 第二句的单位资格（移动模式、登车前最多半程 MA）与 13.3f 的轨距仍照常；13.3e-2 的路径、13.3e-3 的卸货也仍照常        |
| 运力       | 13.3a/13.3b：按当回合额度扣；1 点＝1 SP 或 1 RE                                                                             |
| 终点       | 13.3c 可火车卸货格 + 不在敌 ZOC（13.3e-3）                                                                                  |
| 路径       | 相连铁路、本方轨距、无敌方单位/ZOC（13.3e-2）                                                                               |

**行为含义**：铁路运输的「起点」不在图上——增援单位从抵达格直接进入铁路网，省掉「先站到可卸货格再登车」这一步；但落点仍是正常的 13.3c 卸货格。它只发生在增援到场那一刻，不是移动阶段的通用登车权。

## 3. 读法乙：含铁路的入场格本身就是「主动登车格」

**主张**：移动阶段中，任何单位只要站在含铁路的入场格，就可以主动登车；这些格本身就是合法登车格，与 13.6b 的增援豁免无关。

**原文核对**：

1. 13.3e-1 第一句是**正面条件**：「the cargo must be in a **detrainable** railroad hex (13.3c) that is not in an enemy ZOC」/「必须位于不在敌方 ZOC 内的一个**可火车卸货**的铁路格」。这里的关键词是 13.3c 的可卸货格，不是「入场格」。
2. 13.3c 的可卸货格＝村庄/城市（任意规模）/港口/有工程能力的指挥部 + 已控制 + 有通往补给源且无敌方 ZOC 的铁路路径。**「位于地图边缘」或「是字母入场段」不在其中。**
3. 13.3e-1 末句的「off-map」主语被明确限定为「**Reinforcements and new SP**」；13.6b 的主语是「**Reinforcements**」。两句都没把登车权扩给「移动阶段的任意单位」。
4. 本作四个轴方铁路入场格的基础地形（`map-layers.json`）：F=8.0 `Open`、H=1.7 `Swamp/Forest/Woods/Open`、J=1.19 `Woods`、G=1.3 `Woods` / G=1.4 `Woods`——**都没有村庄/城市/港口/工程指挥部**，按 13.3c 不是可卸货格。

**结论**：读法乙需要额外加一个前提——「含铁路的入场格视同 13.3c 可卸货格」。四段原文里没有这句话。原文只允许「增援/新 SP 在抵达格地图外登车」，没有允许「任意单位在移动阶段于入场格登车」。

**一个不构成乙的例外**：如果某个入场格本身就有村庄/城市/港口/工程指挥部（例如边城），那么它在 13.3e-1 下本来就是合法登车格——但这是因为它是 13.3c 可卸货格，不是因为它叫「入场格」。本作 J/H/F/G 不属于这种情况。

## 4. 两种读法的行为对照

| 维度                        | 读法甲（13.6b 增援铁路抵达）                                    | 读法乙（入场格＝主动登车格）                 |
| --------------------------- | --------------------------------------------------------------- | -------------------------------------------- |
| 谁                          | 增援单位、新增 SP                                               | 任意单位（含已在图上的单位）                 |
| 什么阶段                    | 增援到场时（13.6b）；与 13.3b 的「仅移动阶段」由 13.6b 例外处理 | 移动阶段（13.3b）                            |
| 起点                        | 增援的抵达格，条件是**含铁路**                                  | 任何**含铁路的入场格**                       |
| 起点是否须为 13.3c 可卸货格 | 否（13.6b 豁免登车检查）                                        | 是（13.3e-1 第一句；乙若不满足就无依据）     |
| 起点敌 ZOC                  | 可忽略（13.6b 允许增援放敌 ZOC）                                | 不可（13.3e-1：不在敌方 ZOC）                |
| 运力                        | 扣当回合额度（13.3a/13.3b）                                     | 同样扣当回合额度                             |
| 终点                        | 13.3c 可卸货 + 不在敌 ZOC（13.3e-3）                            | 同左（13.3e-3）                              |
| 路径                        | 13.3e-2                                                         | 13.3e-2                                      |
| 单位资格                    | 5.6a 移动模式、5.10d 非 DG、登车前 ≤ 半程 MA                    | 同左                                         |
| 代码入口                    | `RailFacts.isEntryHex` → `entrainOffMap`                        | 若成立，需要额外的「入场格视同可卸货格」判据 |

## 5. 现实现支持哪条、缺哪条

**支持甲，且只支持甲。**

> **更正（2026-11-15）**：本段原先引用的 `rail.ts:340`（`input.entrainOffMap === true || facts.isEntryHex(from, cargo.side)`）在当时**实际放行了读法乙**——任何单位在移动阶段站在含铁路的入场格上都能登车，因为 `isEntryHex` 与「这次是不是增援抵达」无关。现已按 §5.1 的闸门改成：`validateRailMovement` 只在调用方**显式**传 `entrainOffMap === true` 时才跳过 13.3e-1 的登车格检查；`isEntryHex` 仅用于认出「入场格且含铁路」，不再单独豁免。增援铁路抵达的两处调用（`beginArrivalRailPickNow` / `confirmArrivalRailNow`）显式传 `entrainOffMap: true`，普通 `railMoveNow` 不传。红用例：`tests/stores/rail-entry-network.test.ts`「剧本 5：普通轴方单位在 J=1.19 … ⇒ 拒」。

- 判据：`src/engine/rules/rail.ts:894-898`——缺省 `isEntryHex`＝字母入场段 ∩ 该格含铁路（2026-11-13 裁定 1 收窄后；轴方 J/H/F/G 合格，K/I 不合格）。
- 豁免：`rail.ts` 的 `validateRailMovement`——**只有 `input.entrainOffMap === true`**（由增援铁路抵达路径显式传入）时跳过 13.3e-1 的四项登车检查（铁路、可卸货、敌 ZOC、敌占）；`facts.isEntryHex` 不再单独触发豁免。
- 工作台：`src/stores/workbench.ts:4115` 的 `entryStart` 复用同一判据；`railMoveNow` 的扣点在 `:4619`。
- 不豁免：轨距（13.3f，`rail.ts:367`）、单位资格（5.6a/5.10d/半程 MA，`rail.ts:354-364`）、路径（13.3e-2）、终点（13.3e-3）均照常。

**乙不成立（已定稿）。** 移动阶段的普通登车仍只认 13.3c 可卸货格；J/H/F/G 这些入场格若没有村庄/城市/港口/工程指挥部，普通单位在移动阶段不能在那里登车。用户 2026-11-13 已裁定：不把 13.6b 扩成移动阶段通用登车权，也不做房规乙。

**是否要并存**：**不并存**。甲是 13.6b 对 13.3e-1 / 13.3b 的**例外**，不是在 13.3e-1 上另开一条并行通道。

## 6. 最终口径（已定稿）

- **甲成立**：增援/新 SP 在含铁路的抵达格可以「地图外」登车；这是 13.6b 对 13.3e-1 的例外。
- **13.6b 同时是 13.3b 的例外**：这一步发生在增援阶段，但仍扣当回合铁路运力；额度与移动阶段共用一本账。
- **乙不成立**：不把铁路入场格当作移动阶段的通用登车格，不做房规。J/H/F/G 不是 13.3c 可卸货格，普通单位在移动阶段不能在那里登车。
- 例外边界见 §5.1：不撬 13.3b 的通用阶段闸门，只给「增援铁路运输」这一条专用路径开显式入口。
