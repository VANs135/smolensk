# Forage（21.10b）与 Supply Cache 设计

> 状态：**方案（未实现）**。`workbench.ts` 现由炮击线占用，本批只出文档。
> 原文＝OCS v4.3（`_tmp_review/ocs_rules_en.txt`、`OCS_TXT/_ocs_v43_clean.txt`）＋本作专规 1.7。

## 1 原文

### 1.1 21.10b Forage

> "**Forage.** In the **Supply Phase**, a player can spend a Supply Cache marker to allow an **HQ** to provide **all combat units within its Throw Range** with trace supply. Some restrictions:
> • Forage can only be used when **enemy action cuts the HQ's trace supply**. It **cannot be used by spearheads**!
> • Forage can only be used on the **first turn an HQ is out of trace supply**. After that, if still out of supply, it must breakout, eat off the map, or risk attrition."

译文：「**征粮**。在**补给阶段**，玩家可花 1 枚补给缓存标记，让一个**指挥部**为其**投递距离内的所有战斗单位**提供追溯补给。限制：① 只能在该 HQ 的追溯补给**被敌方行动切断**时使用；**先头部队（spearhead）不得使用**；② 只能在该 HQ **失去追溯补给的第一个回合**使用；之后仍断补，只能突围、吃图上补给或承受损耗。」

- 限补给阶段：**【原文】**（"In the Supply Phase"）。
- 限 HQ：**【原文】**（"allow an HQ to provide"）。
- 限「首次失补」：**【原文】**（"first turn an HQ is out of trace supply"）。
- 限「敌方行动切断」：**【原文】**；「敌方行动」含 ZOC/敌战斗单位/源被夺，不含玩家自愿放弃源（【口径】）。
- spearhead 定义：**【口径】**（按本作先头部队标记；当前数据未建模，见缺口 F3）。
- 覆盖对象「all combat units」：**【口径】** 取地面战斗单位（含 HQ 自身？见 §3.3）；空军/基地按 12.6 的机场补给另判。

### 1.2 Supply Cache（专规 1.7 + 21.10 引言）

> 1.7："Supply Cache markers ... are a **standard part** of this game (not optional). Both sides begin every scenario with **two** ... new markers are received via **Special Repl**."
> 21.10 引言（OCR 两栏拼接）："…usable **at any friendly HQ** as **either Forage or Shells**."

- 1 枚标记 = 1 次用法，**Forage 与 Shells 二选一**：**【原文】**（"either … or"）。
- 用掉即消失：**【原文】**（两处都写 "**spend** a Supply Cache marker"）——实现即 `supplyCacheHoldings[side] -= 1`，不退回。
- 「1 点」：本作数据把标记计为 1 点（`supplyCacheHoldings` 为整数枚），**【口径】** 不是 T 数。

### 1.3 12.6c 吃图上补给与 Forage 的关系

> 12.6c："**Units can only 'eat off the map' if no trace supply is available.** For every 1T spent, up to 2 RE (within draw or throw range of the dump) can be fed."

- Forage 给的是**追溯补给**；一旦某单位本回合被 Forage 覆盖，它**不再满足** 12.6c 的前提「no trace supply is available」⇒ 该单位本回合**不能**再吃图上补给。
- 两者不是同一资源的两种写法：Forage 花**补给缓存**（1 枚/整个 HQ 范围），12.6c 花**SP**（1T/2RE）。**互斥替代**，只对同一单位同一回合成立；未用 Forage 时 12.6c 照旧。
- 原文没有「Forage 后还要再付 SP」或「Forage 只能替代 12.6c」的表述 ⇒ 不作叠加。

## 2 状态怎么记

| 状态                  | 现有字段/函数                                                                        | 结论                                                                                                       |
| --------------------- | ------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------- |
| 该 HQ 连续断补的起点  | `ConsoleUnit.cutSinceTurn`（`workbench-model.ts:278`），由 `refreshTraceSupply` 落值 | 可直接用：`cutSinceTurn === 当前回合` 即「首次失补」（`isFirstCutTurnInSupplyPhase`，`workbench.ts:9463`） |
| 本回合靠特殊方式续命  | `ConsoleUnit.sustainedBySpecialSupplyTurn`（`workbench-model.ts:603`）               | 受益单位写它；`isOutOfSupplyNow` 据此不判断补（12.8e 括注）                                                |
| 该 HQ 本回合已 Forage | **缺**                                                                               | 新增 `ConsoleUnit.foragedTurn: number \| null`（默认 null），用于幂等、撤销与界面「已用」                  |
| 本次 Forage 覆盖了谁  | **缺**                                                                               | 新增 store 级 `lastForageGrant: { side, hqId, turn, unitIds } \| null`，仅用于本阶段撤销/展示；跨阶段作废  |

**过期判据**：

```
可用 ⇔ hq.cutSinceTurn === turn            // 首次失补（原文）
      && hq.foragedTurn !== turn           // 本回合没花过
      && !hq.isSpearhead                   // 原文
      && holdings[side] > 0                // 有标记
下一回合仍断补：cutSinceTurn < turn ⇒ 自动不可用，无需额外字段
```

HQ 若恢复追溯补给，`cutSinceTurn = null`；以后**再次**被切断会得到新的 `cutSinceTurn`，视为新的「第一个回合」（原文未禁止反复，**【口径】**）。存档：`units` 整体序列化，`foragedTurn` 作为可选字段随单位落盘；`lastForageGrant` 属阶段内临时态，可不入库（或存可选字段，读档即清）。

## 3 效果范围

### 3.1 复用哪套可达判定

用户口径「该 HQ 投递范围内、可合法追溯该 HQ 的己方单位」＝ **12.3b 投递可达**，但 **不要求 HQ 自己有追溯补给**（Forage 正是为断补 HQ 用的）。故复用：

- `countSupplyDistanceToAny(facts, { from: hq.hex, side, mobility: throwMobility, rangeMp: throwRangeMp, target: unit.hex })` —— 12.3d 路径 + 印值距离；
- `selfAndNeighbors(unit.hex)` —— 12.3c「相邻也算」；
- `throwRangeMpOf` / `throwMobilityOf`（`workbench-model.ts`）—— 读 HQ 印值，**不再手填**；
- **不要**用 `computeHqCanThrow`（它判 HQ 自己能否取补给，正好是 Forage 要绕开的前提）。

### 3.2 覆盖与落盘

```
covered = units.filter(u =>
  u.side === hq.side && u.isCombat &&
  (u.hex === hq.hex || selfAndNeighbors(u.hex).some(h => countSupplyDistanceToAny(...h...) ≠ null))
)
markSustainedBySpecialSupply(covered.map(u => u.instanceId))   // 已有函数，12.8e 同口径
```

- 受益单位的 `hasTraceSupply` **保持 false**（用户 2026-11-06 裁定：Forage 不构成追溯补给），只写 `sustainedBySpecialSupplyTurn = turn`；本回合因此不判断补。
- **HQ 自己不做受益单位**：原文只说「让 HQ 为范围内单位提供」，HQ 仍在断补；`cutSinceTurn` 不被清除，下一回合自然不能再用。
- 12.6f 编队同源：Forage 是「供给事件」不是「拖取来源」，不触发编队拆分；**【口径】**。
- 被 Forage 覆盖的单位在本回合 12.6c 喂食列表中**排除**（避免叠加）。

### 3.3 边界例子

- HQ 36.10、投递印值 5、36.14 的步兵：4 ≤ 5 ⇒ 被覆盖；36.16 的步兵：6 > 5 ⇒ 不覆盖，仍可吃图上补给或断补。
- 该 HQ 下一回合仍断补：`cutSinceTurn` 仍是上一回合 ⇒ Forage 选项消失，只剩 12.6c/12.6d。

## 4 入口放哪

**结论：与吃图上补给并列，同一面板、两个选项**（与用户倾向一致，原文也支持——Forage 就在补给阶段）。

- 落点：`SupplyPhasePanel.vue` 的 D 段「③ 吃图上补给分配（12.6c）」区域，改成「断补处置」二选一：
  - `吃图上补给（SP）`：现有 `applySupplyPhaseFeedingNow`；
  - `Forage（1 枚补给缓存）`：仅当存在可用 HQ 时出现；选中后列出**可用 HQ**（`cutSinceTurn === turn`、未 spearhead、有标记），并预览覆盖单位数。
- 「不可用项不出现」：第二次失补（`cutSinceTurn < turn`）、无标记、无可用 HQ 时，Forage 选项**整项不渲染**，只剩吃图上补给。
- 单一入口：删除 `ExclusiveRulesPanel.vue` 的 Forage 表单（HQ 格、投递距离、执行按钮），该栏只保留「剩余缓存枚数」信息；`supplyCacheInputs.use` 的 `'shells'` 死分支一并删除（Shells 已迁到炮击面板）。
- 12.6c 仍由 D 段落盘；Forage 与喂食共用同一个提交按钮，内部按选择分派，避免两个入口各扣一次。
