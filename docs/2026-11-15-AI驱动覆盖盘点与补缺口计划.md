# AI 驱动覆盖盘点与补缺口计划（2026-11-15）

> 范围：`src/ai/policy.ts`（纯决策）、`src/ai/driver.ts`（快照 + 提交）、`src/views/GameTableView.vue`（PVE 循环）。
> 本文只做盘点与计划，**未改任何代码**。
> 约束：`src/stores/workbench.ts` 当前有别的线（增援）未提交改动，本计划中凡需改该文件的项，一律等其提交后再动。

## 0. 结论摘要

1. 现有 AI 是「单动作贪心」：每步从快照挑一个动作，提交失败就记规则号并换下一个候选。
2. 真正跑通的只有 **移动、常规战斗、地面炮击、补给阶段三段（计划/恢复/供养/损耗）、低空扫射**。
3. 规则表 `ACTION_GATES` 共 32 个动作族；AI **直接提交**到的只有 8 个：
   `move.order`、`move.modeChange`（仅预备→战斗）、`barrage.declare`（仅地面炮兵）、`combat.declare`、
   `supply.draw`（仅阶段总计划/供养，不含逐单位拖取）、`supply.recovery`、`supply.attrition`、`air.mission`（仅 `hip_shoot`）。
   `move.overrun`、`air.transfer`、`air.refit`、全部 `rein.*`、全部 `move.rail*/load/construction/...`、`supply.fuel`、
   `reserve.release`、`exclusive.*` 均未进入 AI 的直接分支。
4. **33 个既有提交入口从未被 AI 调用**（见 §3 清单），覆盖 A 整备、B 增援落位/重建、C 铁路/装载/架桥/换轨/拆合/延补队/突围/突袭、D 燃料/拖取/Forage、E/G 预备释放、H 治安检查等。
5. 初设的「抽取编队、确认开局」也不在 AI 里：`drawSetupEffectsNow` / `startGameNow` 从未被 AI 调用（现有自对打用例是**测试代码**代做的）。
6. 直接原因有三类：
   - 快照没带该动作族的候选；
   - 入口需要「点地图」的多段式输入，而 `runAiStep` 直接调 `clickHex`，绕过了地图层的分派（突袭、六角选点、选项页点图都在地图层）；
   - 策略层只写了移动/战斗/炮击/补给四条主链。

## 1. 现有结构与动作族

### 1.1 决策链

- `policy.ts#decideAiAction`：按固定优先级返回**一个** `AiAction`；
- `driver.ts#snapshotOf`：把 store 的既有只读投影拼成 `AiSnapshot`；
- `driver.ts#execute`：把 `AiAction` 翻译成 store 的具名提交入口；
- `driver.ts#runAiSelfPlay`：循环 + 拒绝计数 + 卡死判据。
- 策略层纪律：不新增规则判据、不掷骰、不用 `Math.random`；合法性只读既有投影。

### 1.2 已实现的 `AiAction`

## 4. 根因归类

1. **快照缺候选**：`AiSnapshot` 没有 B 段到货/重建、A 段基地、铁路目的地、装载点、工事格、突袭目标、预备单位（E/G）等字段。
2. **地图分派被绕过**：`moveClick` 直接调 `workbench.clickHex`，而地图层在 `clickHex` 之前还有四类分派：`pickHexFor`（六角选点）、options 草稿、`overrunTargets → overrunNow`、退款/挺进格。AI 走不到这些分支。
3. **策略没写**：`decideAiAction` 只按「提问 → 结算 → 初设 → 移动 → 空军 → 预备 → 移动 → 炮击 → 战斗 → 补给 → 推进」顺序，其他动作族没有分支。
4. **默认值过简**：选项一律全撤退格、损失不改派、补给站取第一座——不是错误，但会制造白名单拒绝（12.4 等）。

## 5. 补缺口计划（最小策略）

### 批次划分（每批先红用例，再实现，单独提交，六门槛报实数）

**批 1：初设 / A / B（行政链）**

- 初设：加 `drawSetup`、`startGame` 两个动作；`startGameNow` 失败时按 `setupStartEntryVisible` 再试一次（两段式）。
- A：`refitBase` —— 取 `airBases` 中本方、`airInactiveAtBase(baseId)` 非空、`airRefitPayDumps(baseId)` 有站的基地，调 `refitBaseNow(baseId, [第一架], 第一个付款站)`；无可用基地则推进。
- B：`placeArrival(index)` —— `arrivalCandidates[index][0]` 非空则 `placeArrivalNow(index, arrivalRecordOf(index)?.id, hexText)`；候选空且 `arrivalAirBoxAvailable(index)` 则 `placeArrivalInAirBoxNow(index)`。
- B：`applySupplyArrivals`（`freeRailPlan` 非空时）、`placeSupplyTrain`（`supplyTrainPending` + 第一个 `supplyTrainPlacementHexes`）。
- B：`rebuild` —— `rebuildCandidates` 逐个试 `beginDeadPileRebuildNow` + `pickHexFor(rebuildLegalHexes[0])`，或 `rebuildOnMapUnitNow` / `rebuildAircraftIntoBoxNow`；整编用 `canConsolidateSelectionNow` + `consolidateSelectionNow`。
- B：特殊补员返场 / 方面军落位用 `replArrivalPlacement` 的格；结束本段时保留「确认放弃」兜底。
- 默认：到货能落就落，落不下按规则进死亡堆（入口自己判）；重建优先死亡堆、再图上打残。

**批 2：C 移动支线**

- 突袭：快照带 `overrunTargets`；移动中目标非空时 `moveClick` 改为先 `overrunNow(hex)`，再按 combat 链结算（8.1b 落下由引擎给）。
- 空军轰炸（C 段 `movement.barrage`）：快照带 `barrageAirUnits` / 目标；`setBarrageTargetKind` + `toggleBarrageAirUnit` + `beginBarrageNow`。
- 铁路：`railMoveFacts` + `railSupply.detrainableHexes` 取卸货格，`railMoveInputs.toHexText` 后 `railMoveNow(kind)`；单位登车、SP 货运分别试。
- 换轨：`convertRailGaugeNow(unitId, hexTextOf(unit.hex))`（引擎判是否 justEntered）。
- 装载/卸载：`selectTransportLoadPointNow(pointId)` 后 `loadTransportPointNow` / `unloadTransportPointNow`。
- 合并/拆分：`transportPointInputs.mergeIds` 选同格同型，`mergeTransportPointsNow`；拆分用既有 SP 拆分入口。
- 延补队：`transportPointsOfSide` 逐格 `convertTransportToExtenderNow(hexText, kind)`。
- 销毁补给站：`spDumps` 中本方、可销毁者 `destructDumpNow(id)`。
- 工事：`hedgehogInputs.hexText = 工程兵所在格` → `buildHedgehogNow`；建造标记 `useConstructionMarkerNow('bridge'|'airStrip', 工程兵所在格)`；基地 `constructionInputs.hexText` + `buildAirBaseNow`。
- 拆分单位：移动开始后 `canCreateBreakdownNow(unitId)` 为真时 `createBreakdownNow(unitId, breakdownRecordChoicesFor(unitId)[0].id)`。
- 突围：`breakoutCandidates` 取 `ok` 者 `breakoutNow`；返场 `deployBreakoutReturnNow(unitId, replArrivalPlacement.hex)`。
- 加油：移动前 `fuelMethodsForUnitNow(unitId)` 有合法方法则 `openFuelNow` + `payFuel`（默认 `singleUnit`，付款站取第一个）。
- 堆叠移动：`beginMoveFor(该格全部可动单位)`；落下由 8.1b 引擎处理。

**批 3：D / E / G / H**

- 拖取/投递：`beginSupplyCheckNow(unitId)` → `chooseSupplySourceNow(0)` → `confirmSupplyPickupNow`（逐个断补单位）。
- Forage：`forageOptions[0]` → `useForageNow(hqId)`。
- 预备释放：E/G 段对本方 reserve 单位 `selectedId = id` → `releaseReserveNow()`（每单位一次）。
- 治安：H 段 `applySecurityNeedsNow()`；3.4a 段末对 `panzerObligationActive` 的单位 `applyPanzerGroupDgNow(id)`。
- 空军任务种类：除 `hip_shoot` 外，按环节从 `airMissionKindChoices` 取第一种（移动环节：空运/空投/扫荡；轰炸环节：空军轰炸/运输破坏）；只做「有目标、有飞机」的最小宣布，结算仍走现有 C→G 循环。

**批 4：F 战斗默认值收口**

- 选项：先试「撤退格 = 规则允许的最大值、损失点 = 0」；被拒再试「0 撤退、全损失点」；仍拒且守方才忽略（保持现状但用快照判断守方/攻方归属）。
- 损失：保留引擎默认分配；仅在 `canTakeOptionLossPoint` 有合法候选且默认分配被拒时改派 1 点。
- 补给站：按可用量降序选站（读 `combatSupplyDumps` 的 `availableT/SP`），减少 12.4 白名单拒绝（白名单保留，但计数应下降）。

**批 5：双 AI 跑分与报告**

- 先 `Intro`，再剧本 1–7；每局记录 `iterations / refusedByRule / stalls / rules`。
- 同种子两次签名对比（现有剧本 1 用例扩展到 Intro + 1–7）。
