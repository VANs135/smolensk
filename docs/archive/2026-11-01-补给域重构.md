# D段补给域重构

本轮接续 aa0490f 的生命周期与快照边界，将 D 段恢复、供养、损耗及阶段退出义务从工作台迁入独立域。保留 Vue/Pinia、既有地图和规则数据、界面操作入口及 v6 存档字段；没有替换现有规则体系。

## 模块与职责

| 模块                                    | 职责                                                                             |
| --------------------------------------- | -------------------------------------------------------------------------------- |
| `stores/supply-phase.ts`                | 每局独立持有计划、输入、结算标记、已掷损耗和已执行损耗；编排恢复、供养及损失落盘 |
| `stores/supply-types.ts`                | 共用 SP 持仓类型，兼容工作台原有类型出口                                         |
| `engine/rules/supply-phase.ts`          | 继续负责恢复费用、供养计划和损耗规则；新增统一的实际断补堆叠汇总函数             |
| `engine/rules/supply-phase-progress.ts` | 纯函数决定退出阶段的下一项义务；不持有地图、随机源或界面状态                     |
| `stores/workbench.ts`                   | 连接单位、实际可达站付款、种子骰源、标记、淘汰及正式阶段切换；原接口转交独立域   |

快照注册表继续绑定域返回的同一批 ref，因此恢复和阶段重置均不会另建一份隐藏状态。输入保留原有策略，阶段重置清除计划、错误、骰面和执行账本。

## 修复的行为

1. **旧断补单位获补给后仍被掷损耗。** 旧实现将原有断补名单与新增名单合并，却未减去恢复名单。现按最终断补状态汇总；恢复追溯补给和获实际供养者移出损耗名单。
2. **计划可供养、实际付款失败后漏掉损耗。** 原实现虽将单位重新标为断补，却继续使用付款前的损耗名单。现使用实际落盘后的单位状态统一汇总，保留付款失败者的义务。
3. **清空或重算计划可能覆盖待决义务。** 供养落盘后，计划成为阶段损耗账本；清空草稿不能删除它，重复载入复用已结算计划。等待玩家分配损失时保留原骰面，重试阶段退出不会重掷。

恢复、供养及损耗的已执行标记仍确保重复点击不重复扣款或损失。退出整个 D 段时依次处理恢复、进入检定、供养和损耗；存在可选择的损失分配时停留等待玩家。只有规则结果没有选择空间时才自动分配。

## 验证

新增独立域测试使用真实单位数据和规则，并在付款及骰源端口记录操作，覆盖实例隔离、重复恢复、状态容器稳定、付款失败、待决损失保护、骰面保留及整段退出顺序。引擎新增旧断补恢复后免损耗回归；修复前已复现恢复者误损耗和付款失败者漏损耗两项失败。

动作入口检查同步扫描独立域的实际函数体，避免仅扫描兼容转发函数而丢失环节闸门检查。既有补给专项、七剧本流程及存读档回归继续使用正式工作台入口。

全量运行首次出现冷读档用例超过默认 5 秒限时（6.39 秒），单独重跑其全部断言通过但耗时仍接近 5 秒。该用例包含真实整图冷启动和重建，单独设置 15 秒上限，以容纳并行调度波动；保留全部状态断言和其他用例的限时。

最终全量结果：302 个测试文件、3995 条用例全部通过。补给专项 73 条用例通过；类型检查、ESLint、全仓格式检查、架构扫描和生产构建通过。生产构建仍有既有的单包体积提示，未将包拆分纳入此次规则域迁移。

## 剩余边界

本轮迁移的是 D 段状态和编排。可达补给站选择、运输载货付款及淘汰公共通道仍由工作台提供端口；移动、战斗和空军也仍待逐域迁移。没有将整个项目宣布为已完成重构，也没有宣称复杂规则组合均已得到人工规则认证。
