# S1/A3第七批：混编补给付款检查

基线`2c82405`。检查SP归属的实际使用时发现，工作台把全部受益单位聚合为一个集群，并要求所有单位都属于编队；混入独立单位或两个集群时，可能把整笔付款判成不受限。

本批新增纯规则函数`checkPanzerGroupSpBeneficiaries`，逐个复用既有`checkPanzerGroupSpPayment`。独立单位自身不受限，但不能使其它受益编队获得豁免；两个集群混编时，也不能把不同归属折成一个null而绕过检查。共用工作台入口为燃料、战斗补给与轰炸付款提供这项检查，调用位置和费用不变。

新增3项store回归，分别覆盖fuel/combat/barrage用途。每项检查独立单位混编、不同集群混编均拒付且单位、SP和骰序不变，正确归属下独立单位与编队混编可通过。既有付款专项一并回归，相关文件21项测试通过。

边界：新增混编用例直接验证三个付款消费者共用的门禁，不等同于三类真实战斗/燃料/轰炸完整结算均已逐场验收。资源总账、拖取及人工界面验收继续待办，S1/R0未完成；未改存档格式或规则数值。两份原有未跟踪UI分析文档未改动、未提交。

最终全量323个文件、4239项测试通过（210.58秒），类型、ESLint、全仓格式、架构检查及生产构建通过。构建保留既有大包提示。
