## 1. 权威口径（用户原话要点）

- 触发判据是「**该师与本集团军指挥部在同一位置进场**」，不是全图 `locked` 前缀、
  也不是"任意时刻到场即锁"。
- 「OCS 并没有集团军的下属编制，唯一同编制的只有编队单位，这个只是慢动员等专规的特例」
  ⇒ **不得引入 OCS 编制概念**：不新增"军-师隶属"字段，不把它当通用机制。
- 交互：每回合由玩家从"仍锁定"的师中**自选**，可挑数量＝表 2-2 当回合配额；已解锁的累计生效。
  原型：30 集团军共 5 师；7.12 选 2 ⇒ 2 可动、3 仍锁；7.15 其余 3 一并可动（累计 5 封顶）。
- 核对目标：30 集团军 5、28 集团军 8、24 集团军 11；**须从增援表数据推导**，不得硬编码，不符则停下回报。

## 2. 原文与表 2-2

- 专规 2.4「Slow Mobilization」：随集团军指挥部到达的师，到场即锁定；被锁师不能移动、不能拆解；
  解锁按表分批，由玩家在被锁的师中自选。
- 表 2-2（`rules-constants.json → smolensk.slowMobilization.table`，与规则书核对后订正）：

| 日期 | 30th  | 28th  | 24th   |
| ---- | ----- | ----- | ------ |
| 7.12 | 2     | —     | —      |
| 7.15 | 3     | 3     | 3      |
| 7.19 | —     | 5     | 5      |
| 7.22 | —     | —     | 3      |
| 合计 | **5** | **8** | **11** |

- 原文未细分"同一位置"是"同一格"还是"同一入口卡批次"；本作以**到达卡分组**承载位置
  （同一组的 HQ 与其师同批同处进场），实现按"同一到达卡分组"判定。此解释属**用户裁定**。

## 4. 实现（最小改造）

- 引擎：`src/engine/rules/arrival.ts`
  - 新增 `slowMobilizationQuotaRemaining({date, army, alreadyUnlocked})`：
    `min(当日配额, 截至当日累计配额 − 已解锁)`；`planSlowMobilization` 复用它，提交时仍复核。
  - `planSlowMobilization` 已支持 `selected` 批量 + `alreadyUnlocked`，未改语义。
- Store：`src/stores/workbench.ts`
  - `slowMobilizationLockedOf(army)`：该集团军仍锁定的师（只认到达卡分组落到算子上的
    `slowMobilizationArmy`，不猜番号前缀，不新增编制字段）。
  - `slowMobilizationQuotaOf(army)`：面板显示/置灰用的当日可挑数。
  - `unlockSlowMobilizationBatch(ids)`：整批校验（跨集团军 / 无归属 / 非师 / 已解锁 / 超配额
    一律整批拒绝，规则号 2.4，账本不动）；成功后只解锁勾选的几枚，并写会话日志。
  - `slowMobilizationUnlockedAt(id)`：从**已存档的会话日志**（`action: 'slowMobilizationUnlock'`，
    记 `turn`＋`date`＋`selectedIds`）回答"何时解锁"；**未新增存档字段**。
  - `unlockSlowMobilizationNow(id)` 保留为单枚入口，内部走整批，口径一致。
- 界面：`ReinforcementPanel.vue`
  - 集团军选择 + 仍锁师清单勾选；勾满当日配额后其余置灰；可取消勾选后再提交。
  - 显示"当日可挑 / 已勾"与"已解锁（日期 / 回合）"；提交后清空本地勾选。
- 保留既有防重复逻辑：同日重复提交由 `alreadyUnlocked` 推导 ⇒ 不重复给配额；
  换方往返不重置当日配额；读档后 `locked=false` 已持久化，已解锁状态不丢失。

## 5. 失效/边界场景（如实交代）

- **1.6a 永久移除**：已解锁师被永久移除后不留在死亡堆，盘面推导的"已解锁数"会下降，
  理论上回吐配额。需正式账本才能精确 —— 见待审批①，本批保持近似并在代码注释标注。
- **未开局演练**：没有会话日志 ⇒ `slowMobilizationUnlockedAt` 返回 null，界面显示"履历未开局"；
  解锁状态本身仍正确（`locked=false`）。
- **跨集团军同批提交**：整批拒绝（原文按集团军分别解锁）；界面每次只列一个集团军。
- **晚起始剧本**：开局时"历史应解锁多少"仍留白 —— 见待审批②。
