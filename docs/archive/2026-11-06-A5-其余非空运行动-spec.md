## 5. A5-01 最小修复方案（先红后绿）

**文件**：`src/stores/workbench.ts`，函数 `createBreakdownNow`（约 18069–18143）。

**现状问题**：`planBreakdownCreate` 收到的 `breakdown` 视图由母单位复制而来，且 `ar: parent.raw.ar`，使 20.0b 的 `breakdown.ar > parent.ar` 永远为假。

**改法**：

1. 把 `choices.value.find(item => item.id === breakdownRecordId)` 提前到 `planBreakdownCreate` 之前。
2. 新增内部映射（只读记录，不改状态）：
   ```ts
   function breakdownViewOfRecord(
     record: UnitRecordView,
     parent: ConsoleUnit,
     nationality: string,
   ): BreakdownSideView {
     return {
       ...toBreakdownSideView(parent, nationality),
       id: `breakdown:${record.id}`,
       classKind: record.classes.combatClass,
       ar: record.factors.combat.ar,
       steps: record.steps.total,
       printedSteps: record.steps.total,
     }
   }
   ```
   - `dg` / `internalStocks` / `mode` 保留母单位值：20.0c 要求创建时状态相同，这是**当前创建时点**的正确口径。
   - `classKind` 取记录自身的 3.2a 分类（20.0「只有其他类型」）。
3. `planBreakdownCreate` 改用该视图。记录查不到时沿用现有 `20.0g` 日志并返回 false。
4. 不改 `planBreakdownCreate` 引擎判据、不改 `absorbBreakdownNow`（吸收已用真实算子视图）、不改 `containers.takeBreakdown`（其 AR 由玩家显式选择）。

**红用例**（先写，预期失败）`tests/stores/breakdown-ar-20-0b.test.ts`：

- 用真实数据挑一个 `combatClass=other`、`ar=2`、`steps.total≥2` 的母单位与一个 `ar=3` 的拆分子记录。
- 创建时：`createBreakdownNow` 返回 `false`；日志规则号 `20.0b`；母单位 `steps` 不变；池计数不变；图上不新增算子。
- 修前实际会返回 `true` ⇒ 红。

**绿用例**：同母单位选 `ar≤2` 的拆分子 ⇒ 返回 `true`，母单位 −1 军力、池 −1、新增 1 个 1RE 算子。

**数据前提**：拆分子记录自带 `factors.combat.ar`（`units-soviet.json` 的 `su-breakdown-russian-3-3-3-breakdown` 等），无需新字段；若实跑发现某国籍池没有 AR 可区分的记录，则该方用例记为数据缺口，只保留有数据的一方。

## 6. A5-08 待裁定项（不自行扩引擎）
