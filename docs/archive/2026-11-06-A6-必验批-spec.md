## 1. A6-11 13.8b 失能例外（行为缺口，本批实现）

### 1.1 原句与语义边界

原文（`_ocs_v43_clean.txt` L2530–2532）：

> 「当单位不再具备工程能力时，架的桥就会消失。（例外：具有工程能力的单位在通过切换模式或朝向而失去工程能力后，**可以使用自己架的桥离开该格**。）」

可确证的行为边界（不扩展）：

1. 主体：**该单位自己**（其它友军不能借这座已消失的桥，13.8b 前半句的"进出工程能力单位所在格"已不成立）。
2. 方向：只允许**离开**该格（`from` 格），不允许进入该格，也不允许第三方使用。
3. 触发：因**切换模式或朝向**而失去工程能力（13.8a 的 `canEngineer` 由真变假）。
4. 突袭：8.1c/13.8b「攻击单位不能使用架桥能力跨越格边来过河突袭」仍然优先 ⇒ 突袭步不降级。
5. 战斗：原文只说"离开该格"，未说可用自己的桥跨河**攻击**；`createBattleFacts` 的攻击门槛**不改**，记入文档，不臆造。

### 1.2 现状与缺口

| 事实       | 现状                                                                                                                                     |
| ---------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| 架桥格来源 | `workbench-model.ts#bridgedHexesBySide` 只收**此刻**具备工程能力的 HQ 所在格                                                             |
| 失能后     | 切成移动模式后该格立即从清单消失，`moveContext` 与 `combatFacts` 都不再认为有桥                                                          |
| 按单位事实 | `MoveContext` 无任何按单位的"自有桥"通道；`bridgedCrossing` 的 `bridgePresent` 由两个调用点恒传 `true`，无法表达"只有该单位可用"         |
| 既有断言   | `tests/engine/construction.test.ts:637` 只测"非自己架的桥不降"；`tests/stores/bridge-terrain-flow.test.ts:62` 只测"切移动模式后清单为空" |

⇒ 规则句"可以使用自己架的桥离开该格"**整局不可达**，属真实行为缺口。

### 1.3 改动面（为什么必须扩签名）

必须扩：现有输入只有"格集合"（按格、无单位身份）与"布尔 bridgePresent"（全有/全无），无法同时表达"该格无桥（其他人不能用）＋该单位离开时例外"。

| 文件                             | 函数/字段                                                        | 改动                                                                                                                                                                                |
| -------------------------------- | ---------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `src/engine/rules/move-types.ts` | `MoveContext`                                                    | 新增可选 `ownBridgeHexByUnitId?: Readonly<Record<string, HexRef>>`——**按单位**的自有桥格（瞬时事实，不进存档、不进 `ConsoleUnit`）                                                  |
| `src/engine/rules/move.ts`       | `crossingForStep`                                                | 桥生效条件由"本步出/入格在 `bridgedHexesBySide`"扩为"**或** 该单位 `ownBridgeHexByUnitId[id]` 等于 `from`"；仍交给 `bridgedCrossing`（`bridgePresent:true`），`forOverrun` 照旧阻断 |
| `src/stores/workbench.ts`        | 新 `ownBridgeHexByUnitId` ref                                    | `unitId → hex`；只记录"刚因模式/朝向切换而失能"的那一格                                                                                                                             |
| `src/stores/workbench.ts`        | `switchUnitMode`、`flipUnitOrientation`                          | 切换前记 `wasEngineer = engineerCapableNow(unit)`；切换后若 `wasEngineer && !now` 且在地图上 ⇒ 记该格；若恢复能力 ⇒ 清该单位记录                                                    |
| `src/stores/workbench.ts`        | `moveContext` computed                                           | 注入 `ownBridgeHexByUnitId: ownBridgeHex.value`                                                                                                                                     |
| `src/stores/workbench.ts`        | `applyMovePatches`、铁路落盘（`railMoveNow` 内 `unit.hex` 赋值） | 单位离开记录格 ⇒ 清记录（避免离开后重返仍享受降费）                                                                                                                                 |

**不扩的点（写明依据）**：

- `buildMoveContext` 的入参只加一个透传字段，`toMoveUnitView` 不改（该事实不是单位印值/模式，放 `MoveContext` 更贴近既有 `bridgedHexesBySide` 模式）。
- `createBattleFacts` 不传该通道：13.8b 的例外只授权"离开该格"，未授权失能单位跨河攻击。
- `setUnitModeAtSetup` 不记录：初设时从未具备过工程能力，不存在"自己架的桥"。
- `releaseReserveNow`、DG 施加不记录：5.10e 下 DG 朝战斗面仍具工程能力；预备释放不构成"切换模式或朝向"。

### 1.4 先红后绿的用例设计

1. 引擎级（新文件 `tests/engine/own-bridge-13-8b.test.ts`，合成地图）：
   - 红：移动模式单位（`canEngineer=false`）、`bridgedHexesBySide` 为空、`ownBridgeHexByUnitId[id] = from` ⇒ `evaluateStep` 跨 Major River **成功**且按 Minor River 计费；修前为 `prohibited`。先跑红（失败断言为"期望 ok"）。
   - 对照：同一上下文去掉该通道 ⇒ 仍 `prohibited`（证明不是把桥白送给所有人）。
   - 对照：同格另一单位（无记录）⇒ `prohibited`。
   - 对照：`ownBridgeHexByUnitId` 指向别格（不在 `from`）⇒ 不降级。
   - 对照：`forOverrun` ⇒ 不降级（8.1c）。
2. store 级（追加到 `tests/stores/bridge-terrain-flow.test.ts`，产品真实地图的 `MAJOR_EDGE`）：
   - HQ 战斗模式在 `from` ⇒ 清单含该格。
   - `switchUnitMode('move')` ⇒ 清单不含该格（对其它单位无桥），但 `store.moveContext.ownBridgeHexByUnitId[hq.id] === from`。
   - `evaluateStep(store.moveContext, hq.id, to)` ⇒ ok（红→绿）。
   - 同格轮式卡车 ⇒ 仍 `prohibited`（桥对该单位已消失）。
   - HQ 走离该格后（store 移动入口）⇒ 记录被清空。
