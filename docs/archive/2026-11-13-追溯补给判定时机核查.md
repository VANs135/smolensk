## 三、发现的偏差

1. **12.8a 的「标记保持」被中途重判破坏（最严重）。**
   战斗里摧毁 HQ/延补队、换轨、延补队翻面或崩溃，都会立刻把受影响单位写成断补并即时生效：后续同一阶段的战斗按 ×½、丢 ZOC、图标变红。按 12.8a 这些标记应保留到**下一个友方补给阶段**才重判。

2. **12.8e 用「全局重写」实现「本环节检查」。**
   突围资格（`breakoutVerdictOf`）与「最近的拥有追溯补给的友方战斗单位」都读标记，所以实现只能在进入移动阶段时全局刷新来保鲜。若把这次刷新删掉，突围就会读到上一回合的旧标记。正确做法是：突围环节对每个候选单位就地实时查 `traceSupplyAt`（只读），条件 A/B 的「有追溯补给的友方」也实时查；**不写** `hasTraceSupply`。

3. **4.5 的 ZOC 判据有两份。**
   地图高亮（`map-view.ts` 246–257）与引擎内敌方 ZOC 事实（`workbench-model.ts` `toTraceSupplyUnitView`，`hasTraceSupply: unit.hasTraceSupply`）读的是「有无追溯」；实际 ZOC 判定（`hotseat.ts` 179）读的是「是否被标记断补」。吃图上补给/部队储备续命的单位 `hasTraceSupply=false` 但**未被标记断补** ⇒ 显示上被判无 ZOC，实际判定却有 ZOC，同一盘面两套结论。

4. **补给阶段内仍有三条判定入口。**
   阶段入口全场重判（1）→ 玩家逐单位检查（3）→ 阶段末计划 + 落盘（6），同一单位可能被写两三次；入口那次还会把**对方**也重判。另外引擎 `planOutOfSupply` 把「被喂饱者」列进 `clear`（`trace-supply.ts` 1703），store 落盘只清 `status === 'inSupply'`（`supply-phase.ts` 387–390），日志里的「除 N」会把被喂饱者算进去。

5. **消耗 SP 会即时改变追溯结论。**
   12.3b 的 HQ 投递资格要求 HQ 能按 12.3a 拖到 SP（`hqCanThrow` → `canDrawFromDump`），而 trace facts 的 dump 只记位置、不记数量；装载中的 dump 一旦用尽就从 `allSpDumps` 消失（`workbench.ts` 3644–3658），可能让 HQ 失去投递资格。补给阶段内恢复/喂食花掉 SP 后再重判，会让本阶段已经判过的单位改判。这是「12.3b 依赖 SP」与「一阶段判一次」的交叉点，需要明确判定顺序（见改法 5）。

## 四、改法要点（若要改）

1. **阶段边界一次判定。**
   `refreshTraceSupply` 只允许在 `phase === 'supply'` 且只写 `activeSide` 的单位；入口判定与 D 段计划合并为一次（计划直接读入口结论，或入口不写、只由 D 段落盘写）。给本阶段加 `supplyJudgedThisPhase: Set<unitId>`，重复写入跳过并在日志标「已判」。
2. **回合内沿用同一结论。**
   删除第二节表中所有非补给阶段的 `refreshTraceSupply` 调用（含移动阶段入口、摧毁/翻面/崩溃/换轨/突围往返/SP 用尽）。这些动作只改「此刻能否够到」的事实，不改断补标记。
3. **局部「此刻」查询列入白名单，只读。**
   12.8e 突围（含条件 B 的「有追溯补给的友方战斗单位」）、12.6e 战略收步、9.14d 崩溃落点、12.3a/b 取补候选、12.4/10.1b/12.5 付款、12.6c 可用性：一律走 `traceSupplyAt` / `drawableDumpsFor` 实时查询，**不写** `hasTraceSupply`。
4. **显示与规则用同一份结论。**
   抽一个 `supplyStatusOf(unit, turn)`（= 标记 + 续命），地图图标、ZOC 高亮、ZOC 事实、战斗值、损耗全部取它。把 `ZocSource.hasTraceSupply` 的语义改成「未被标记断补」，或直接在构造处传 `!isOutOfSupplyNow`。
5. **12.3b 与 SP 消耗的判定顺序。**
   二选一并写进文档：① 本阶段追溯判定用「本阶段开始时的 dump 持仓」，阶段内消耗不回改标记；② 明确「每花一次 SP 都重判」，但那就等于承认补给阶段内会改判，与「一次判定」口径冲突。推荐 ①，与本轮用户口径一致。
6. **两处 `clear` 口径统一。**
   要么 `planOutOfSupply` 不再把被喂饱者列进 `clear`，要么 store 按计划全量落盘；同时修正日志计数。

### 6.2 「提醒」落在哪

- 结论：**只用只读 computed 做两处文字提醒，不加单位角标、不染地图色。**
  - 地图 hover `tip`（`map-view.ts` `groundTokens`，约 339–348）追加一段 `当前补给线：通/断`；
  - 补给面板的单位状态行追加同义的一行。
- 显示规则：**只在「当前实时追溯」与「本回合已结算标记」不一致时出现**（例：走出范围但未被标记断补；或标记断补但此刻线又通了），避免平时刷屏。
- 纯展示：`traceNow = traceSupplyAtForMove(hex, side)`；不写 `hasTraceSupply`、不写 `cutSinceTurn`、不参与 ZOC（4.5）、战斗值（9.5/9.5a）、损耗、12.6c 候选。
- 角标为什么不加：角标是 12.8d「标为断补」的结算效果，再叠一个实时角标会被玩家当成断补；地图色会与 ZOC/移动范围/选中态冲突。

### 6.3 补给阶段判定收成一处

1. **唯一判定入口**：`settleTraceSupplyAtPhaseEntry(side)`，在进入 `phase==='supply'` 时调用一次（`setPhase` 与 `phase-coordinator` 两条路径共用，用 `turn|side` 幂等键防重复）。它一次完成：
   - 固化**本阶段起始持仓快照**（见 6.5）；
   - 算覆盖集 + 12.6f 同源取舍 + 空投/非战斗豁免；
   - 写一次 `hasTraceSupply` 并落 `cutSinceTurn`；
   - 存 `traceSettlement = { turn, side, byUnit, marked, cleared, sustained, assessments }`。
2. **另两条入口改为只读**：
   - `beginSupplyCheckNow` 读快照；只有快照里没有该单位（如阶段中新增的增援）才对该单位做一次定向判定并登记；
   - `planSupplyPhaseNow` 用快照的 `assessments` 与断补状态，**不再全场重算**；`applySupplyPhaseFeedingNow` 只按快照写标记。
3. **闸门**：`supplyJudgedThisPhase: Set<unitId>` + `traceSettledKey`。`markTraceSupply` 只接受两类定向写入：12.3a 拖取成功（该单位，12.6「可直接拖取」）与断补处置（该单位）。其余一律以快照为准。
4. **计数与写入对齐**：
   - `markTraceSupply` 返回旧值，结算器只在真实变化时累加 `marked / cleared`；日志与面板数字取结算器，不再取 `plan.outOfSupply.mark.length`（`SupplyPanel.vue` 约 1114–1115、`supply-phase.ts` 约 421）。

### 6.5 12.3b 与「消耗 SP 后持仓变化」的判定顺序

- **建议口径：本阶段判定一律用「进入补给阶段那一刻的持仓快照」；阶段内恢复/喂食/拖取/12.11a 花掉的 SP 不回改其他单位的断补标记。**
- 理由：
  1. 12.8a 明写标记保留到「下一个友方补给阶段重新判定」；阶段内因花钱改判等于同阶段多次判定；
  2. 12.10e-A 的「恢复优先于以 SP 代 trace」是一条**固定预算下的分配顺序**，不是反馈循环；按实时持仓会让结果依赖玩家操作顺序；
  3. 避免「先花光某站 ⇒ 别的单位突然断补」这类由操作顺序制造的结算。
- 例外（仍允许）：12.3a 直接拖取成功，对该单位自身写 `hasTraceSupply=true`（12.6 明写直接拖取可用于追溯接收），这属定向动作，不是全场重判。
- 实现：结算时用快照构造 trace facts（只影响「装载中 dump 用尽后消失」与 12.3b 的 HQ 投递资格）；**删掉** 13807 / 13832 两处重判。
- 既有用例影响：
  - 没有用例断言「花光 SP 会改判」；13807/13832/14688 三处删除预计不改任何现有断言。
  - **要改**：`tests/stores/supply-interaction-flow.test.ts` 427–452（它钉的正是「进入移动阶段自动重判」），改为断言「标记不变 + 突围候选按实时线变化」；`tests/stores/breakout-flow.test.ts` 51–53 的注释需同步。
  - **不变**：`supply-phase.test.ts:326`（`clear` 语义不变）；`supply-phase-feeding-flow.test.ts:55`（被喂单位本来就没被写过 false，保持 true）；`trace-firstturn-flow` / `extender-collapse-flow` / `40-phase-d-supply` 走手动 `evaluateTraceSupplyNow`，保留裁判入口即不受影响。
