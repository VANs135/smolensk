## 0. 目标与判据

**目标**：把「面板平铺、表单驱动」的操作台，改造成**地图优先、事件驱动**的正式界面：玩家在地图上完成
一切操作，右侧只读信息，任何需要结算的事件都在地图上生成**唯一一个**可拖动会话框。

**判据**（沿用「真正实现」四判据）：

| 判据       | 本方案的具体含义                                                                     |
| ---------- | ------------------------------------------------------------------------------------ |
| **可达**   | 每个规则动作都能从地图上点到（点堆叠 → 高亮候选 → 点目标），不靠侧栏表单             |
| **强制**   | 阶段隔离：非当前环节的动作为**不可点**（不是点了才报错）；不满足条件的候选**不高亮** |
| **留痕**   | 每次拒绝/落账都带规则号进日志并在**地图上就地**显示一次（ActionFeedback）            |
| **可玩通** | 从剧本选择到终局裁定，全程不用回侧栏表单即可打完一局（初设 → 各阶段 → 结算）         |

**明确不做**：不引入 `vue-router`（沿用现路由表）；不做多窗口并存（参考图 1 的教训）；
不把规则判断写进组件（架构门禁会红）。

### 2.3 渲染层次修正（用户 2026-09-16 #2 的两条）

**现状（`render/map-render.ts` 的绘制序）**：① 底图 → … → **⑤ 印刷永久工事** → ⑥ 格号 → ⑦ 高亮格 →
**⑧ 移动覆盖层（算子）**。⇒ **工事画在算子之下**，堆叠一压上去就看不见该格有工事。

**要改成（自下而上）**：… → ⑤ 底图要素 → ⑥ 格号 → ⑦ 高亮 → **⑧ 算子堆叠（含就地展开）** →
**⑨ 工事贴图**（压在最上层）→ **⑩ 单位状态贴图**（进击 / 战略 / 断补；在**该单位自己的图**之上）。

- **⑨ 的可见性处理**：工事贴图缩到 0.8 倍并放在格的**右上角内沿**（半透明），既不遮住堆叠印值，
  也不至于点不到堆叠；有工事的格在堆叠角标旁加一个「⛨」小字提示（图未就绪时的回退画法）。
- **⑩ 现状已正确**：`drawToken` 的第 ④ 步 `drawModeTextures` 已把三种贴图画在算子图之上，
  本次只需把它从「token 内部」提到独立的一层（⑩），以便就地展开的多枚算子各自贴自己的状态。
- 全部走 Canvas（不是 DOM），保持缩放时线宽/字号屏幕恒定（现有做法：除以 `scale`）。

### 4.2 地图优先的操作链（战斗 / 炮击 / 空军 / 补给统一）

> 用户 2026-09-16 澄清（#1）：**「拾取」不是把算子捡起来**，而是**在该格里把堆叠展开**，
> 让玩家一眼看清堆叠里有什么；此时**默认全选**，被选中的算子**高亮边框**，**再点该算子即取消选择**——
> **不需要到别的页面去取消**。交互必须**简洁可靠、能达成目的**。

```
点格子 ──► 【就地展开堆叠】（在该格内把每一枚摊开，一眼看全；不再只画顶牌）
   │         · 默认：整堆**全选**（多数动作是「整堆一起做」）⇒ 每枚描金色选中框
   │         · 点某一枚 = 取消/恢复它的选择（**就在地图上点，不去别的页面**）
   │         · 摊不开时（>4 枚）：2×2 + 角标「+n」，点角标换页（不弹新窗）
   │         · 收起：再点该格 / 点空白 / Esc（Esc 只收展开，**不清选择**）
   ▼
高亮候选目标格（可攻击 / 可炮击 / 可投送 / 航程内；引擎给的集合）
   │         （多格联合：点另一格已展开的堆叠，选择集合并到当前动作）
   ▼
点目标格 ──► 生成【唯一会话框】（§4.3）→ 逐步骤确认 → 结束即关闭
```

**展开的布局与命中**（写进 `render/` 的纯函数，便于单测）：

| 枚数 | 布局                                 | 命中              |
| ---- | ------------------------------------ | ----------------- |
| 1    | 原地（现状不变）                     | 该格              |
| 2    | 左右各内缩 0.25 格宽                 | 两个矩形          |
| 3–4  | 2×2 栅格（各 0.45 倍格宽）           | 四个矩形          |
| >4   | 2×2 + 右下角标「+n」；点角标增删一页 | 四矩形 + 角标矩形 |

- 展开态的算子仍**按格中心吸附**（不溢出到相邻格），保证「点相邻格 = 点相邻堆叠」不误触。
- **选择集就是后续动作的参与集合**：战斗/炮击/补给/移动共用同一套「展开 + 选择」，
  不存在「面板里再选一次」；这也让 §4.1 的「参与算子」判定只有一处。
- **可靠性的硬要求**：① 单击只做「展开/收起/切换选择」三件事，不引入双击/长按/右键语义；
  ② 任何被拒的操作都在**原地**给一行规则号提示（不弹窗、不离开地图）；
  ③ 会话结束、切方、换环节时**自动清空选择集**（避免残留导致下一步误操作）。

**苏德差异**（专规）：炮兵联合炮击**苏联须同格**、德国无此限制 ⇒ 拾取阶段的候选判定交给引擎
（`barrage-interaction` / `combat-interaction` 已有），组件只渲染引擎给的候选集合。

### 4.9 算子**选择界面**规格：算子图阵列（用户 2026-09-16）

> 用户原话：「各种算子选择界面最好把**当前可选择的算子图片**排列出来；如果页面太多，也可以在**合适的位置加下拉**

#### 4.9.1 统一组件 `game/CounterPicker.vue`

| 项            | 规格                                                                                                                                                                        |
| ------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 输入（props） | `candidates`：每项 = `{ unitId, images, side, face, loadedSpT?, spPoints?, nonLevel?, disabledReason?, groupKey }`（**全是引擎/数据给的只读投影**）                         |

#### 4.9.2 分组与「页面太多」时的下拉

- **分组键**（按使用场景给）：编队（「第 3 装甲师」）/ 盒（死亡堆 · 地图外盒 · 空军盒）/ 类型（地面 · 非战斗 · 飞机 · 卡车）/ 到货批次（回合）。
- **下拉位置**：放在**面板标题栏右端**（会话框标题、盒卡标题、决策队列标题），一个紧凑 `select`，选项 = 分组名（**极短**：编队号或盒名，不用长句）；默认选第一个非空分组。
- **组内不换页**：组内超过一屏时**组内滚动**（保持上下文），只有跨组才用下拉切换 —— 避免「翻页把当前选择翻丢」。

#### 4.9.3 文字纪律（用户明确要求）

算子上已经印了 A-AR-MA、模式、兵种、国籍与移动力类型，**不要重复**。只允许三类文字：

1. **环节提示**：一行，如「本环节：炮击（10.0）」——告诉玩家当前能干什么（这是用户点名的例外）；
2. **分组标题**：一行，如「第 3 装甲师（3 张）」「轴心地图外盒」；
3. **被拒原因**：**一行灰字**，含规则号，且**只在点击被禁项之后**出现（不是常驻说明）。

悬停提示（`title`）只给**规则号与最短名词**（如「14.7d 低空扫射」），不写整句解释；解释留给右侧只读栏或日志。

## 8. 门禁与验收

- 每片结束：`npm run check`（lint → format → typecheck → test → **arch**）全绿 + `npm run build` + 手工整局走查。
- **新增测试**（沿用现有风格）：
  - 可点性表（`allowedActions`）：每个环节允许/禁止各断言一次（规则号进断言名）；
  - 会话框单例：制造两个会话请求，断言只挂载一个（`sessionKind` 唯一）；
  - 决策队列：初设条目与 `pendingDecisions` 一一对应，落格后递减到 0；
  - 表条数据：CRT 行数与 `charts-crt.json` 一致（防手抄）。
- **门禁不可绕**：组件里出现规则号比较会红（`arch-scan`）；新增颜色必须先在 `tokens.css` 声明。

## 9. 风险与对策

| 风险                                                 | 对策                                                                                                               |
| ---------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| **追溯重判性能**（单次数十秒，已实测）               | 覆盖集缓存（P1-1）在 U1 之前/之内落地；否则不用补给的环节不做全场重判（现状即如此，UI 不得引入新触发点）           |

| **Canvas 与 DOM 混排**（鼠标穿透）                   | 地图只监听自己的 `pointer` 事件；DOM 浮层 `pointer-events: auto` 且在地图命中测试前被排除（`hitTestHex` 先判浮层） |

| **回归面**：现有 2768 用例里约 300 条是 store 级交互 | 重做**只动视图层**，store/engine 不动 ⇒ 用例应整体保持绿；若必须动 store，先补用例再改                             |
