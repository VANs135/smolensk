## 0. 纪律（与第二批同）

每个批次仍走**六步**，缺一步不算做完：

1. **先核原文**（`_ocs_v43_clean.txt` 通用规则 / `rules.json` 专规）——不凭记忆；
2. **先写/改测试**，带上**测法边界**注释（说清"这条测试问的是什么、不覆盖什么"）；
3. **改代码**；
4. `npm run check`（lint → format:check → typecheck → test → arch）**全绿** ＋ `npm run build` 通过；
5. 在 `docs/待改清单与修改方案.md` 追加 **§17.x 回执**（改了什么 / 怎么验的 / 如实边界 / 回滚点）；
6. 快照 `src` `docs` `scripts` `tests` → `backup/<日期>-<批次>-green/`。

环境纪律（本项目踩过的坑，务必照做）：**不是 git 仓库**（只能手工快照）；**不要跑 `scripts/sync-*.mjs` 去覆盖
`src/data/*.json`**（会毁手写数据）；控制台是 GBK ⇒ 中文一律写进 UTF-8 文件再用 Read 看；**绝不用 PowerShell
文本管道改源码**；批量改动写成 `backup/<批次>/audit-scripts/*.cjs` 再 `node` 跑（多行 `node -e` 会被 cmd 撕开
而**静默失败**）；串联命令只用 `&&`；并行 vitest 会 OOM ⇒ 一次只跑一个。

### B40 13.7a 追溯补给：**编队数据 + 同源接线**（A-1 + A-2）

**步骤**：

1. **数据段**：把源库 `units.json` 的 `formation`（131 条）导出进 `src/data/units-{axis,soviet}.json`；

2. **视图段**：`UnitRecordView`/`ConsoleUnit` 透出 `formation`（`toConsoleUnit`，`src/stores/workbench-model.ts:1425`

3. **接线段**：`refreshTraceSupply`（`src/stores/workbench.ts:8550`）按 `(side, formation)` 分组，对**每组 ≥2 个战斗单位**

## 5. 如实边界（本方案**没**覆盖的）

1. **B40 的数据段**要动 `src/data/*.json` 与 schema（严格模式），风险高于纯代码改动 ⇒ 该批应当**单独一轮**做，
   改完立刻快照；不得与其它批次混在一轮里。
2. **B46 只是"范围表"**，不是完成态：本方案没有、也不可能一次性完成全部规则的逐条对照；它给出的是**顺序与做法**。
3. **死导出扫描只覆盖 `src/engine/**`** 的导出与 `rules-constants.json` 的叶子键；`src/render`、`src/stores`、
   `src/components` 的零引用导出**尚未扫**（同一个脚本改一行即可扩展，见 B45 的 `--strict` 计划）。
4. 本方案的每一条**都尚未动手**（§0 的六步从 B40 开始执行）；清单本身按第二批的写法落在本节，便于逐批勾掉。
