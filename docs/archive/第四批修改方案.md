## 4. 建议顺序与理由

**A → B → C → E → D → F**。

- **A 与 B 是"可玩通"级别**（打不了仗 / 单位动不了），必须先做；A 放最前是因为它同时是用户最新备忘录的第一条，
  且批 C、D 的"单一对话框/候选过滤"都建在它的机制上。
- **C** 是"点进去一路自动"的体验，依赖 A 的环节入口（否则自动化无处挂）。
- **E** 与 **D** 是入口与版面的收口，不阻塞对局，可与 F 并行安排。
- **F** 是不影响可玩通的保真项（分界线画线与 9.x 对照），放最后但不省略：它决定"规则实现是否照原文"。

每批仍按既有六步走：**先读原文 → 先写用例（含测法边界注释）→ 改代码 → `npm run check` + `build` 全绿 →
回执（含如实边界）→ 快照**。
