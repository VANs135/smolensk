## 2. 发现

### P2-1 类型环（fragility，建议下批顺手做）

`workbench-core.ts` / `workbench-gates.ts` 反向 `import type { ConsolePhase, WorkbenchLogEntry, SettlementLock } from './workbench'`。当前**安全**（type-only 被擦除，已验证无运行时环），但一旦有人为了拿 `PHASE_LABELS` 改成值导入，立刻变成运行时环。

**改法**：把这 3 个类型移进 `workbench-model.ts`（它本来就是类型家），`workbench.ts` 侧保留 `export type { … } from './workbench-model'`，组件既有导入路径不动。约 30 行搬运、零行为变化。

### P2-2 facade 里留了两段长论据

`requireAction` 前的 BUG② 说明与 `refuseWhileSettling` 的拒绝理由，现在都悬在 3 行转发上，实现处也各有一份。**改法**：facade 只留一句指针（"判据唯一实现在 `workbench-gates.ts`"），避免以后改一处忘另一处。

### P2-3 `WorkbenchGates` 已装三类判据

准入（`actionAllowedNow`）／拒绝（`requireAction`）／结算锁（`refuseWhileSettling`）。三者同源（都回答"此刻能不能动"）但不同层；若 B8 的段推进判据也往里塞，建议那时拆出 `settling-gate.ts`。

### P2-4 `deps.log: WorkbenchCore['pushLog']` 类型耦合

gates 只想"写一条警告"，却绑定了 core 的成员类型。**改法**：窄签名 `(kind, text, rule?) => void`。

### P3

- **P3-1** 公开面测试只冻结键名、不冻结键的类型；类型退化只能靠 typecheck，组件调用处的签名变更无快照。
- **P3-2** `recordLogHeader` 仍直写 `log`，未走 core 的日志服务（要搬得注入 `seed / RNG_ALGORITHM / DATA_VERSION`，收益小，建议与 E4 文案一起做）。
- **P3-3** gates 的 deps 已 11 项；仍在 `AirMissionPorts`（17 项）标尺内，但已提示"闸门与段状态缠得紧"。
