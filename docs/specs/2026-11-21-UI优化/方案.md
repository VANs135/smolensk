## 0. 结论先行

把 53 个组件（22,669 行）+ 5 个视图（3,553 行），合计 58 个 `.vue`、26,222 行，和 3 份样式表过了一遍，按 WCAG 实际算了一遍色度，结论是：**现有 5 处硬伤不是 5 个孤立 bug，而是 4 个系统性根因的可见症状**；只逐个修症状，下一批面板还会复发。

| 根因                          | 事实                                                                                                                                                                                                                                                                                                                             | 后果                                                                             |
| ----------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------- |
| **R1 主题作用域靠手抄**       | 同一套"外壳令牌→command 令牌"的映射被抄了 **4 份**：`base.css .theme-command`(21 项)、`GameTableView .gt`(20 项)、`ConsensusChecklist`(6 项)、`android.css`(ops/glass 两组)。覆盖不一致：`.gt` 漏 `--color-border`（深色下 1.29:1，2 处引用）；Consensus 把 `--color-danger` 映射成 `--color-command-amber`（语义错位）          | 对比度、亮块类缺陷反复出现，且只在特定作用域暴露                                 |
| **R2 语义色被当实心底的前景** | 浅色下 `teal on accent-solid` **1.15**、`amber` **1.34**、`danger` **1.15**；深色下反过来 `on-accent on teal` **1.40**、`on-accent on danger` **1.62**                                                                                                                                                                           | 徽标、按钮文字"看得见但读不出"；现测 7 处低于 4.5:1                              |
| **R3 密度没有标尺**           | `line-height` 出现 **16 种**取值（1 / 1.1 / 1.2 / 1.25 / 1.35 / 1.4 / 1.45 / 1.5 / 1.6 / 1.7 / 10px / 12px / 14px / 18px / var）；`gap` 仍有 19 处越出 4 阶（2px/4px/6px/10px）；`font-size:10px` **9 处**，其中 `.picker__action` 是**可点按钮**；断点 **10 种宽度**（480–1080，含根壳 `App.vue` 的 620）散在 27 处 `@media` 里 | 面板里"看着能点但字太小"、行高忽松忽紧、不同宽度下布局行为不可预期               |
| **R4 反馈层既遮挡又吃点击**   | `ToastHost` 固定右上 `z=300` 且子项 `pointer-events:auto`，`Teleport` 到 body ⇒ 显示期间点「存档/读档」命中的是 toast；`queue__hint` 仍 `nowrap + overflow:hidden`                                                                                                                                                               | 表现为"按钮点了没反应""提示缺半句"，玩家会当成 bug                               |
| **R5 回归只守源码形态**       | `tests/render/ui-ux-theme-light.test.ts` 全是 `toContain` 字符串断言；仓库内**没有** `scripts/ui-regression.mjs`，没有色度/几何判据                                                                                                                                                                                              | 改一个令牌不会红，改坏一处对比度也不会红 —— 这是所有 UI 缺陷能反复回流的根本原因 |

**建议按 4 批推进**（见 §5）：A 令牌与主题收口 → B 遮挡/裁字/内部键 → C 密度与排版标尺 → D 可达性与回归入库。A、B 两批合起来就能把现有 5 硬伤 + 新增 4 处收干净；C 是观感升级、风险最高，必须截图矩阵兜底。

## 3. 根因展开

**R1（主题作用域）** 是龙头。现在"把页面色换成外壳色"这件事写成了 4 份手抄清单，任何一份漏项都只在特定页面暴露：`FlowStrip` 落在 `.gt`，于是读到 `accent=teal`、`accent-2=accent-solid`；`BaseTag` 在页面作用域用的是 `:root` 原值；`ConsensusChecklist` 又自建一套。**同一语义在两个作用域有两套色值**，是这个项目所有对比度问题的共同上游。

**R2（配对规则）** 是 R1 的下游：因为 `accent` 在不同作用域指向不同色（页面=品牌红、对局台=青），"用 accent 当实心强调底的前景"就必然有一半场景失效。修单个徽标不改规则，等于留一个持续生成 bug 的模具。

**R3（密度）** 不是审美问题而是**操作准确性问题**：这是一款靠点格子、点算子的兵棋，10px 的可点按钮和忽高忽低的行高直接抬高误点率；10 种断点让"1024 下抽屉怎么摆"没有唯一答案。

**R4（反馈层）** 属于"看得见却点不到"，比"看不清"更伤 —— 玩家会归因为程序坏了。

**R5（回归）** 决定上面四条能不能不复流：现有守卫是字符串断言，改色值不会红；`ui-regression.mjs` 至今只在会话目录里，没入库。

## 4. 优化方案

### A. 主题与令牌（治本，先做）

**A1 收敛成"一个作用域、一份清单"。**
把 `--color-*` → `--color-command-*` 的映射从 4 处手抄收成 1 处（新增 `.theme-shell` 类，或在构建期由一张表生成），`base.css .theme-command`、`GameTableView .gt`、`ConsensusChecklist` 全部改为挂同一个类；`android.css` 的 ops/glass 保留为皮肤层，但同样只允许引用同一张表。
同时补齐 **`--color-border`**（`.gt` 漏项，深色 1.29）与 `ConsensusChecklist` 的 `danger` 错映射。

> 判据：仓内 `.gt` / `.theme-command` / `.consensus--formal` 的令牌赋值条目数量一致；`grep` 不再出现第二份手写映射。

**A2 把"语义色不得压实心底"变成可计算的门禁。**
新增 `tests/styles/tokens-contrast.test.ts`：解析 `tokens.css` 两套皮肤，对**每一对**（前景令牌, 背景令牌）算 WCAG 比值，凡低于 4.5 且属于"正文/小字"用途一律失败；并显式锁死三条规则：

1. 任何 `*-accent-solid` 作背景，前景只能是 `on-accent` 家族；
2. 语义色（teal/amber/danger/info/success）**不得**作实心底上的文字色；
3. `accent` on `accent-2` 这种"双强调"配对禁止。

> 这是取代"改一个颜色"的治本动作，也是唯一能防住下一批徽标的机制。

**A3 修掉 3 处已实测的配对，并按作用域分别验收。**

| 处                  | 改法方向                                             | 验收值                                                                            |
| ------------------- | ---------------------------------------------------- | --------------------------------------------------------------------------------- |
| `FlowStrip:598`     | 前景改 `on-accent`（或换底）                         | 浅色 ≥ 7.5、深色 ≥ 6.5                                                            |
| `TutorialGuide:279` | 深色下徽标底改 `accent-solid` 或前景改深色           | 深色 ≥ 6.5                                                                        |
| `BaseTag:96`        | `warning` 前景加深 / 底提亮                          | 浅色 ≥ 4.5                                                                        |
| `BaseButton:146`    | 深色 `danger` 实心底改深红（与 `danger` 文字色分工） | 深色 ≥ 4.5；2 处在用（`AirPanel` 裁判覆写、`WorkbenchView` 移除），须与 A3 同批修 |

**A4 去掉无条件 `color-scheme: dark`。**
`ScenarioSetupView:351`、`OverstackPanel:95`、`SupplyPhasePanel:304` 改为随 `data-theme` 走（或在浅色下删掉）。这三处现在是"浅底 + 深色原生控件"的错配。

> 判据：浅色主题下这三个容器滚动条为浅色。

### B. 遮挡、裁字、内部键（玩家感知最强）

**B1 toast 换锚点。**
`ToastHost` 在 body 上，`.gt` 上设变量继承不到（已证）。两个可行解二选一：① 常驻**左下**（与任何顶栏不相交）；② 保留右上，但由视图层在 `body` 上设 `--toast-top`。
**同时**要把"toast 显示期间按钮仍可点"作为判据 —— 因为 `.toast-host > *` 是 `pointer-events:auto`，只挪位置不解决问题，得让 toast 区域不覆盖可点控件（左下角只有工具栏与"格 —"读数）。

**B2 `queue__hint` 允许换行**，并把"任何 `overflow:hidden` 且 `scrollWidth > clientWidth` 的叶子文本"列为全局 FAIL。

**B3 战报内部键。**
`SettlementLogPanel:237` **和** `FlowStrip:424` 两处一起走 `SETTLEMENT_ACTION_LABELS`（66 键），未知键显示"未分类"，不留"原样回显"的后门。

**B4 深色地图外围底板。**
`map-render.ts` 导出 `DARK_BOARD_COLOR = '#101820'` 并加守卫测试锁与 `--color-command-bg` 一致；`MapCanvas:526` 在桌面深色也传。**纸面不压暗**。

**B5 10px 交互文字清零。**
`.picker__action`（`CounterPicker:365`）是可点按钮、10px，触摸端不放大；其余 8 处 10px 用于角标可保留，但**交互控件文字下限设 12px**。

### C. 密度与排版标尺（观感升级，风险最高）

**C1 行高收成 6 档**（1 / 1.25 / 1.35 / 1.5 / 1.75 / px 仅用于等宽数字行），删掉 16 种散值。
**C2 间距回 4 阶**：19 处越阶的 `gap` 收进 `--space-1/2/3`。
**C3 新增"紧凑"档（可选）**：给面板加 `--density`（舒适/紧凑）两套 `--control-height` 与行高，默认舒适；兵棋玩家普遍想要"一屏多看点"。**这是产品级选择，需拍板**。
**C4 断点收敛为 3 档**：`≥1200`（宽）、`900–1199`（标准）、`<900`（窄/竖屏），现有的 1024/1080、840/900 合并；`(pointer:coarse)` 单独成档。
**C5 棋盘叠加层可读性**（只调 UI 叠加，不动地图配色）：算子底、选中高亮、ZOC、可达区在**深色底**与**浅色地图纸面**两种底上的对比分别实测；`token-layer.ts` 的 `select #e0b64a` 在米白纸面上偏弱，建议加描边而不是换色。

### D. 可达性与回归（把上面的成果锁住）

**D1 `--focus-ring` 接线**：至少覆盖 `BaseButton`、抽屉开关、队列选项；统一 `:focus-visible` 与 `--focus-ring` 二者之一，别留两套。
**D2 键盘可达**：389 个点击面 / 14 个键盘处理，至少把"队列选项、抽屉、关闭按钮"补 `Enter/Space`；`title=` 的 119 处说明逐步换成可聚焦的 `?` 提示（现有 P2-4 就是这个方向）。
**D3 `ui-regression.mjs` 入库**：放 `scripts/`，本地解析 `playwright-core`（不下载浏览器，用本机 Edge）。
**D4 判据从 6 条扩到 10 条**：原 6 条 +「跨 2 皮肤 × 4 作用域的全量对比度扫描」+「未重绑容器（如 `.consensus--formal`）在深色下的低对比/浅底」+「toast 期间按钮可点」+「10px 交互文字为 0」。
**D5 截图矩阵**：1600 / 1280 / 1024 × 浅/深 × 首页/剧本/初设/棋桌/四抽屉/战报；安卓 916×412 单独一格。

## 7. 不做什么 / 需要拍板

**不做**：

- 不重画地图、不改 `MAP_PALETTE`/`token-layer` 的配色语义（只调 UI 叠加的描边与对比）；
- 不改任何规则数值、文案语义、store 逻辑（本文全部落在 `src/styles`、`src/components`、`src/render` 的呈现层）；
- 不做响应式重写，只做断点收敛；
- 不为"好看"替换字体族（Outfit/InstrumentSans/IBMPlexMono 已有）。

**需要拍板（3 个）**：

1. **要不要"紧凑/舒适"密度档**（C3）？—— 影响一屏信息量，属产品选择，不是纯技术决定。
2. **`android.css` 的 ops/glass 两套皮肤是否拆成独立皮肤层**？—— 现在它与 `tokens` 并行，收编工程量大（726 条声明）。
3. **是否把 `playwright-core` 作为 devDependency 入库**（约 5MB，不含浏览器）？—— 入库后 `ui-regression.mjs` 才能成为长期资产。
