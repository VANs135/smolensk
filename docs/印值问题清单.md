## 0. 怎么用

| 等级  | 含义                                                     | 处置                 |
| ----- | -------------------------------------------------------- | -------------------- |
| **S** | 有**素材图证**（放大读图）或**库内硬矛盾**，可直接判对错 | 可直接开改（§1、§2） |
| A     | 库内矛盾（近似同图/同族）但**未看图**                    | 改前先读图确认       |

## 4. B 级：数据卫生（不改也玩得下去，但会误导复核）

1. **`ocr` 证据块与现印值不一致：123 个面**。
   例：苏步兵师正面 `ocr.A=2` 而现印值 `12-2-2`（OCR 把多位数切成了一位）；
   编内卡车 `ocr` 读到 `A:1,AR:7,MA:45` 而现印值是 `--45`（运输单位无战斗值）。
   ⇒ 这些块的**证据价值很低**（OCR 管线对多位数分割不可靠）；重读全库时应一并**标注/刷新**，
   否则后来者会拿它当"权威读数"去推翻正确的现印值。
2. **源库 `images.*_paths` 陈旧：56 个面** 指到不存在的子目录（如 `…\独立装甲\Ru_43_Tk_Bn_F.png`，
   实际在 `…\独立装甲\营\`）。`sync-counters` 按**文件名**解析，产物不受影响；但该字段本身要修。
3. **硬不变量**：判定式写成 `战斗 A ≥ 移动 A`（炮兵两面向同一弹幕值，A 相等是合法形态）后，
   全库 **0 违反**。当前 `870 面` 里含 0 的有 **81 面**，其中绝大多数合法：
   HQ 正面 `5-0-0`（带括号不可攻击）、补员 `0-0-5 / 0-0-10`、各单位 AR=0（无装甲等级）、
   铁路修理 `(1)-0-3`。**唯一反常的 4 条「师级移动面 A=0」已在 §1.2 改正为 6-2-4**。
4. **字符串型印值：244 处 → 仍剩 238 处**（`"A": "1"` 这类写法，来自 2026-09-11「剧本数值回填」批次）。
   模式层 schema 要求 `z.number()`（sync 会强转，故不影响运行），但源库字段类型不统一；
   本次触及的字段已规范成数值型，其余待同一批清理（多为 HQ 背面与坦克师）。
5. **`verified_by` 多为 `auto`**：435 条里 112 条 `verified`、323 条 `valued`。§1.2 改过的条目
   建议在下次批次里一并标 `verified`（现在是「有图证」的了）。
