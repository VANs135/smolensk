## 0. 三分钟读懂

### 0.1 一句话

把 OCS《斯摩棱斯克》的掷骰、查表、补给追溯、状态记录交给引擎，玩家只做决策；程序是**纯静态前端 + 可选壳**，没有后端、没有网络请求。

### 0.2 数据怎么流

```
规则书原文 / 算子图 / 地图扫描 / 图表页
        │  scripts/sync-*.mjs（构建期，可重跑、幂等）
        ▼
src/data/*.json  ──Zod 校验──▶  深度冻结  ──▶  src/engine/（纯函数规则内核）
                                                    │  状态进 / 状态出
                                                    ▼
                                            src/stores/（Pinia 编排、撤销、日志）
                                                    │  只读投影
                                                    ▼
                                    src/components/ + src/views/（Vue，只显示与收集输入）
```

### 0.3 五条铁律（违反即返工）

| #   | 铁律             | 具体含义                                                                                  |
| --- | ---------------- | ----------------------------------------------------------------------------------------- |
| 1   | **原文优先**     | 先读规则书条款，再改代码；原文能确证的不挂审批，原文缺失/矛盾才记「待裁定」并写清缺哪一句 |
| 2   | **规则只在引擎** | `src/engine/` 之外不判规则、不重算数值；组件里出现规则号比较会被架构扫描拦下              |
| 3   | **随机可重放**   | 禁用 `Math.random`，一律走 `src/engine/rng.ts`；种子入存档，固定种子能复现整局            |
| 4   | **数值单源**     | 数值只来自 `src/data/*.json` 与 `engine/rules/*` 常量；组件里不写规则数字字面量           |
| 5   | **一改一提交**   | 代码/文档/测试/数据同批提交，门禁全绿后 `commit` + `push`；不攒、不只提交不推送           |

### 0.4 第一条命令

```bash
cd /d/OCS/smolensk
npm ci
npm run dev     # http://127.0.0.1:5173
```

## 1. 项目速览

### 1.1 是什么 / 不是什么

| 是                                                       | 不是                       |

## 3. 架构地图

### 3.1 分层与依赖方向

```
components / views
        │  只读投影 + 收集输入
        ▼
stores（Pinia：编排、撤销、日志、投影）
        │  调用纯函数
        ▼
engine（纯 TS：规则、状态机、表查询）
        ▲
        │  只读
render（Canvas：绘制与命中，不改状态）
```

| 层                     | 允许                                      | 禁止                                                           |
| ---------------------- | ----------------------------------------- | -------------------------------------------------------------- |
| `engine/`              | 纯函数、类型、常量、查表                  | Vue / Pinia / DOM / Canvas / 网络 / `Math.random` / 取系统时间 |
| `data/`                | JSON、Zod schema、加载管线                | 业务逻辑、格式化、组件                                         |
| `render/`              | 绘制、坐标换算、命中检测                  | 规则判断、状态写入                                             |
| `stores/`              | 编排、投影、持久化                        | 规则计算、Canvas 调用、数据解析                                |
| `components/` `views/` | 显示、收集输入、调用 store 动作           | 规则判断、直接改引擎状态、规则数字字面量                       |
| `shared/`              | id / format / assert / math / is 等纯工具 | 任何与规则有关的逻辑                                           |

依赖只能自上而下。`engine/` 反向 import store 或组件 = 架构事故。

### 3.2 `src/engine/` 内部

| 区域       | 职责                                                   | 代表文件                                                                                        |
| ---------- | ------------------------------------------------------ | ----------------------------------------------------------------------------------------------- |
| 会话与流程 | 19 步 SOP、待答问题、阶段推进、日志                    | `session.ts`、`session-flow.ts`、`session-flow-steps.ts`、`turn-driver.ts`、`game-lifecycle.ts` |
| 状态与结果 | 状态类型、统一成败返回、规则错误文案                   | `state-types.ts`、`result-types.ts`、`rules/rule-error-text.ts`                                 |
| 规则模块   | 按章/机制拆分的纯函数                                  | `rules/combat.ts`、`rules/supply.ts`、`rules/move.ts`、`rules/air.ts`…                          |
| 交互状态机 | 一次操作的逐步推进（战斗九步、轰炸、补给、空军、移动） | `rules/*-interaction.ts`、`rules/engagement-progress.ts`                                        |
| 查表       | CRT、轰炸、空战、防空、奇袭、消耗、夺取、补员          | `tables/*.ts`                                                                                   |
| 几何与随机 | 六角格坐标、邻接、距离；可重放骰流                     | `hex-geometry.ts`、`rng.ts`                                                                     |
| 存档       | 序列化、四层版本校验、盘面快照                         | `save-file.ts`、`board-snapshot.ts`、`board-validation.ts`                                      |
| 派生与投影 | 规则派生量、流程条只读模型                             | `derivation.ts`、`derivation-builders.ts`、`flow-model.ts`                                      |

### 3.3 `src/stores/` 的两类 store

| 类型                | 例子                                                                                                                                         | 职责                                         |
| ------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------- |
| **盘面主 store**    | `workbench.ts`                                                                                                                               | 对局状态、交互提交入口、撤销封印、日志、快照 |
| **领域/流程 store** | `session.ts`、`setup.ts`、`containers.ts`、`hotseat.ts`、`map-view.ts`、`session-steps.ts`、`recorder.ts`、`tutorial.ts`、`legal-actions.ts` | 各自领域的编排与投影，不复制规则             |

`workbench-model.ts` 只做**展示模型与格式化**（如 `formatHexPath`），不放判定。

### 3.4 一次点击的完整链路（以「移动一格」为例）

```
MapCanvas 指针事件
  → stores/map-view.ts 命中格/算子
  → workbench.selectUnit / beginMove
  → engine/rules/move.ts#computeReachableHexes（纯函数：MP、ZOC、地形、模式、5.7g）
  → 玩家点目标格 → workbench.finishMove
  → 引擎校验（消耗、堆叠、禁入、结束位置）→ 成功则写 units/records/log
  → session-flow 推进环节/段（必要时产生待答问题）
  → flow-model 生成展示模型 → FlowStrip / 面板重绘
  → render/token-layer 按新状态重画（视口裁剪 cullOverlay）
```

调试一条操作时，按这条链路**逐段打点**，不要从 UI 直接猜引擎。

### 3.5 状态所有权（唯一事实源）

| 事实                           | 唯一存放处                        | 说明                                   |
| ------------------------------ | --------------------------------- | -------------------------------------- |
| 单位位置、模式、军力、DG、燃料 | `units`                           | 补员算子是**投影**，事实仍在 `units`   |
| 补给点、运输点、补给站         | `spDumps` / 相关账本              | 支付走台账，读 `replHoldings` 只是投影 |
| 回合、阶段、行动方、先手       | `records`（会话记录轨）           | 界面兜底阶段不参与生命周期判定         |
| 骰流                           | `rng`（seed + drawCount + state） | 存档必须带，读档校验算法与计数         |
| 审计日志                       | `session.log`                     | 只追加事实，不写规则推断               |
| 视觉状态（选中、悬浮、缩放）   | `ui` / `map-view`                 | 不进存档                               |

**原则**：能由事实算出来的，不要再存一份；必须缓存的，标明「投影」并给出重建路径。

## 4. 回合与阶段机

### 4.1 2.2 流程表的 19 步

`engine/session-flow-steps.ts#SOP_STEPS` 是**抄自流程表**的 19 步（Pre-Turn 2 步 + 先手方 A–H 8 步 + 后手方 A–H 8 步 + Turn End 1 步），每步带 `rule` 与 `driver`：

| driver      | 含义                                   |
| ----------- | -------------------------------------- |
| `automatic` | 引擎自动完成（如天气判定）             |
| `question`  | 必须由玩家作答（如先手选择、共识开关） |
| `player`    | 玩家在本段执行操作，完成后手动推进     |

`GamePhase` 的 10 个值：`preTurn`、`aircraftRefit`、`reinforcement`、`movement`、`supply`、`reaction`、`combat`、`exploitation`、`cleanUp`、`turnEnd`。段内还有「环节」（`rules/sop-segments.ts`），例如移动段 = 突围 / 模式与移动 / 轰炸（仅空海）。

### 4.2 会话（Session）是唯一的流程权威

- 会话持有 `status`（`awaiting` 时**包含待答问题**）、`records`、`log`。
- 读档后若 `awaiting`，必须停在同一个问题等作答，**不能自动猜答案**。
- 阶段生命周期只看记录轨（`game-lifecycle.ts#phaseTransition`），不看 UI 为显示补的兜底值。

### 4.3 交互状态机

一次复杂操作（战斗、轰炸、补给、空军、移动）由 `engine/rules/*-interaction.ts` 的**纯状态机**推进：收「当前交互状态 + 输入」→ 返回「新状态 + 结果/拒绝原因」。store 只做三件事：保存交互状态、把 UI 输入翻译成引擎参数、把结果写进日志/盘面。

**新增交互时照此办**：引擎状态机 + 同名测试 + store 接线 + 面板。不要在 `.vue` 里写步骤判断。

| 管线   | `index.ts`、`pipeline.ts`、`freeze.ts`、`version.ts`、`errors.ts` + `schema/*.schema.ts` | 唯一加载入口、校验、冻结、版本、报错        |

### 5.2 加载管线（`src/data/pipeline.ts`）

```
import raw JSON
  → 校验 meta.version 与 DATA_VERSION 一致（不符即 DataError）
  → Zod schema 解析（失败列出「字段路径: 原因」）
  → deepFreeze 递归冻结
  → 导出 DeepReadonly<T>
```

引擎拿到的是**只读**数据；运行时改写会直接抛 `TypeError`。类型由 schema 推导，不手写第二份接口。

### 5.3 权威源与生成物

多数 `src/data/*.json` 是**生成物**：权威源在 `/d/OCS/OCS_EASTERN`（或素材库），由 `scripts/sync-*.mjs` 生成。规则：

1. **先改权威源，再跑同步脚本**；直接改 `src/data` 会在下次同步时被覆盖。
2. 同步脚本必须**幂等**：连跑两次结果一致。
3. 生成物与脚本同批提交；`tests/data/*` 与 `tests/scripts/*` 守住契约。
4. 例外：少量手工维护的常量/配置（如 `rules-constants.json`）按注释说明为准。

### 5.4 改数值 SOP

1. 查 [`docs/数值修改指南.md`](数值修改指南.md) 确认字段与联动。
2. 改权威源（或确认该文件为手工维护）。
3. 跑对应 `scripts/sync-*.mjs`。
4. 更新测试里写死的样例值（`tests/data/units.test.ts` 等）。
5. `npm run check`。
6. 浏览器里重摆子目检。

### 5.5 改字段结构 SOP（破坏性变更）

```
① src/data/schema/*.schema.ts 改契约
② 所有相关 JSON 加/改字段
③ src/data/version.ts#DATA_VERSION 递增
④ 所有 JSON 的 meta.version 同步递增
⑤ 改引擎/测试中的读取点
⑥ tests/data/* 补用例（缺字段必须报错到字段路径）
```

漏掉 ③④ 会让旧文件静默通过校验；漏掉 ① 会让类型与运行时脱节。

## 6. 规则改动 SOP（本项目最重要的一节）

### 6.1 先读原文，再动代码

| 材料               | 位置                                                                   | 用途                             |
| ------------------ | ---------------------------------------------------------------------- | -------------------------------- |
| OCS 通规 v4.3 全文 | `/d/OCS/OCS_TXT/_ocs_v43_clean.txt`                                    | 条款原文、编号、例外             |
| SOP 流程表         | `/d/OCS/OCS_TXT/_ocs_sop_clean.txt`                                    | 2.2 段与环节                     |
| 专规分界线摘录     | [`2026-11-09-专规分界线原文摘录.md`](2026-11-09-专规分界线原文摘录.md) | 通规/专规边界                    |
| 剧本专规生效矩阵   | [`2026-11-05-剧本专规生效矩阵.md`](2026-11-05-剧本专规生效矩阵.md)     | 哪些专规在本剧本生效             |
| 规则技能摘要       | `/d/OCS/skills/ocs-rules-v43/`                                         | **只作心智模型，不能当原文引用** |

`skills/ocs-rules-v43/chapters/*.md` 是摘要，可能省略例外；**改代码的依据必须是全文条款**。

### 6.2 六步法

```
① 定位条款：规则号 + 原句 + 例外（把原句抄进方案/提交信息）
② 找落点：程序目录与清单 §0「我要做什么 → 改哪里」
③ 改引擎：纯函数，函数头注释写条款号与依据；不碰 UI
④ 补用例：测试名带规则号，覆盖正例 + 边界 + 拒绝原因
⑤ 过门禁：npm run check（五关）+ 必要时 build
⑥ 提交推送：代码/测试/文档/回执同一 commit，push 到 origin/main
```

### 6.3 写法约定

- **规则号落字符串**：注释、返回值、测试名都写 `'9.5'`、`'12.8e'`、`'专规 2.4'`，便于反查。
- **统一返回**：用 `result-types.ts` 的 `succeed/fail`，拒绝要带 `rule` 与可读原因，不要抛裸 `Error` 做业务分支。
- **保守取值**：原文没明说的效果**不施加**；在注释与回执里写「为什么这样取」。拿不准进「待裁定」，不要用低优先级材料去圆高优先级原文。
- **不改数据口径**：数值来自 `src/data`；引擎里只放派生公式与常量引用。
- **时间与随机**：不取系统时间（时间入参），不 `Math.random`（走 `rng.ts`）。

### 6.4 一次改动的样子（示意）

```ts
/**
 * 12.8e 断补单位的战斗补给：不得使用部队储备降级（原文：...）
 * 依据：_ocs_v43_clean.txt 12.8e；专规 3.2 未改写本条。
 */
export function combatSupplyFor(unit: UnitView): RuleOutcome<number> {
  if (unit.outOfSupply && unit.internalStocks !== 'full') {
    return fail('12.8e', '断补单位不得以部队储备替代战斗补给')
  }
  // ...
  return succeed(cost)
}
```

配套用例：

```ts
it('12.8e 断补单位不得用部队储备降级', () => {
  const out = combatSupplyFor(unit({ outOfSupply: true, internalStocks: 'low' }))
  expect(out.ok).toBe(false)
  expect(out.rule).toBe('12.8e')
})
```

### 7.3 跑测试

```bash
# 单个文件（最快，改规则时先跑这个）
npx vitest run tests/engine/battle.test.ts

# 一个目录
npx vitest run tests/engine

# 全量（串行，避免 worker 启动超时）
npx vitest run --no-file-parallelism

# 监听
npm run test:watch
```

**耗时预期**：全量一轮约 **1 小时量级**（2026-11-18 实测 65 分钟，625 文件 / 约 6 千用例；大头是 `tests/flows/ai-selfplay.test.ts` 的多剧本对打）。日常只跑改动相关子集 + 提交前跑全量。

**并行坑**：默认并行模式偶发 worker 启动超时（不是用例失败）；全量一律加 `--no-file-parallelism`，不要误判为代码坏了。

**已知红灯（不是你的改动弄坏的）**：`tests/flows/ai-selfplay.test.ts`「剧本 1 完整档八回合」在 `preTurn` 出现白名单外拒绝
`unknown｜fuelPay:arr-…｜提交被拒`。用 `git stash` 清空工作区后同样红 ⇒ 属既有失败；`test` / `test:fast` / `check` / CI 都已排除该文件。
**不要**为了让「全绿」去放宽它的白名单——那会把真实的付款链路回归一起盖掉。该文件单轮 4–5 分钟，除明确要求外不要跑。

### 7.4 固定种子与夹具

- 测试新局种子统一用 `engine/rng.ts#TEST_FIXED_SEED`，保证骰序不漂移。
- `tests/flows/*-harness.ts`、`tests/regression/regression-harness.ts` 提供开局/推进/快照工具；新流程用例优先复用，不要另起一套。
- 整局回归基线更新是**显式动作**：先确认差异来自预期改动，再改基线，并在提交信息里说明。

## 8. 门禁

### 8.1 一条命令跑完门禁

```bash
npm run check
# = eslint .                          （代码规范）
# → prettier --check .                （格式）
# → vue-tsc --noEmit                  （类型）
# → audit:ports                       （端口/启动期依赖方向）
# → audit:clauses / audit:error-text  （条款号与失败码文案真实性）
# → tdz                               （模块顶层暂时性死区）
# → gen:counters --check              （算子数据产物与权威源一致）
# → vitest run（test:fast：排除 AI 对打）
# → node scripts/check-arch.mjs       （架构扫描）
```

`npm run check:all` 是同一串、只把 `test:fast` 换成含 AI 对打的 `test`——**当前有既有红灯（见 §7.3）**，日常不要用它判断「我改坏了没有」。

CI 在 `.github/workflows/check.yml`：push 与 PR 跑**同一条** `npm run check`（windows-latest 与 ubuntu-latest 两路矩阵 + Node 22），于是「本地绿但忘了跑」不再能带进分支。

**Linux 口径**：两路跑同一条命令、同一批用例，不因平台删步骤。Linux 上唯一踩过的坑是 `package.json` 曾把 `@rolldown/binding-win32-x64-msvc` 写成直依赖，导致 `npm ci` 直接 `EBADPLATFORM`；rolldown 已自带各平台 `optionalDependencies`，该条已删（2026-11-25）。删后实测：Linux `npm ci` 42 s、`npm run build` 32 s、`tests/engine` 2176 例全过；`gen:counters --check` 只看入库产物，Linux 上也过。素材库那批用例在 Linux 上按上一条跳过。

**本地还有一道**：`.git/hooks/pre-push` 直接跑同一条 `npm run check`（逻辑在 `scripts/pre-push-check.mjs`），红了就不推。钩子由 `scripts/install-hooks.mjs` 生成，`npm install` 的 `prepare` 会自动装；换机器或新克隆后手跑 `npm run hooks:install` 即可。急推绕过：`SKIP_PRE_PUSH_CHECK=1 git push`（或 `git push --no-verify`），别把它当常规做法。

**并行度口径**：`vite.config.ts` 的 `test.maxWorkers` 在 CI 上固定 4，本地交给 Vitest（本机 20 线程拉满时偶发单例 5s 超时，两次红在两个不同的 seed-search 用例、单文件复跑均过）。要按 CI 的并行度在本地复现：`VITEST_MAX_WORKERS=4 npm run check`。

**素材库与 CI**：`D:\OCS\OCS斯摩棱斯克素材`（原始扫描图、工程数据库）**不入库**，CI 的 runner 上没有。拿素材库当对照物的用例（源库 ↔ 产物、源图 ↔ 声明尺寸）按 `tests/shared/source-library.ts` 的 `sourceLibraryAvailable` 跳过（报告里显示 skipped），不当作失败；本机/发版机上素材库在位时照旧逐条核对，缺项仍然红。素材库换了位置就设 `OCS_SOURCE_DIR`。同理，`sync-counters` 的「产物一致性」要枚举源库，源库不在位时也跳过。

外加构建验证：

```bash
npm run build     # 不要用 `| grep` 接管道，见 §12
```

### 8.2 架构扫描查什么

`scripts/arch-scan.mjs` 把三类「编译能过、测试不红」的退化变成红灯：

| 扫描             | 拦什么                                                          | 为什么危险                                    |
| ---------------- | --------------------------------------------------------------- | --------------------------------------------- |
| `ruleLiteral`    | 组件/视图里比较规则号（`=== '9.5a'`、`case '6.1'`、规则号数组） | 规则判断跑到视图层，改规则时无人知道          |
| `cssVariable`    | 使用了未定义的 `var(--x)`                                       | 浏览器**静默忽略**，边框/底色不生效，肉眼难查 |
| `zeroCallExport` | 全树只出现一次的导出                                            | 「已实现但没人调用」的假象                    |
| `staleWhitelist` | 白名单里已接线的旧条目                                          | 白名单不随接线收敛，逐渐失效                  |

零调用白名单在 `scripts/arch-scan.mjs#ZERO_CALL_WHITELIST`：旧账不红，**新增**零调用导出会红。接线完成后要删掉对应白名单行。

### 8.3 常见红灯处理

| 报错               | 原因               | 处理                                      |
| ------------------ | ------------------ | ----------------------------------------- |
| `ruleLiteral`      | 组件里写了规则判断 | 把判定移进 `engine/`，组件只接收结果/文案 |
| `cssVariable`      | 变量名拼错或未定义 | 在 `tokens.css` 定义，或改用已有令牌      |
| `zeroCallExport`   | 新导出没人用       | 接线；确实为公开 API 则加白名单并注释原因 |
| `staleWhitelist`   | 白名单过期         | 删除该行                                  |
| `vue-tsc` 报 `any` | 违反 strict        | 用 zod 推导类型或显式联合，不要 `as any`  |
| prettier 失败      | 格式               | `npm run format` 后重跑                   |

## 9. 存档与兼容

### 9.1 四层版本，各管一件事

| 层           | 常量                   | 当前值 | 管什么                     | 位置                  |
| ------------ | ---------------------- | -----: | -------------------------- | --------------------- |
| 存档文件外壳 | `SAVE_FILE_VERSION`    |      1 | 文件字段结构、旧文件能否读 | `engine/save-file.ts` |
| 会话容器     | `SESSION_SAVE_VERSION` |      1 | 会话信封格式               | `engine/session.ts`   |
| 会话数据模型 | `meta.schemaVersion`   | 随会话 | 会话内部字段               | 存档头                |
| 数据契约     | `DATA_VERSION`         |  0.4.0 | 单位库/图表/剧本字段       | `data/version.ts`     |

另有**盘面快照版本** `BOARD_SNAPSHOT_VERSION`（当前 **11**），在 `stores/workbench.ts` 内，管「盘面投影/撤销快照」的字段形状。

### 9.2 铁律

- 读档**逐层校验**：任一层不符即拒，报错指出字段路径。
- **不静默迁移、不猜值**。唯一例外是专规 4.0 的共识日志 v1→v2（`migrateConsensusLogV1ToV2`，纯函数、只改题号）。
- 存档必须带：`records` / `units` / `stacks` / `markers` / `rng`（seed + drawCount + state）/ `session.status` / `log`。
- `awaiting` 状态读回后停在原问题，不能自动作答。

### 9.3 改状态的 SOP

```
① 改 state-types / session 类型
② 递增对应版本常量（容器或盘面快照）
③ 写迁移函数（纯函数）或明确拒读
④ 补用例：旧档拒读/迁移后等价、读回后能继续
⑤ 手动验证：导出 → 重启 → 读档 → 推进一回合
```

盘面快照的 `boardSnapshotFits` **只认上一版**；当前版必须走逐字段在场检查——曾因提前 `return true` 把「缺项拒读」关掉。

## 11. 性能与调试

### 11.1 性能口径

`scripts/perf-compare.mjs` 用**同一探针、同组指标**对照 Web 生产包与桌面壳：

| 指标                        |  验收线 |
| --------------------------- | ------: |
| 进入对局台 `click:进入初设` | ≤ 250ms |
| 突围段                      | ≤ 250ms |
| 移动会话 `click:开始移动`   | ≤ 300ms |

绝对值受机器负载影响大（同一构建实测 264–450ms 漂移），报表必须同时记录 `msedge` / `msedgewebview2` 进程数与 CPU 占用，否则数字不可比。

### 11.2 排查手段

| 场景             | 手段                                                            |
| ---------------- | --------------------------------------------------------------- |
| 骰序/结算可疑    | 用存档里的 seed 复现；写固定种子用例最小化                      |
| 流程卡住         | 看 `session.status` 与待答问题、`records.phase`、`stepIndexFor` |
| 操作被拒但没提示 | 查引擎 `fail(rule, reason)` 是否被 UI 丢弃；查 `legal-actions`  |
| 地图错位         | 先查 `map-config` 标定与 `hex-geometry`，不要逐格改数据         |
| 面板样式失效     | `npm run arch` 查 CSS 变量拼写                                  |
| 性能回退         | `perf:compare` + 打点；先看是否整盘重绘/未裁剪                  |

### 11.3 日志

对局日志（`session.log` / `recorder`）只记**事实**：谁在何时做了什么、掷了什么、结果是什么。不要写规则推断或 UI 文案，便于回放与审计。导出日志带构建提交号（`__APP_COMMIT__`），方便对照版本。

### 11.4 UI 探针（`npm run probe:ui`）

改「看得见的东西」（贴图尺寸与落位、标记、面板样式、命中区）时，别只靠源码守卫 + 手点：

```bash
npx vite build --outDir dist                       # 先出生产包（探针不替人 build）
npm run probe:ui -- --out E:/OCS/工作文件/tmp/shot.png
npm run probe:ui -- --scenario "Short Campaign" --preset --out shot.png
npm run probe:ui -- --preset --zoom 6 --focus 820,520 --steps my-steps.mjs --out shot.png
```

| 选项                 | 作用                                                                     |
| -------------------- | ------------------------------------------------------------------------ |
| `--dist`             | 生产包目录（默认 `dist`；不存在会直接报「先 build」）                    |
| `--scenario`         | 剧本卡片文本片段（默认 Short Campaign；匹配不上会列出候选文本）          |
| `--mode`             | 模式项序号 1–4（默认 2）                                                 |
| `--preset`           | 进对局后执行「脚本落初设 + 开始游戏」，并在页面挂 `window.__probe.pinia` |
| `--zoom` / `--focus` | 在焦点处滚轮放大 N 次（默认画布中心）                                    |
| `--steps`            | 步骤脚本：`export default async ({ page, out }) => {}`                   |
| `--keep-open`        | 截图后不关浏览器，人工接着看                                             |

它**不是**回归门禁（不进 `npm run check`），也**不驱动引擎跑回合**；结论仍靠人眼判图。
步骤脚本里取 store 的写法（只 return 可序列化片段，别整体 return 响应式代理）：

```js
page.evaluate(() => {
  const w = window.__probe.pinia._s.get('workbench')
  return w.units.filter((u) => u.side === 'axis').length
})
```

## 12. 协作与 Git

### 12.1 提交纪律

- **一改一提交**：代码 + 测试 + 文档 + 回执同一 commit。
- 提交信息中文，沿用仓库风格：`type(scope): 摘要`，正文写「改了什么 / 为什么 / 怎么验证」。
- 推送前 `git fetch` + `git rebase origin/main` 保持线性；远端偶有用户自建提交。
- 不 `--amend` 已推送提交，不 `--no-verify` 跳钩子。
- 分支：日常在 `main`；大改可开 `feat/...`、`codex/...`，合并前跑全量。

常用 type：`feat`、`fix`、`refactor`、`test`、`docs`、`chore`、`perf`。

### 12.2 不入库

`node_modules/`、`dist/`、`release/`、`coverage/`、`src-tauri/target/`、`src-tauri/gen/`、`backup/`、`.env.local` / `.env.*.local`、`*.log`、`android/keystore*`、`android/local.properties`。

`backup/` 是逐字节保留的人工备份，**不要格式化、不要批量改**。

### 12.3 文档命名

| 类型           | 命名                           | 例                                                    |
| -------------- | ------------------------------ | ----------------------------------------------------- |
| 常青文档       | 无日期，稳定标题               | `开发文档.md`、`数值修改指南.md`、`程序目录与清单.md` |
| 方案/规格/回执 | `YYYY-MM-DD-主题.md`           | `2026-11-12-具象补给支付台账.md`                      |

| 已失效         | 移入 `docs/archive/`，**不删** | 追溯决策用                                            |

## 13. 常见坑（实测）

| 现象                                           | 原因                                                                          | 处理                                                                                   |
| ---------------------------------------------- | ----------------------------------------------------------------------------- | -------------------------------------------------------------------------------------- |
| `npm run build \| grep ...` 显示成功但产物没出 | 管道把退出码换成 `grep` 的 0                                                  | 直接跑 build，看 `$?`；要过滤用 `tee` 后查 `PIPESTATUS`                                |
| 全量测试偶发 worker 启动超时                   | 并行 worker 争抢资源                                                          | `--no-file-parallelism`                                                                |
| Android 编译报「无效源发行版: 21」             | JDK 17                                                                        | 装 JDK 21，设 `JAVA_HOME`                                                              |
| C 盘被 Gradle 塞满                             | `GRADLE_USER_HOME` 默认在用户目录                                             | 指到 `F:/ocs-android-build/gradle-home`                                                |
| 换机后 APK 装不上/存档没了                     | 签名变了，只能卸载重装                                                        | 带走 `android/keystore/*` 与 `keystore.properties`                                     |
| 改了 `src/data` 下次同步被覆盖                 | 改的是生成物不是权威源                                                        | 改权威源后跑 `sync-*.mjs`                                                              |
| 组件里 `var(--color-border)` 不生效            | 变量名拼错，浏览器静默忽略                                                    | `npm run arch` 定位                                                                    |
| 新增导出没人调用                               | 只写了实现没接线                                                              | 接线或加白名单并注明原因                                                               |
| 预备单位停进环形工事                           | 5.7g 只许路过不许停留                                                         | 查 `computeReachableHexes` 与 `finishMove` 兜底                                        |
| 通用夹具误取 `Pax Repl`                        | 补员算子是 leg/可攻击/MA 5                                                    | 夹具谓词排除补员，或改用种子扫描                                                       |
| 触摸长按后下一次点击失效                       | 长按成立时复位了 `drag`                                                       | 长按成立时保留 `drag`，见 `long-press.ts`                                              |
| 读旧档被拒                                     | 四层版本之一不符                                                              | 按 §9 递增版本并写迁移，不要临时放宽校验                                               |
| 中文批处理乱码                                 | `.bat` 正文含非 ASCII                                                         | 正文纯 ASCII，首行 `chcp 65001`                                                        |
| 全量 vitest 报 `spawn UNKNOWN -4094`           | 本机并行 worker 与杀软/磁盘状态                                               | 用例本身全 pass 属噪声；可加 `--no-file-parallelism`；`check` 的 `test:fast` 不受影响  |
| 想复现一张界面截图却没有脚手架                 | 仓内此前只有源码守卫，没有浏览器级入口                                        | `npm run probe:ui`（见 §11.4）                                                         |
| PR 上 CI 红了但本地绿                          | CI 跑的是同一条 `check`，差在依赖/缓存                                        | `npm ci` 后重跑；先比对 `node -v` 与 lockfile                                          |
| AI 在 9.10 选项步「从不撤退」或原地卡住        | 选项步读 `retreatPlans`（要等选项落盘才建）恒为空；全损又超可用军力被 9.11 拒 | 用 `combatOptionRetreatLadder/Attempts`（选项步预演）＋失败退避/判卡见 `ai/step-guard` |
| `npm run check` 偶发单个用例 5s 超时           | 并行 worker 拉满时单例被挤过 5s 线（两次红在不同 seed-search 用例，单跑均过） | CI 已固定 4 worker；本地复现用 `VITEST_MAX_WORKERS=4 npm run check`，别改用例超时      |
| push 卡在「跑 npm run check」很久              | `pre-push` 钩子在跑全量门禁                                                   | 已跑过门禁就 `SKIP_PRE_PUSH_CHECK=1 git push`；钩子是本地文件，不属于版本库            |
| CI 红在「素材库缺少 …」/`units.json` 打不开    | runner 上没有本机素材库（素材库不入库）                                       | 已由 `tests/shared/source-library.ts` 跳过；本机仍红就是真缺图/真缺文件                |
