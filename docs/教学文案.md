# 教学文案（25 步 · 德军玩家视角）

> 这是教学文案的唯一出处。改教学提示只改本文件，不必再翻《游戏文案包》。
> 落码位置：`src/stores/tutorial.ts` 的 `source` 数组——只替换 `title` / `hint` / `intro`，`id` / `done` / `targetOf` 不动。
> 三层职责：`title` 求一瞥可懂，`hint` 是一道命令，`intro` 讲为什么 / 这是什么（安卓横屏隐藏）。
> 口径：不写格子编号与规则编号，用维捷布斯克、列佩利等地名指路；自称「我部 / 我集群」，敌方一律「敌」；不预设战斗结果；去四字格。

## 修改须知（改之前先看，别踩红线）

**测试断言**（`tests/stores/tutorial-mode.test.ts`，改坏就挂）：

- 每条 `hint` 不超过 40 字；含「霍特」的步骤不少于 10 条（现为 25 条全带）。
- `intro` 必须包含的关键词：`fuel`→「补给堆」、`strafe-1`→「斯图卡」、`bombing`→「Ju.88」、`overrun-1`→「没有进攻能力」、`move-mode`→「8-4-3」、`scout`→「控制区」。
- 尚有两条断言与文案口径冲突、待程序侧改断言：`fighter-sweep.intro` 与 `bombing.intro` 要求含「10 格」（本稿按用户口径不写格子编号，用「在我部截击机够得着的距离内」等自然语言代替）；`fighter-sweep.hint` 要求含「Bf110」（无点号，本稿已照写）。

**口径铁律**：

- 不写格子编号（如 19.27）或「某某格」，用真实地名指路。
- 不写规则编号（如 9.2），说具体动作与后果。
- 不预设战斗结果——胜负没打出来就不能先写死，只讲动作、机制和代价。
- 自称按层级：「我集群 / 我军 / 我部」；敌方番号写「敌第 X」，泛指写「敌军」。
- 去四字格；界面既有术语与阶段名（战斗补给、堆叠突袭、结算战斗、增援 SP）照旧，那是按钮上的词。
