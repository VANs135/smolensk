## 1. 四条铁律（不遵守就「改了不生效」）

### 1.1 版本闸门：`meta.version` 必须等于 `DATA_VERSION`

每个数据文件的头部都有 `meta.version`。加载时 [pipeline.ts](../src/data/pipeline.ts) 会先比对
[version.ts](../src/data/version.ts) 里的 `DATA_VERSION`（当前 **`0.4.0`**），不一致直接抛 `DataError`
并指出字段路径 `/meta/version`，**应用起不来**。

- 只是改数值、不改字段结构 ⇒ `meta.version` **不动**。
- 增删改字段结构（破坏性变更）⇒ 递增 `DATA_VERSION`，并把**所有**数据文件的 `meta.version` 一起改。

### 1.2 深度冻结：数据是只读的，只能改文件

`bootstrapData()` 完成「校验 → `deepFreeze`」，运行时的数据对象不可写。
**不存在「在控制台里改一下内存」的路径**，必须落到 `src/data/*.json` 文件。

### 1.3 `status` 门禁：只有 `valued` / `verified` 的记录会进游戏

- 运行时库 `units-*.json` 里**只存**了 `status` 为 `valued` / `verified` 的记录。
- 摆子清单也只列这两种：[workbench-model.ts](../src/stores/workbench-model.ts) 的 `unitChoices()`
  按 `status === 'valued' || status === 'verified'` 过滤。
- 想让一条 `classified`（未落值）的单位能用：先在**权威源**把它的 `fill_stage` 改成 `valued`，再重新同步（见 §6）。

### 1.4 单一来源：数值只许出现在数据层

组件里**禁止**写规则数字字面量（CODE_SPEC §3.2）。要改数值就改数据文件，
不要在 `*.vue` / `stores` 里直接改数字——那会同时违反规范且被门禁的代码审查判为事故。

## 2. 单位数值：字段对照表

单位记录结构由 [units.schema.ts](../src/data/schema/units.schema.ts) 定义（Zod）。
下表是**改动频率最高的字段**，以及它落到游戏里的哪里。

### 2.1 印值（最常改）

| 字段                                | 含义                                        | 游戏里的体现                                        |
| ----------------------------------- | ------------------------------------------- | --------------------------------------------------- |
| `factors.combat.attack`             | 战斗面 战斗值（A）                          | 算子标签第 1 段、选中面板 `A##`、战斗结算攻方实力   |
| `factors.combat.ar`                 | 战斗面 行动值（AR）                         | 算子标签第 2 段、战斗/突袭面板 `AR##`、内层战斗顺序 |
| `factors.combat.ma`                 | 战斗面 移动力（MA）                         | 算子标签第 3 段、模式切换后的可移动 MP 额度         |
| `factors.move.attack / ar / ma`     | 移动面（背面）同名三项                      | 切到移动面后同上                                    |
| `factors.*.barrage`                 | 炮兵轰炸值（仅火炮单位）                    | 轰炸面板候选与强度、`A##（炮击）` 显示              |
| `factors.*.range`                   | 炮兵射程（格）                              | 轰炸目标格的可选范围                                |
| `steps.total`                       | 军力（步数）总数                            | 算子军力点、损失分配、`3.2d` 多军力判据             |
| `reSize`                            | 团级当量（RE）                              | 堆叠上限（`4.8`）、运输当量（`4.7`）                |
| `throwRange.combatFace / moveFace`  | HQ 投递距离（`13.1b`）                      | 补给投递范围（两面不同值）                          |
| `classes.combatClass`               | 攻方类别 `armor`/`mech`/`other`             | CRT 列选择（`9.4d`）、装甲效果                      |
| `classes.movementClass`             | 机动类型 `leg`/`truck`/`tracked`            | 移动消耗（TEC）、燃料需求（`12.5a`）                |
| `attackCapable`                     | 能否进攻（`4.4`）                           | 能否主动发起战斗；`false` 时面板拒绝                |
| `attackValueBracketed`              | 战斗值是否带括号                            | 带括号 ⇒ 只能防御                                   |
| `rebuildable`                       | 是否可重建（`13.5c`，AR 后黄点）            | 重建/补员阶段能否重建该单位                         |
| `atEffects`                         | 反坦克效果 `heavy`/`light`/`none`（`9.4e`） | 装甲列战斗修正                                      |
| `specialized`                       | 规则化分类 `artillery`/`hq`/`replacement`/… | 炮兵/HQ/补员的专门判定分支                          |
| `specialAbilities` / `capabilities` | 规则能力标签                                | 专规门禁（如 NKVD、苏军炮群合堆）                   |
| `specialRule`                       | 规则章节号（如 `13.1b/13.5a/13.8a`）        | 提示与日志里的规则引用                              |
| `nameZh` / `nameEn`                 | 显示名                                      | 算子名（**见下方注意**）                            |
| `id`                                | 稳定主键 `<国籍>-<兵种>-<番号>[-<部件>]`    | 运行实例 id 的唯一来源，**创建后不可改**            |

> ⚠ **显示名的坑**：名字取自 `nameZh ?? nameEn ?? id`
> （[workbench-model.ts](../src/stores/workbench-model.ts) 的 `toConsoleUnit()`）。
> 当前 `units-*.json` **没有** `nameZh`/`nameEn` 字段，只有 `vassalName`（源库原名，引擎不读），
> 所以**游戏里现在显示的是 unit id**（如 `ax-infantry-ge-5-inf-div`）。
> 想让界面显示中文名，就在记录里补 `"nameZh": "第5步兵师"`。

数据 → 算子 → 界面的链路是固定的，改完数据后按下表逐处自查：

| 界面位置                                         | 数据来源                                    | 代码位置                                                                                                             |
| ------------------------------------------------ | ------------------------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| **摆子清单**（可选单位列表）                     | `units-axis/soviet.units`，按 `status` 过滤 | `unitChoices()` @ [workbench-model.ts](../src/stores/workbench-model.ts)                                             |
| **算子实例**（印值快照、显示名、机动、RE、军力） | 单位记录                                    | `toConsoleUnit()` / `faceFactorsOf()` / `mobilityOf()` / `reOf()` @ 同上                                             |
| **地图上的算子标签**（`A-AR-MA`）                | `unit.raw`                                  | `map-view.ts` 与 [WorkbenchView.vue](../src/views/WorkbenchView.vue)                                                 |
| **选中单位面板**（`A## AR## MA##`）              | `unit.raw`                                  | [WorkbenchView.vue](../src/views/WorkbenchView.vue) 选中区                                                           |
| **轰炸面板候选**（按 `barrage > 0` 过滤）        | `unit.raw.barrage`                          | [BarragePanel.vue](../src/components/barrage/BarragePanel.vue)                                                       |
| **战斗 / 突袭面板**（AR 选择、攻方实力）         | `unit.raw.attack` / `unit.raw.ar`           | [CombatPanel.vue](../src/components/combat/CombatPanel.vue)、`workbench.ts`                                          |
| **引擎移动判定**（MA 额度、燃料需求）            | `MoveUnitView.ma` / `mobility`              | `toMoveUnitView()` / `needsFuelOf()` @ workbench-model.ts                                                            |

> （摆子本身不落盘：存档只存会话/种子/日志游标，不在 `localStorage` 里存算子实例。）

## 4. 为什么表里给的样例都是「点号路径」

单位记录用三层结构，改的时候别找错层：

```
factors.combat.attack   ← 战斗面的战斗值（算子左上）
factors.combat.ar       ← 战斗面的行动值
factors.combat.ma       ← 战斗面的移动力
factors.move.attack     ← 移动面的战斗值（算子背面）
factors.move.*          ← 同上的移动面三项
noncombatDetails.*      ← 非战斗单位专用（SP 点数 / 运力 / 等级）
classes.*               ← 表列资格（不得按兵种推定，见 CODE_SPEC）
```

- `factors` 里**没有**某一面（单面算子、炮兵无背面值）是合法的，引擎按 0 兜底，不要硬塞 `null`。
- 所有 schema 都是 `.passthrough()`：多写的键**不会被拒绝**也会被保留，但**不会**被类型系统认识——
  要让新字段真正参与判定，得同时改 [units.schema.ts](../src/data/schema/units.schema.ts) 并接线到引擎。

## 6. 权威源 vs 运行时库（最容易踩的坑）

```
权威源（只读，禁止手改结构）
D:\OCS\OCS斯摩棱斯克素材\斯摩棱斯克工程数据库\
  ├── units.json        地面单位（含 fill_stage / printed_values / setup_placement…）
  └── aircraft.json     空军
                │
                │  node scripts/sync-units.mjs      ← 字段映射 + 只挑 valued/verified
                ▼
运行时库（游戏真正读的）
src/data/units-axis.json / units-soviet.json / aircraft.json
```

- **同步会覆盖**：`sync-units.mjs` 直接重写 `units-*.json` / `aircraft.json`。
  你手改运行时 JSON 后一旦再跑同步，**手改内容全丢**。
- 两条正确姿势，二选一：
  1. **长期生效**（推荐）：改权威源 `units.json` → `node scripts/sync-units.mjs` → 提交两份产物；
  2. **临时试验**：直接改 `src/data/units-*.json`，**并且不要再跑同步脚本**。
- 权威源的字段名与运行时**不同**，对照表：

| 权威源 `units.json`                        | 运行时 `units-*.json`                     |
| ------------------------------------------ | ----------------------------------------- |
| `printed_values.front.A / AR / MA`         | `factors.combat.attack / ar / ma`         |
| `printed_values.back.*`                    | `factors.move.*`                          |
| `artillery_values.front.barrage / range`   | `factors.combat.barrage / range`          |
| `unit_kind`（`combat`/`non_combat`）       | `unitKind` + `isCombat` + `unitFamily`    |
| `combat_category`                          | `classes.combatClass`                     |
| `mobility_type`                            | `classes.movementClass`                   |
| `RE` / `steps_total`                       | `reSize` / `steps.total`                  |
| `fill_stage`                               | `status`（只同步 `valued`/`verified`）    |
| `non_combat_type`（`supply_point` → `sp`） | `noncombatKind`                           |
| `special_abilities`                        | `specialAbilities` + `capabilities`       |
| `setup_placement` / `setup_by_scenario`    | →（经另一个脚本进 `scenario-setup.json`） |


### ⚠ 先确认你开的是哪一个（最常见的「改了没生效」）

| 你打开的页面           | 端口 | 实际读的是什么                       | 改 `src/data/*.json` 会变吗      |
| ---------------------- | ---- | ------------------------------------ | -------------------------------- |
| `npm run dev`          | 5173 | **源码**（JSON 现取现用）            | ✅ 会（刷新页面即可）            |
| `release/启动兵棋.bat` | 5174 | **已构建产物**（数据在打包时被内联） | ❌ 不会，必须重新 `npm run pack` |

判断方法：页面标题带「· 开发版」的是开发服务器；不带的是发布包。
发布包服务器在跑时，命令行是 `node release/serve.mjs --root "." --port 5174`。

数据在构建时被**内联进 `release/assets/*.js`**，所以发布包是「冻结」的：
改源文件后要 `npm run pack` 重新装配，再重新双击启动文件。
日常调数值请一律用 `npm run dev`（5173）迭代，改完再打包。

## 8. 三个动手示例

### 例 1：把轴心第 5 步兵师的战斗面 MA 从 3 改成 4（临时试验）

1. 打开 [units-axis.json](../src/data/units-axis.json)，搜 `ax-infantry-ge-5-inf-div`；
2. 改 `"factors": { "combat": { "attack": 20, "ar": 4, "ma": 3 } }` → `"ma": 4`；
3. `npm run dev` → 刷新页面 → 摆子清单选中该师 → 地图标签显示 `20-4-4`，选中面板同步；
4. `npm run check`。若 `units.test.ts` 有相关样例断言则一并更新。

> 不要跑 `sync-units.mjs`，否则这一步会被权威源覆盖。

### 例 2：给一个单位加中文显示名

在该记录里加一行 `"nameZh": "第5步兵师"`（`id` 保持不变）。
`toConsoleUnit()` 的命名回退链是 `nameZh ?? nameEn ?? id`，
所以加了 `nameZh` 之后，算子名、日志、面板里的显示名都会变成中文。

### 例 3：改规则常量（补给换算 SP → T）

1. 打开 [rules-constants.json](../src/data/rules-constants.json)，`supply.spToT` 当前为 `4`；
2. 改成目标值（例如 `5`）；
3. 引擎侧 `engine/rules/supply.ts` 的 `SP_TO_T` 随之变化 ⇒ 补给点数换算、日志中的 T 数一起变；
4. 因为这是**规则改动**，必须核对规则书章节并在提交信息里写明依据；`rules-constants.test.ts` 若有取值断言需同步。
