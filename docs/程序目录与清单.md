## 1. 项目定位与技术栈

OCS《斯摩棱斯克》（Smolensk: Barbarossa Derailed, OCS #17）**电子裁判台**：
掷骰、查表、路径与补给追溯、状态记录全部交给引擎；玩家只保留决策。

| 领域 | 选型                          | 领域 | 选型                |
| ---- | ----------------------------- | ---- | ------------------- |
| 语言 | TypeScript strict（禁 `any`） | 渲染 | Canvas 2D 自绘      |
| 框架 | Vue 3 组合式 API              | 样式 | 原生 CSS + 设计令牌 |
| 构建 | Vite 8                        | 数据 | JSON + Zod 校验     |
| 状态 | Pinia（setup store）          | 测试 | Vitest              |

对局形态：**双人同机热坐**；无后端，生产产物为纯静态文件（单文件静态服务器打开）。

## 3. 分层与依赖方向（唯一定向线）

```
        views / components            ← 界面：只渲染与派发意图
                 │
                 ▼
              stores                  ← Pinia：界面状态 + 引擎状态的只读投影
                 │
                 ▼
              engine                  ← 规则内核：纯 TS，禁 vue/pinia/DOM/Canvas/网络/Math.random
                 ▲
                 │（只读引擎输出）
              render                  ← Canvas 绘制与命中检测，无状态写入

        shared / data / styles        ← 横向基座：纯工具 / 数据唯一入口 / 设计令牌
```

**硬纪律**（违反即事故，见 CODE_SPEC §3）：

1. 规则结算只在引擎 —— UI 不重算规则，render 无状态写入；
2. 数值只有一个来源 —— 表格与常量只来自 `src/data/*.json` 与 `engine/rules/*`；
3. 掷骰必须可重放 —— 禁 `Math.random`，随机一律走 `engine/rng.ts`；
4. 数据先过校验 —— JSON 载入必过 Zod，类型由 schema 推导；
5. 样式只用令牌 —— 组件内不写死十六进制；
6. 规则编号落字符串 —— 便于反向检索规则书。

## 17. 改动后的固定动作

```bash
npm run dev      # 迭代：改数据/组件即时看效果（发布包不会自动更新）
npm run check    # 门禁：eslint + prettier + vue-tsc + vitest（四关全绿才算完成）
npm run pack     # 交付：重新构建并装配 release/
```

**改动影响的联动清单**（按波及范围由小到大）：

| 你改了                   | 还要连带改/跑                                                                                                              |
| ------------------------ | -------------------------------------------------------------------------------------------------------------------------- |
| 某个单位数值             | 同步权威源（否则重跑 `sync-units.mjs` 会覆盖）；`tests/data/units.test.ts` 里写死的样例值                                  |
| 地图工事/地形            | `tests/data/map-layers.test.ts` 的条数；`scenarios.json` 的 `printedHedgehogOwners` 归属账本；权威源 `map_facilities.json` |
| 规则常量                 | 对应引擎常量（如 `supply.ts#SP_TO_T`）；`tests/data/rules-constants.test.ts`                                               |
| 数据字段结构（增删字段） | 递增 `src/data/version.ts#DATA_VERSION` + **所有** JSON 的 `meta.version` + 对应 `schema/*.schema.ts`                      |
| 规则判定                 | 同名 `tests/engine/*.test.ts`，并核对 `CODESTYLE`：注释标规则章节号                                                        |
| 界面面板                 | 无联动，但样式须用 `tokens.css` 令牌                                                                                       |

> 更细的数值改动指引（含权威源字段对照、易踩坑清单）见 [数值修改指南.md](数值修改指南.md)。
