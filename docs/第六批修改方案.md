  验收：C 段空军炸 X → 推进到 F 段 → 炮兵可再炸 X（引擎放行）；C→F 后空军候选仍可按类别列出；低空扫射同格两次不被账本拒（14.7d-A）。

## 6. 顺序与理由

**P0 → S → R → M → A → F → U → T**。

- **P0** 是三条最便宜的真 bug/缺口（跨段轰炸账本、轮式停车突袭、射程未判），先修可立刻改善可玩性，且互不依赖。
- **S（初设）→ R（增援）→ M（移动）→ A（空军）→ F（战斗）** 是用户使用频率最高的主链；S 的分方游标与"确认"是 R/M 单会话骨架的样板。
- **F** 与第五批批 E 合并，避免同一批文件两轮返工。
- **U** 横切（UI 最简化、SP 投影、迷雾裁剪）放后，避免与前面批次的面板重排互相冲突；**T**（20.0 触点）独立，最后做。

共 **8 批 / 18 个切片**。每切片仍走六步固定动作（原文 → 先红用例 → 改码 → `npm run check` + `build` 全绿 → §17.x 回执 → 快照），
用户清单里凡是**改变既有契约**的（条 8/10/13/5/24 的裁定取代、条 19 的旁路废除、条 22 的时机迁移）都按契约变更写明理由，不把断言改宽松。
