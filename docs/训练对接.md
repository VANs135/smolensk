# 训练对接：Linux 神经网络策略 ↔ 本仓引擎

> 读者：负责训练的朋友（Linux 环境）＋ 本仓维护者。
> 本文只写**接口与流程**，不承诺具体网络结构。标“已交付”的接口可照抄；标“尚未实现”的不要照抄调用。
> 事实基准：`refactor/workbench-decouple` @ `2a81542` + 本次训练支撑修复（2026-11-26）。
>
> 已具备：同步 `TrainingEnv`、checkpoint/restore、预编译训练 bundle、单/多进程 JSONL 采集器、canonical 动作键、候选表 v1、吞吐基线脚本。
> 尚未具备：跨进程 stdio 决策协议。正式多档吞吐基线已补：剧本 1、1/2/4 worker、每档 100 步（见 §5）。

## 0 一句话

引擎已经能在 Linux 无头跑通。训练支撑这批已经落了一版**同步环境 + 采集器 + canonical 动作键 + 候选表**：

- `src/ai/training/env.ts`：`reset / observe / step / candidates`，不 `await nextTick()`、不驱动 Vue；
- `TrainingEnv.checkpoint / restoreCheckpoint`：在明确起点抓「会话 + 盘面」，回滚后清空 AI 内存；
- `scripts/collect.mjs`：用脚本策略采 `obs → key` JSONL，支持 `--workers=N` 多进程分片；
- `scripts/bench-training.mjs`：`TrainingEnv` 稳态步吞吐、回滚与内存基线（不跑 `ai-selfplay`）；
- `scripts/build-training-bundle.mjs`：把训练入口预编译成 Node bundle，采集/bench 不再每次冷启动 Vite SSR；
- `canonicalActionKeyOf`：把 `instanceId` / 随机 id 换成训练别名（含死亡堆与补给站）；
- `candidateActionsOf`：把快照既有投影翻成可直接 `step` 的 `AiAction`（v1，不声称穷举）。

还差的是**跨进程 stdio 协议**与训练方自己的 Python 策略进程；这两件不在本仓本轮交付里。

## 1 先把环境跑起来（Linux）

```bash
git clone --depth 1 -b refactor/workbench-decouple https://github.com/VANs135/smolensk.git
cd smolensk
npm ci                     # 按 lockfile，别用 npm install 改锁
npm run build:train        # 预编译训练入口（.training-bundle/，默认 1 s 级；不入库）
npx vitest run tests/engine --maxWorkers=2   # 引擎用例，最省事的一次自检
npm run check              # 全量门禁（含 lint / 类型 / 审计 / 架构扫描）
```

实测（2 核 3 GB 云主机，Node 22.23.4 / npm 10，2026-11-25）：

| 项                   | 结果                                             |
| -------------------- | ------------------------------------------------ |
| `npm ci`             | 42 s                                             |
| `npm run build`      | 32 s                                             |
| `tests/engine`       | 105 文件 / **2176 例全过**，182 s                |
| `npm run check` 全量 | 640 文件通过、3 个按「素材库」跳过、架构扫描通过 |

两条要注意：

1. **素材库不需要**。原始扫描图与工程数据库不入库；依赖它们的少数用例会自动 skip（`tests/shared/source-library.ts`），
   不影响训练。要跑那几条就设 `OCS_SOURCE_DIR`。
2. 仓库里若干 `scripts/*.mjs` 仍按 Windows 路径写死（`sync-counters` 等），**训练链路不碰它们**。

剧本 id 共 8 个：`1`–`7`（Smolensk 系列）与 `Intro`（维捷布斯克教学）。

## 2 已经就绪的接口

| 挂钩                                                   | 位置                            | 语义                                                                 |
| ------------------------------------------------------ | ------------------------------- | -------------------------------------------------------------------- |
| `type AiDecider = (snapshot: AiSnapshot) => AiAction`  | `src/ai/driver.ts:1775`         | 外部策略入口，**同步**返回一个动作                                   |
| `runAiStep(ctx, { decider, onStep })`                  | `driver.ts:1819`                | 单步决策 + 记录回调（同步；训练环境按它封装）                        |
| `runAiSelfPlay({ ctx, decider, onStep, targetTurns })` | `driver.ts:1930`                | 整局对打，每步 `await nextTick()`；**不是**训练环境                  |
| `snapshotOf(ctx, memory, control)`                     | `driver.ts:670`                 | 观测投影（只读，不改盘面）                                           |
| `serializeObservation(snap)`                           | `src/ai/trace.ts:83`            | 运行时 trace 的可 JSON 纯数据；版本仍为 `AI_IO_VERSION=1`            |
| `TrainingEnv.reset/observe/step/candidates`            | `src/ai/training/env.ts`        | **训练专用**同步环境；reset 重建 Pinia，不等待渲染                   |
| `TrainingEnv.step().info`                              | `src/ai/training/env.ts`        | 额外给 `stateChanged/noop/noopSteps/stalled`；连续空转默认 50 步截断 |
| `TrainingEnv.checkpoint/restoreCheckpoint`             | `src/ai/training/env.ts`        | 起点快照 / 回滚；只恢复会话与盘面，不重跑初设                        |
| `trainingObservationOf(snap, identity)`                | `src/ai/training/serialize.ts`  | 训练观测：稳定 ID + 递归键序 + 实体 roster                           |
| `createTrainingIdentity(ctx)`                          | `src/ai/training/identity.ts`   | 原始实例 id → `u:/a:/d:/b:` 稳定别名                                 |
| `canonicalActionKeyOf(action, ids)`                    | `src/ai/training/action-key.ts` | 全参数 canonical key；与旧 `actionKeyOf` 并存                        |
| `candidateActionsOf(snapshot, identity)`               | `src/ai/training/candidates.ts` | 候选动作 v1（来自快照投影，不声称穷举）                              |
| `AI_TRAIN_VERSION = 2`                                 | `src/ai/training/contract.ts`   | 训练观测/数据版本；与运行时 `AI_IO_VERSION` 分开                     |
| `createRngState(seed)` / `rollDice`                    | `src/engine/rng.ts`             | mulberry32，同 seed 完全可复现                                       |
| `serializeSession` / `deserializeSession`              | `src/engine/session.ts`         | 整局状态 JSON，可做快照回滚                                          |

关键语义（**不要误解**）：

- `decider` 返回的东西**结构不合法或抛异常** → 该步回退脚本策略并标 `fellBack: true`。这是「模型输出坏了」，
  不是「规则拒绝」。训练侧应把它当**负样本**，不能当专家动作。
- 动作**参数不合规**（例如越权移动）不算 `fellBack`：引擎会照常拒绝并记规则号（`rule` / `reason`），
  这类才是「学到了违规」，可以统计成违规率。
- `onStep` 的回调是**只读记录**：不得改盘面；抛异常即整局失败，采集器应作废该局。
- `TrainingEnv` 是**单进程单局**：`setActivePinia` 是进程级全局，同一 JS 上下文不要并发跑两个 env；
  多 worker 请 **每进程一局**（与 §6 的吞吐建议一致）。
- `checkpoint` 只在明确、稳定的起点调用（如 reset 之后、动作开始前）。它直接抓会话与盘面，
  不经过 `session.saveNow()` 的 UI 存档守卫；在移动/战斗结算中途拍快照可能留下不可恢复的中间态。
  `restoreCheckpoint` 会清空 AI 记忆并把步数归零，训练侧不要把「回滚前的动作」带进下一段。
- `TrainingEnv.step().info.stateChanged` 是**盘面**变化（已剔除 `move.triedUnits` / `combat.triedDefenderHexes`
  等 policy 试错缓存）；`noop = !stateChanged`，连续 `maxNoopSteps` 步（默认 50）没有盘面变化即 `done` 并置
  `stalled`。外部策略不要只看 `ok=true`：p5 的 9000 步空转就是 `applyAction→true` 但 `stateHash` 不变。
- 稳定别名现在覆盖**死亡堆**（`rebuild` 的 `unitId` 来自这里）与**补给站**；补给站别名不含 `sp/t`，
  扣款/装载/拆分不会换身份，装载在运输点上的 SP 跟随承运单位的别名。
- `AI_TRAIN_VERSION` 与 `AI_IO_VERSION` 不是一回事：前者只管训练投影/采集数据，后者保留给现有运行时 trace
  消费者；训练数据不要拿 `serializeObservation` 顶替 `trainingObservationOf`。

## 3 观测（`obs`）

`AiSnapshot`（`src/ai/policy.ts:279`）分组如下：

| 组          | 字段                                                                                                                                          |
| ----------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| 局面骨架    | `turn`、`phase`、`segment`、`segmentStepIndex`、`activeSide`、`defenderSide`、`terminated`、`locked`、`scenarioId`                            |
| 待答        | `awaitingOptionIds`、`awaitingResponder`、`awaitingPrompt`、`specialPending`                                                                  |
| 环节候选    | `setup`、`refit`、`rein`、`move`、`branch`、`air`、`airInterception`、`barrage`、`combat`、`supply`、`overstack`、`rebuildHqHexes`、`control` |
| 推进/动作面 | `can`、`advanceAvailable`、`reserveUnitIds`、`reserveTriedUnitIds`、`reserveOnHedgehogIds`、`fuel`、`setupRemaining`、`setupInProgress`       |

**`can` 的准确含义**：它是当前环节**可用的动作族**集合（`w.segmentActionKeys`，如 `move.order`、`combat.declare`、
`air.refit`），**不是**实例级合法动作列表。所以它只能当「这一族现在能不能做」的闸门，不能直接当动作掩码用。

给训练侧的实操建议：先别指望自动特征工程。`obs` 是给人看的规则投影，字段会随规则改动增长；
建议先用手挑 60–150 维表格特征（回合/阶段 one-hot、各方兵力步数、补给状态、当前环节候选数量等），
再考虑上 GNN/张量。

## 4 动作（`act`）

`AiAction` 是判别联合（`policy.ts:363` 起，约 40 个 `kind`），典型几条：

```ts
{ kind: 'moveBegin', unitId: 'u-…' }
{ kind: 'moveClick', hex: { col: 7, row: 31 } }
{ kind: 'combatRetreatPaths', paths: [{ unitId: 'u-…', path: [{ col, row }, …] }] }
{ kind: 'answer', optionId: 'opt-…' }
{ kind: 'wait', reason: '…' }   // 玩家侧待办，AI 不提交
```

旧 `actionKeyOf(action)`（`policy.ts:460`）仍是运行时死锁判据的可读签名，**只做了单向**，且部分分支
内嵌 `instanceId`（如 `transportLoad:<pointId>`、`moveBegin:<unitId>`）。训练侧**不要**再用它当动作空间键，
改用：

- `createTrainingIdentity(ctx)`：把 `unit.instanceId` / `air.instanceId` / `dump.id` / `base.id`
  换成 `u:` / `a:` / `d:` / `b:` 稳定别名（库键 + 首次出现序号）；死亡堆（`rebuild` 来源）也登记，
  补给站别名不含 `sp/t`，装载点跟随承运单位；
- `canonicalActionKeyOf(action, identity.actionIds)`：覆盖所有带参 kind，列表参数先按稳定别名排序；
- `candidateActionsOf(snapshot, identity)`：每步给训练方 `{ key, action, family, source }[]`。

候选表 v1 的边界要说清：

- 它只把**快照已经给出的候选**翻成 `AiAction`（移动可达格、整备基地、到货条目、战斗选项梯子、撤退路线等）；
- 它不是引擎穷举合法动作：战斗补给只给首个站点组合、多单位撤退组合上限 32、部分入口动作仍可能被引擎拒；
  攻方图上与储备都付不出时只给 `combatSkip`（12.4「该方根本不攻击」），补给落盘前也始终保留这个合法出口；
- 被拒不是 bug：`runAiStep` 会照常返回 `ok=false` 与 `rule`，训练侧按规则号统计违规/负样本。

`actionKeyOf` 与 `canonicalActionKeyOf` 并存，不是替换：现有 trace 消费者继续用前者，训练数据只用后者。

## 5 决策协议（**尚未实现**，stdio 逐行 JSON 设计稿）

一个进程一局，父进程（引擎侧）spawn 训练方的解释器，双方逐行 JSON：

| 方向      | 消息                                                                                                              | 说明                                                      |
| --------- | ----------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------- |
| 我们 → 他 | `{"type":"hello","trainVersion":2,"commit":"2cb6d18","scenarioId":"1","seed":123,"side":"axis","control":"both"}` | 开局握手。`trainVersion` 不匹配请他直接报错退出           |
| 他 → 我们 | `{"type":"ready","policy":"nn","model":"bc-v1"}`                                                                  | 就绪。`policy` 取值 `scripted` / `nn`，写进每局元信息     |
| 我们 → 他 | `{"type":"decide","t":37,"obs":{…},"candidates":[{"key":"moveBegin:u:axis:…:1","action":{…}}]}`                   | 一步一问；`candidates` 为空 ⇒ 这一步只能 `advance`/`none` |
| 他 → 我们 | `{"type":"act","key":"moveBegin:u:axis:…:1"}`                                                                     | 必须来自该步 `candidates`，否则记 `fellBack`              |
| 我们 → 他 | `{"type":"done","ep":12,"steps":3104,"result":"axis_win","refused":7}`                                            | 收局                                                      |

约定：

- 单步超时默认 500 ms（可用 `--decide-timeout` 调）。超时视同 `fellBack`，并把该局标 `degraded`。
- 训练方**只读**：不得在回调里改盘面、不得自己造 `AiSnapshot`。
- 协议要能「无模型跑通」：`--policy scripted` 时由引擎自己走脚本策略，用来验证链路与数据格式。

## 6 训练侧怎么干（建议顺序）

1. **先模仿学习（BC）**：用脚本策略跑 100–300 局，采集 `obs → key`。这一步不需要 RL，一周内能有「能完整下完一局」的模型。
   本仓已有采集器：

   ```bash
   # 先预编译一次（collect/bench 缺 bundle 时会自动补，但手动跑一次更直观）
   npm run build:train

   node scripts/collect.mjs --scenario=1 --episodes=10 --steps=400 \
     --seed=20261126 --out=/data/ocs/ai/sc1.jsonl

   # 多进程：每 worker 独立 Pinia；先写 .part-N，再合并成正式 JSONL
   node scripts/collect.mjs --scenario=1 --episodes=40 --steps=400 --workers=4 \
     --seed=20261126 --out=/data/ocs/ai/sc1.jsonl
   ```

   默认只落**正样本**：`ok=true` 且 `stateChanged=true`。要诊断被拒/空转步，显式加 `--include-refused`；
   要完整候选动作（不只 key），加 `--include-candidates`。输出首行
   `{"type":"meta", version, commit, scenarioId, seed, episodes, maxSteps, includeRefused, includeCandidates, runtime, workers?}`，
   其后每行 `{ version, episode, step, scenarioId, seed, observation, actionKey, executedKey, action, ok,
stateChanged, noop, noopSteps, stalled, truncated, candidateCount, candidateKeys, candidates?, rule?, reason?, reward, done }`。
   `candidateKeys` 取自**动作前**的 `env.candidates()`；`observation` 是 `TrainingObservation`（`state` + `entities`），
   不是运行时 `AiSnapshot` 原样。

2. **再自对打/PPO**：动作空间 = `env.candidates()` + mask；奖励先只用终局（胜负/VP），别急着加过程奖励，避免奖励塑形引入规则脑补。
3. **吞吐现实**：旧 `runAiSelfPlay` 路径单步 8.7–29.7 ms（含每步 `await nextTick()`）；`TrainingEnv` 去掉了渲染等待。
   `scripts/bench-training.mjs` 的正式多档基线（剧本 1，每 worker 1 局 × 100 步，warmup 5，bundle 入口，
   i9-12900H / 20 逻辑核 / 47.7 GB；2026-11-26 实测）：

   | worker | 总步 | 临界路径步/秒 | 含启动墙钟步/秒 | p50  | p95   | RSS/worker | 启动墙钟 | 并行效率 |
   | ------ | ---- | ------------- | --------------- | ---- | ----- | ---------- | -------- | -------- |
   | 1      | 100  | 11.30         | 11.02           | 71.1 | 223.9 | 142.1 MB   | 1.72 s   | 0.98     |
   | 2      | 200  | 21.07         | 20.42           | 75.7 | 246.1 | 156.6 MB   | 3.08 s   | 0.97     |
   | 4      | 400  | 38.33         | 37.17           | 81.0 | 271.8 | 152.6 MB   | 5.75 s   | 0.97     |

   1 百万步外推：1 worker 约 24.6 h / 24.6 core-hour；2 worker 约 13.2 h / 26.4 core-hour；
   4 worker 约 7.25 h / 29.0 core-hour。扩展接近线性但每档约损 3%，单 worker 稳态仍是 ~11 步/秒上下；
   `reset` 另计 0.86–1.07 s/局，`checkpoint` 约 30–38 ms，回滚 2 次 / 146–208 ms。预编译后单 worker 20 步的短测：
   Intro 启动 `startupWallMs≈0.9–1.0 s`、`moduleLoadMs≈0.5 s`、35–41 步/秒、p50 17–22 ms；剧本 1 启动 ≈1.7 s、
   12.2 步/秒、p50 60.5 ms。对比同剧本 1 的旧基线（启动 317.8 s、9.41 步/秒、p50 62.7 ms、RSS 1083 MB），
   启动与内存下降是主收益；稳态步耗时仍受规则分支影响，不能拿 Intro 的 35 步/秒或 4 worker 的 38 步/秒直接外推到
   单局长剧本。Vite SSR 兜底仍保留，但不再走冷启动主路径。要多进程并行：**每进程一局、各自 `createPinia()`**；
   4 worker 的内存约 0.6 GB，8–32 并发按 `RSS/worker × 并发` 预留，别在同进程里开多局。

4. **纪律**（对训练方也是硬约束）：不得改规则、改剧本数据、改骰子来提分；胜率必须是「同规则、同 seed、对脚本策略」的胜率。

## 7 评估口径（固定下来，别每次换）

- 剧本：`1`（长剧本）与 `2`（短剧本）各 50 个 seed；轴心方（`side: 'axis'`），苏方固定用脚本策略。
- 四项指标：胜率、`fellBack` 率、引擎拒绝率（按 `rule` 分组）、每步 p50 延迟。
- 复算要求：同 seed 重跑一局，`canonicalActionKeyOf` 序列逐字一致（`TrainingIdentity` 归一化后才成立）。
- 已知既有红灯：`tests/flows/ai-selfplay.test.ts`「剧本 1 第 9 回合」在 `preTurn` 白名单外拒绝
  （`unknown｜fuelPay:…｜提交被拒`），与模型无关，别当回归基准。该用例单轮 4–5 分钟，**默认不跑**。

## 8 模型怎么回灌到游戏里

| 方案                  | 做法                                                | 适用              | 代价                         |
| --------------------- | --------------------------------------------------- | ----------------- | ---------------------------- |
| A 离线评估            | 模型只留在训练机，评估也由引擎侧跑                  | 训练期            | 游戏里看不到                 |
| B 权重 JSON + TS 前向 | 导出小 MLP 权重（JSON）→ `src/ai/nn-policy.ts` 前向 | **发布/实机推荐** | 需要固定网络结构，参数量受限 |
| C ONNX                | 导出 `.onnx` → `onnxruntime-web`                    | 结构复杂          | 加依赖、包体变大             |
| D Python sidecar      | 本地起 HTTP/stdin 服务，游戏连本地进程              | 训练期联调        | 不能随发布包走               |

建议：**训练期用 D 联调，发布用 B**。若模型是树模型/大网络，再考虑 C。

## 10 版本与文件交换纪律

- **数据与权重不进仓库**（体积）。JSONL 与权重放对象存储/网盘，附 `sha256`；每份数据在首行 `{"type":"meta"}` 记
  `version`、`commit`、`seed`、`scenarioId`、`episodes`、`maxSteps`、`includeRefused`、`includeCandidates`、`runtime`，缺一项就作废。
  `scripts/collect.mjs` 已自动写这条。
- `AI_TRAIN_VERSION` 变了 ⇒ 旧训练数据默认不能用（除非显式转换）；模型加载前必须校验，不匹配就拒载。
- 动作 key 一旦归一化，**只增不改**；新增 `kind` 追加，不重命名。
- `AI_IO_VERSION` 仍只服务运行时 trace；不要把它当训练数据版本。

| 现象                              | 原因                                                   | 处理                                                            |
| --------------------------------- | ------------------------------------------------------ | --------------------------------------------------------------- |
| Linux `npm ci` 报 `EBADPLATFORM`  | 曾是 `@rolldown/binding-win32-x64-msvc` 直依赖         | 已在 `7edecfd` 删除，勿再加回                                   |
