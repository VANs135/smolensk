# OCS 斯摩棱斯克重构计划

更新：2026-11-04，按用户要求调整优先级。本次仅修改计划文档；后续开发以本文件的执行顺序为准，历史批次文档中的“下一步”不再决定当前排期。

## 目标与范围

首要目标是：玩家通过正式游戏界面，按规则完整执行一个游戏回合的全部环节，并正确使用各单位在相应环节中的合法行动。保留现有地图、单位数据、Vue/Pinia/Canvas技术栈及存档兼容，继续渐进修复和解耦。

一个完整游戏回合（Game Turn）包括：回合准备 → 先手方A–H → 后手方A–H → 回合结束；未达到终局则进入下一回合准备，达到终局则按规则收束。每方的E反应阶段由对方执行允许的行动，不能把“阶段玩家”直接等同于“当前操作者”；先手也不能固定假设为轴心国。

“各单位各行动”指本作规则、剧本及已启用选项允许的行动。设施、SP及标记按自身能力验收，不强行赋予地面移动或攻击能力；互斥模式、不同日期、不同战果分支通过多个合法场景覆盖，不要求同一单位在一次回合中做完互斥动作。

空运、空投、联合承运、分货和部分返航降为低优先级待办，停止作为下一批主线。地面补给、燃料、运输点、铁路和ZOC仍是高优先级，直接推进，不再等待空运完成。常用空军的整备、轰炸、空战、拦截、防空和返航继续纳入完整回合。

## 交付分层与最终完成标准

| 交付               | 必须达到的结果                                                                          | 尚未完成时的表述                               |
| ------------------ | --------------------------------------------------------------------------------------- | ---------------------------------------------- |
| R1：常规完整回合   | 双方完整A–H可连续执行，地面移动、补给、反应、炮击、战斗、进击及常用空军有真实行动和结算 | 只能称“常规回合通过”，低频行动另列待办         |
| R2：非空运行动覆盖 | 本作各类单位及每个非空运合法行动、专规和日期分支逐项验证，合法结算点存读档后可继续      | 有缺项即保留未验收，不能以空过环节代替         |
| R3：最终行动覆盖   | 补完低频待办，包括适用的空运/空投；各单位行动清单无未实现或未验收项，并重新跑通完整回合 | 低优先级表示后做，不表示已完成或从最终目标删除 |

最终签收同时要求：完整双方回合连续通过、单位行动清单覆盖、本作适用专规覆盖、真实界面复现、资源与骰序可对账。完整战役至终局保留为后续耐久验收，不能代替这一回合的逐环节、逐行动验收。

## 一回合逐环节验收

下表的A–H须对先手、后手分别执行；E阶段还须核对操作者反转。原规则未固定的段内动作次序要标明依据，不能把当前界面排列直接当成规则。

| 阶段/环节               | 必须真实执行的内容                                                              | 放行到下一环节前核对                                                                 |

| 回合准备：天气、先手    | 剧本指定首回合分支，以及后续回合掷骰和胜者选择先后手                            | 骰子只用一次；未回答先手选择时不能开拔；日期与天气生效                               |

| C：突围                 | 有资格单位尝试、失败/成功、路径和后续；无候选自动跳过                           | 突围先于其它移动；单位、货物和骰序去向完整                                           |

| E：反应移动、轰炸       | 对方释放预备、反应移动/突袭、允许的炮兵和空军轰炸                               | 反应方而非阶段玩家执行决策、付费和承担损失；MA和资格正确                             |
| F：炮兵轰炸、地面战斗   | 选炮、射程、补给与目标；按9.2完成战斗及所有后续                                 | 不借旧战果放行新战斗；损失、选项、撤退、推进和进击判定收束                           |

| H：清理                 | 按规则方别/时点清理DG、进击、燃料、运输破坏等状态及段末义务                     | 不提前清敌方或跨阶段有效状态；不重复清理或漏清                                       |
| 双方交接、回合结束      | 先手完成后后手完整A–H；核对控制权及到期胜利检查，继续对局则更新日期进入下一准备 | 不跳过任一方；一次回合只推进一次；合法终局正确结算并停止，新旧额度按真实生命周期重置 |

有玩家行动的环节覆盖适用的“有行动并完成”“合法无事可做”“玩家放弃可选行动”分支。强制事项不能被空过；自动项核对适用条件、结果和下一步，不能因无界面而漏结算。规则存在但未实现的行动不得伪装成“无事可做”。

每个规定的环节末/阶段末还需核对超堆叠、强制吸收、装甲集群等适用义务。控制权与胜利检查按规则规定的时点执行，覆盖继续下一回合与合法终局两种分支。

## 高频共用规则的处理要求

### ZOC

分别核对投射、移动进入/离开、突袭、战斗资格、撤退、战后推进、铁路、抽取/投递/追溯、整备等操作的效果，区分可抵消和不可抵消。不能把普通移动的ZOC政策复制到补给或撤退。

凡规则允许抵消且正式行动依赖该抵消，计划需明确承担单位、路径/用途与承诺时点；成功提交才写入本阶段MP约束，失败预览不锁兵。覆盖先使用后尝试移动、先移动后使用、多条路径共享承担者、承担者离开或损失，以及存读档和阶段切换。

### 补给、燃料与资源

追溯补给、图上SP消耗、部队储备、燃料分开记账；HQ/延补/铁路来源同源规则与本作限制分别验证。常用地面SP搬运及防接力在A3执行，空运专用搬运与离图货源在B后补。任何库存变化都需有来源和去向，不能靠输入数字生出资源。

### 炮击、战斗与移动交接

按9.2核对宣布、补给、行动值、地形/攻防比、奇袭与战果、损失/选项、撤退及推进等顺序；具体次序以规则核对结果为准。目标方决策、不可承担损失、无合法撤退路径、全灭、夺取设施、突袭前后MP都要有处理。已付款或已掷骰的状态不能因关闭、改选、撤销或重试而重结。

### 阶段与保存

只有真实生命周期边界才能清额度或标记；同阶段切环节、重选当前阶段不能清账。检查回合/阵营编辑入口与正式推进，明确演练工具和正式对局的权限，不能用编辑工具补流程。

首先保证合法结算点保存恢复完整，恢复后下一行动、位置、库存、额度、操作者和骰序一致；未完结算须明确拒绝保存或完整持久化。通用的战斗/任务任意中途保存作为低频增强，不能阻塞R1/R2。

## 综合验收办法

1. 优先从维捷布斯入门剧本建立回合脚本，再用主战役合法初设或经过校验的合法局面补足单位与分支；记录种子、日期、双方资源和全部单位。测试准备可设置场景，正式执行过程中禁止手改坐标、补SP、切阶段绕过待办。
2. 编排一条有实际行动的双方完整回合：移动与加油 → 补给与损耗 → 对方反应 → 炮击和战斗 → 撤退/推进 → 进击 → 清理与交接；在相应位置包含整备、增援及常用空军。不能全程空过后宣布回合可玩。
3. 用补充合法场景覆盖未在该回合触发的动作、日期、天气、双方先手顺序及互斥选择；以单位行动清单逐项追踪，B待办保持可见。
4. 自动流程逐步核对盘面、资源、MP/状态、待办、死亡堆、骰序和下一合法行动；人工在正式界面复做同样的决策，检查按钮、选兵、点图、提示和不能继续的原因。
5. 在合法保存点保存/读取后接着做下一行动，再完成剩余回合；验证普通成功、非法拒绝、资源不足、重复点击、中止/放弃、战斗极端结果。
6. 出具逐环节及逐行动结果表；R1/R2签收必须列清B待办，最终R3签收不得有适用行动缺项、P0/P1阻断或靠备注代替的结算。

## 下一次开始改程序时的具体任务
