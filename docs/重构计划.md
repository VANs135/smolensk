# OCS 斯摩棱斯克重构计划

更新：2026-11-02。此文件为后续批次的执行清单；历次重构文档记录各轮实际改动。本计划不把现有测试通过等同于规则全覆盖，也不预设交付日期。

## 目标与决策

继续渐进重构，保留地图、算子数据、现有规则函数、Vue/Pinia/Canvas 技术栈及存档兼容。优先修正能让对局卡死、资源凭空增加、结算被跳过或重复执行的问题，再迁移相关状态。每批形成可运行、可审查、已推送的提交，避免长期维护一套不可玩的平行实现。

完成标准：从真实剧本开局，双方按 SOP 完成行动、反应与结算，直到剧本终局；需要玩家决定时明确停下，不能靠手改数据、跳阶段或备注替代规则执行。

## 当前基线

已拆出阶段协调、快照注册、交战现场、掷骰与结果提交、补给阶段、地面移动运行状态及空军任务运行状态。地面移动和空军任务分开；ZOC 已按具体动作区分；部分不可逆操作增加撤销保护。

这些是基础改造，不能视为全域验收。`workbench.ts` 仍接近两万行，部分规则事实构建、跨域提交和资源账本仍集中在其中。空运 SP 起点扣账、补给路径 ZOC 抵消承诺是已确认缺口。空军 F 步的任务与轰炸归属是本轮优先修复项。

## 各域设计约束

### 行动与提交

预览只读；正式操作先校验，再确定骰序和变更计划，最后统一落盘。提交失败不应留下半笔扣款、半次减损或已消耗的出动次数。重试继续已确认的状态，不能通过取消或改选重掷。暂时没有事务能力的入口应先覆盖故障用例，再迁移。

### 资源与所有权

SP 统一按 T 计算，界面再显示 SP/T；库存、载货、落地、退回及损失必须能对账。地面单位、飞机、空军任务、炮击和战斗之间传递明确的归属，不能仅凭“同一目标格存在一个结果”推断本次已完成。反应段和目标方决策不能沿用阶段玩家身份。

### 规则、ZOC 与移动

OCS 4.3 加本作专规与勘误为依据，明确记录用户已确认的规则口径。地面逐格 MP、空军任务航程、补给抽取/投送路径、撤退和战后推进分别建模。ZOC 投射与抵消效果分开；可抵消的操作还必须履行 4.5b 承诺。规则含糊处保留来源和判定理由，不默默发明新规则。

### 存档与兼容

继续兼容旧档，不以一次性清空数据解决迁移。新增持久状态必须同步快照字段、默认值、迁移、恢复顺序与回归用例。当前仍以完整结算点保存为基础；支持战斗或空军任务中途恢复前，必须把所有待决状态和随机进度一并设计，不能只保存盘面。

## 每批交付与验证

1. 记录真实触发条件、错误结果、对应规则与影响范围。
2. 增加能复现问题的行为用例；规则矩阵使用引擎测试，跨域操作使用真实 store/SOP 入口。源码文本守卫只作辅助。
3. 修复并拆出对应职责，保持对外入口兼容；补充失败、重试、取消、重复提交及合法下一步的检查。
4. 运行相关回归、类型/代码/格式检查、架构扫描与构建；跨域变更提交前跑全量回归。
5. 更新此计划、目录清单及本轮记录，提交并推送 Git，核对本地和远端提交一致。

每批报告写明实际完成、测试证据和剩余缺口。没有用真实入口验证的流程标为待验收，不使用“整体已完成”的结论。
