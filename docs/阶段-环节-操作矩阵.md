# 阶段 / 环节 × 操作矩阵（规则书口径）

> 用户 2026-10-25：**「按规则书分清楚每个阶段\环节有哪些操作，哪些阶段\环节是人工操作，
> 哪些是自动结算，每个阶段\环节只能出现该环节可用 UI，不要什么都糅杂在一起」**
>
> 本文件是这条要求的**对照表**。代码里的唯一派生源是 `actionKeysOfSegment()`
> （`src/stores/workbench-model.ts`），它由 `sop-segments.ts`（规则书 2.2 流程表：`driver` / `actions`）
> 与 `ACTION_GATES.where`（每条动作族的原文位置）派生。
> 界面显示/禁用一律问它（`workbench.segmentActionKeys` / `actionAllowedNow(key)`），
> **不得**在组件里自己拼阶段名或规则号。

## 2. 只有这 6 个环节是**自动结算**（不出动作 UI）

| 环节                           | 自动做什么                                     | 依据              |
| ------------------------------ | ---------------------------------------------- | ----------------- |
| `preTurn.weatherDetermination` | 掷 1d6 定天气；有随机事件则一并掷              | 2.2 / 专规 1.5    |
| `reinforcement.replRoll`       | 掷补给表（得 SP）与补员表（得 Ftr/Tac/Pax/Eq） | 13.6b / 专规 1.6b |
| `reinforcement.randomEvent`    | 掷随机事件（轴方，19 Jul / 25 Aug）            | 专规 3.6          |
| `reinforcement.variableExit`   | 掷可变撤离（轴方，19 Aug 起）                  | 专规 3.3c         |
| `cleanUp.auto`                 | 移除 DG 与进击标志、翻回燃料面、清运输破坏     | 2.2「清理」       |
| `turnEnd.advance`              | 移动回合标记                                   | 2.2「回合结束」   |

> 判定口径：这些环节 `driver === 'automatic'`，`actionKeysOfSegment()` 返回**空集** ⇒
> 界面只该给"本环节自动结算，结果见日志/回执"，**不铺任何动作按钮**。

## 4. 三条落地规则（UI 收敛口径）

1. **面板级**：面板声明它服务的动作族集合；`面板集合 ∩ segmentActionKeys === ∅` ⇒
   本环节不显示该面板（或折叠成一条「本环节不可用」）。
2. **按钮级**：动作按钮一律 `:disabled="!workbench.actionAllowedNow(key)"`，tooltip 给
   `actionGateOf(key).rule` 与它该在的环节（组件里不写死规则号）。
3. **自动环节**：`segmentDriver === 'automatic'` ⇒ 只渲染回执（结果 + 规则号），
   不渲染动作区。这就是"自动结算"与"人工操作"的界面分界。

## 5. 四种"门的粒度"（2026-10-25 落地后）

界面上的显隐一共只有这四道门，**都读 store 的投影/闸门，组件不写规则号**：

| 门                                 | 判据                     | 用在哪                     | 典型例子                                     |
| ---------------------------------- | ------------------------ | -------------------------- | -------------------------------------------- |
| **环节门** `segmentIn([...])`      | 当前环节 id ∈ 列表       | 面板内的大区块             | 增援面板：到达表只在 `reinforcement.arrival` |
| **动作门** `actionAllowedNow(key)` | 该动作族在本环节是否放行 | 单个按钮 / 一小块          | 移动面板：`canMove` / `canReleaseReserve`    |
| **菜单门** `unitActionOptions(id)` | 设施动作族 ∩ 本环节闸门  | 点一枚设施后的**操作清单** | 补给站只有「销毁」；运输点三项               |
| **裁判门** `only === null`         | 只在引擎验证页           | 手动改表类工具             | 回合标记 / 天气 / 铁路容量 / 重置盒子        |

### 5.1 "一个操作一个面板"的菜单表（实测，`facility-action-by-segment` 逐格断言）

| 环节              | 补给站 SP      | 运输点                                                | 延补队    | 空军基地                   | 工事                 |
| ----------------- | -------------- | ----------------------------------------------------- | --------- | -------------------------- | -------------------- |

| G 进击·进击移动   | 销毁           | **只**转延补队                                        | 翻回·崩溃 | —                          | —                    |
| A 飞机整备        | —              | —                                                     | —         | **整备（15.1）**           | —                    |

`—` ＝本环节对这东西**没有**"对它操作"⇒ **连「操作」按钮都不给**（不开空会话）。

### 5.2 裁判工具与流程动作的分界

2.2 的回合推进、1.5 的天气判定、专规 1.2 的铁路容量**都由系统自动结算**（见 §2），
所以它们的"手动改值"入口只出现在**引擎验证页**（对局台一个都不铺）；
`ContainersPanel` 为此新增 `showsReferee`（＝`only === null`）。判定同源：
`docs/第六批修改方案.md` §18②。
